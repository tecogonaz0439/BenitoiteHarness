# 依頼: 共通のリポジトリ（BenitoiteLang）への移行を未決事項に加える

2026-11-03、Benitoite の処理系の取りまとめから BenitoiteHarness へ。

## 依頼の内容

`docs/design/open-issues.md` に、共通のリポジトリ `~/src/BenitoiteLang` への移行の項目を一つ加えてほしい。番号は、この文書の分野ごとの振り方に従ってハーネス側で決める。区分は「未決」とし、決める時期は第1段（下記）の時期をハーネスのロードマップの段階で示す。

移行は二段で行う（2026-11-03 の設計者の方針）。

- **第1段（ハーネス側）**: BenitoiteHarness の側で、共通のリポジトリとディレクトリを準備し、BenitoiteHarness をその下へ移す。
- **第2段（処理系側）**: Benitoite のサーバモードと実行時の権限制御を実装する時期に、処理系のリポジトリ `~/src/Benitoite` を共通のリポジトリの下へ取り込む。

項目の本文と章の参照は、ハーネス側の規約で書いてよい。以下は決まっている内容と、第1段で行ってほしい作業である。

## 背景

Benitoite の docs/todo の TODO-270「共通のリポジトリ（BenitoiteLang）を設け、処理系とハーネスをその下へ移す」に、2026-10-20 の設計者との相談の決定がある（docs/todo は非公開のリポジトリなので、リンクせず番号を文字で引く）。要点は次のとおりである。

- 処理系とハーネスは、別のリポジトリのままとする（Benitoite の docs/todo の TODO-176）。
- 一つ上に共通のディレクトリ `~/src/BenitoiteLang` を設け、それ自体を非公開の git のリポジトリ（共通のリポジトリ）とする。処理系とハーネスをその下へ移す（シンボリックリンクにしない）。子のリポジトリは、共通のリポジトリの `.gitignore` で除く。後で Web サイトのリポジトリ（Benitoite の docs/todo の TODO-268）も、同じく子に置く。
- Claude Code と Codex は、共通のディレクトリの一番上から起動する。
- 共通のリポジトリに置くもの:
  - `AGENTS.md`: 索引（どの作業でどの子のリポジトリの `AGENTS.md` を読むか）と、二つのリポジトリにまたがる決まり。
    - 正の分担表と、正でない側は写さずに版を固定して参照する決まり（Benitoite の docs/todo の TODO-266）。
    - JSON の約束を変えるときの手順と、両リポジトリのリリースの順序。
    - コミットは、変えたファイルが属するリポジトリで行うこと。
    - 公開のリポジトリから共通のリポジトリへリンクしないこと。
  - `.claude/`・`.agents/`: 一番上から起動したときの設定（音で知らせるフック、許可の確認のフックなど）と、二つのリポジトリにまたがるスキル。
  - `docs/`: リポジトリをまたぐ文書と、`docs/todo` だけ。設計書は子のリポジトリに残す。
- 子のリポジトリの `AGENTS.md` は残す。子のリポジトリの中で Codex を動かす使い方では、共通の `AGENTS.md` が読まれない見込みだからである（確かめていない）。

TODO-270 は、移す時期を「クレートの分割（TODO-176）と同じ時期、構文の改造が一段落した後、サーバモードを実装する前」としていた。2026-11-03 の方針で二段に分け、処理系の取り込みはサーバモードと権限制御の実装の時期に行うことにした。処理系の側の TODO-270 は、処理系の取りまとめが別に改める。

## 第1段: ハーネス側で準備すること

1. **共通のリポジトリを作る**: `~/src/BenitoiteLang` を作り、`git init` する。非公開とし、リモートは設計者の指示があるまで置かない。
2. **BenitoiteHarness を移す**: 作業（Codex・Claude Code・作業ツリー）がすべて止まり、変更がすべてコミットしてあることを確かめてから移す。使っていない作業ツリーとブランチは、スキル `archive-and-bundle` で bundle に保存してから片付ける。移した後に `git worktree repair` を行う。
3. **共通のリポジトリの中身を置く**: `AGENTS.md`（索引とまたがる決まり）、`.claude/`・`.agents/`、`.gitignore`（子のリポジトリを除く）、`docs/`。第1段では、処理系の `AGENTS.md` と docs/todo はまだ移さない。索引には、処理系が第2段まで `~/src/Benitoite` にあることを書く。
4. **ハーネス側の参照を直す**:
   - `docs/plan/00-common.md` は、処理系のリポジトリを既定で作業ツリーの隣の `../Benitoite` としている。第1段の後は、`~/src/BenitoiteLang/BenitoiteHarness` の隣に処理系がない。第1段から第2段までの間も処理系を見つけられる指定にする（例: オーケストレータが場所を渡す、設定や環境変数で指定する）。
   - `docs/plan` などに残る手元の絶対パスを直す。
5. **Claude Code と Codex の設定を移す**:
   - Claude Code の記憶は、起動したディレクトリのパスごとに分かれる。ハーネスの記憶を、共通のディレクトリから起動したときの場所へ写す。
   - Codex の信頼するプロジェクトの設定（`~/.codex/config.toml`）に、新しいパスを加える。
6. **確かめる**:
   - 一番上から Claude Code と Codex を起動したとき、共通と子の `AGENTS.md`、子のディレクトリのスキルがどう読まれるか（親の `AGENTS.md` を読むか、Codex が git の根より上を読まないか）。
   - ハーネスのビルドとテスト（Cargo の生成物は絶対パスを含むので作り直しになる）。
   - 確かめた結果は、第2段の手順の根拠になるので、ハーネス側の結果の記録に残す。

## 第2段: 処理系の取り込み（参考）

第2段は処理系の取りまとめが行う。ハーネス側の項目では、第1段の結果を第2段へ引き渡す点だけを書けばよい。処理系の側で予定している作業は次のとおりである。

- 処理系のリポジトリを `~/src/BenitoiteLang` の下へ移し、`git worktree repair` を行う。
- 処理系の docs/todo（非公開の入れ子のリポジトリ）を、共通のリポジトリの `docs/todo` へ移す。ハーネスの未決事項もあわせて扱えるようにするかは、そのときに決める。
- 処理系の側の絶対パスを直す（検査のデータ、`tools/skill-eval/harnesses.json`、改造の道具）。処理系の `AGENTS.md` の docs/todo の扱いと、ハーネスの場所の記述を直す。
- 処理系の記憶を写し、ハーネスの記憶と重なる項目を整理する。
- 処理系のビルドとテスト、`formal/` の `lake build`、`scripts/check.sh` の work を確かめる。
