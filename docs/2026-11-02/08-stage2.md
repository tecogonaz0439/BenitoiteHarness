# 段 2: エージェントの性能（評価用の切り替え）

[04](04-oss-feature-review.md)の「段 2: エージェントの性能」の 1〜3 を、設計者の指示で進めた記録である。作業は 2026-11-03 に行った。確かめは、[01](01-cloud-linux-check.md)の環境（x86_64 の Linux、Alpine 3.22.7 の rootfs、root でない利用者）で行った。macOS での確かめと、本物の LLM を呼ぶ確かめは行っていない。

## 設計者の決定と作業の方針

- 段 2 の各案は、評価で効果を確かめてから採る（04）。本物の LLM を呼ぶ評価は設計者の了承の後に行うので、今回は作るところまでとした。
- 1〜3 は、どれも利用者の設定だけで有効にする評価用の切り替えとし、既定では切っておく。既存の評価用の切り替え（`read.line_numbers`、`agent.completion_check`、`[compaction]`）に倣う。既定の振る舞いと、LLM に渡す文脈の期待値は変わらない。
- 4（計画の道具と確かめの促し）と 5（スクリプトから道具を呼ぶエフェクト。処理系の側の変更を待つ）は、今回は扱っていない。4 のうち確かめの促しは、2026-11-03 に設計者が BH-011 を閉じた（`agent.completion_check` は既定 `false` のまま残し、追加の比べも編集の直後の促しも行わない）ので、加えない。計画の道具（BH-008）は、BH-011 を閉じた後の設計者の指示で、1〜3 と同じく既定で切った切り替えとして作った（下の「計画の道具」）。
- 形の選択（複数の置き換えの引数、刈り込む対象と時機、下のディレクトリの指示を添える道具と忘れる時機）は、設計者の「問い合わせがあれば推奨の方法で進める」の指示に従い、下の「選んだ形」のとおりに決めた。どれも【方針】として設計書に書き、評価の後に見直す。

## 選んだ形

### 複数の置き換え

- Pi（`earendil-works/pi` の `752019d` の `edit.ts`、`edit-diff.ts`）に倣い、`path` と `edits[]` だけを受ける形に替える。一つの置き換えの欄は受けない。各要素は `old_string`・`new_string`・`replace_all`（省略できる）を持つ。
- 各要素を元のファイルで照合し（前の要素の結果に当てない）、範囲の重なりを拒み、どれかが誤りならファイルを書かない。要素の誤りの文は、`edits[N]: ` に一つの置き換えと同じ文を続ける。
- 引数の型にオブジェクトの配列を加え、要素の欄にも外側と同じ strict の規則（OpenAI の必須と `null`、`additionalProperties: false`）を掛けた。本物の提供者が入れ子の Schema を受け付けるかは BH-122 とした。
- 文脈の期待値に、通常モードの複数の置き換えの形（`system-normal-edit-multiple.txt`、`tools-normal-edit-multiple.json`）を加えた。既定の期待値は変わらない。

### 道具の結果の刈り込み

- DeepSeek Harness（`deepseek-ai/deepseek-harness` の `ce7073d`）の `tool-result-pruner` の既定の値（8,192 字を超える結果を、頭 4,096 字と尾 1,024 字にする）に揃えた。字は Unicode のスカラー値で数える。
- DeepSeek Harness は今の会話のすべての結果を対象にするが、最後の応答の後の結果（LLM がまだ読んでいないもの）は刈り込まない形にした。番の前に刈り込むので、そのままでは直前の結果を読む前に縮めることになる。
- 番の前の判定で閾値を超えたら先に刈り込み、閾値を下回れば要約しない。文脈の超過では、刈り込んでから今の超過の圧縮を行う。`/compact` と再開の圧縮では刈り込まない。
- 刈り込んだ後の文を `tool_results_pruned` の節点に記録し、再開、fork、巻き戻しで同じ会話を再生する。fork は、刈り込んだ文の中の保存先のパスも書き換える（元の結果と同じ扱い）。

### 下のディレクトリの指示のファイル

- Hermes（`NousResearch/hermes-agent` の `0aab6dc` の `agent/subdirectory_hints.py`）に倣い、道具が触れたディレクトリの指示のファイルを道具の結果に添える。
- 対象の道具は `read`・`write`・`edit`・`glob`・`grep` とし、`bash` のコマンドは読まない。プロジェクトのディレクトリより下だけを見る（根から上は起動のときに読む）。
- 読む条件は起動のときのプロジェクトの側の指示のファイルと同じ関数で行う（範囲の外へ出ない開き方、読まないファイル、ハードリンク、一度だけ、UTF-8、32 KiB）。起動のときに読んだファイルへのリンクは読まない。合計は起動のときとは別に 64 KiB までとした。
- 指示のファイルは信頼の確認の対象ではない（03-01）ので、添える指示も同じとした。通常モードだけで働く（BH-042）。
- 一つのディレクトリは一つの会話で一度だけ見る。誤りの結果では見たことにしない。圧縮と枝の移動の後は忘れて添え直す。再開では記録から戻さない。
- 添えたファイルと読まなかったファイルをイベント `nested_instructions` で示し、画面にも起動のときと同じ文で示す。

### 計画の道具

- Codex CLI（`openai/codex` の `3026a8e` の `plan_spec.rs`、`plan_tool.rs`）の `update_plan` に揃え、`explanation`（省略できる）と `plan[{step, status}]` を受け、毎回、計画の全体を送らせる。結果の文は `Plan updated.` だけとし、計画は会話の中の呼び出しの引数として残る。
- Codex が説明に書くだけの「進行中は一つまで」を検査し、知らない `status` と空の `step` も誤りとする。
- ファイルにもプロセスにも触れないので、両モードで加えられるようにした。道具の一覧の最後に置き、既定の道具の順序と期待値を変えない。
- 画面には `[x]`・`[>]`・`[ ]` の印の付いた一覧を示す。
- 文脈の期待値に、制限モードの計画の道具の形（`system-restricted-plan.txt`、`tools-restricted-plan.json`）を加えた。

## 確かめ

| 検査 | 結果 |
|---|---|
| `cargo test --workspace --target x86_64-unknown-linux-musl` | 1〜3 の後に 810 件、計画の道具の後に 811 件が通り、失敗 0、無視 16（`work/cloud-check/stage2-3.log`、`stage2-4.log`） |
| `cargo clippy --workspace --all-targets`（`x86_64-unknown-linux-musl`、`aarch64-apple-darwin`） | 通った。`aarch64-apple-darwin` は Linux からの検査だけである |
| `cargo fmt --check` | 通った |

新しいテストは、スキル `test-audit` の作成時の関門に従って加え、既存の表に行を足せるものは足した。要の部分は、実装を一時的に壊してテストが失敗することを確かめた。

- 複数の置き換え: 重なりの拒否、Agent での道具の形の切り替え。
- 刈り込み: 最後の応答の後の結果を残すこと、記録からの再生、超過の前の刈り込み、fork の保存先の書き換え。
- 下のディレクトリの指示: 一度だけ、誤りの結果で見たことにしないこと、起動のときに読んだファイルとの重なり、圧縮の後に忘れること。
- 計画の道具: 進行中を二つ以上にしたときの拒否。

作業の途中で、このセッションの書ける容量を使い切り、リンクが `SIGBUS` で止まった。`target/` の古い成果物（ホストの `debug/` と、`x86_64-unknown-linux-musl` の差分のビルドの記録、`benitoiteh` の古いテストの実行ファイル）を消して続けた。以後は `CARGO_INCREMENTAL=0` でビルドした。
