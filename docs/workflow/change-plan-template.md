# 作業文書の雛形

この文書のコードブロックを `docs/plan/tasks/<ID>-<名前>.md` へ写し、作業の内容に合わせて埋める。設計書と実装プランだけを読めば実装できる粒度にし、作業の状態と依存を [実装プランの一覧](../plan/README.md)にも反映する。共通手順は [作業の進め方](../plan/00-common.md)、依頼に渡す情報は [共通依頼文](implementation-request.md)に従う。

```markdown
# <ID> <作業の題>

## 目的

<実現する振る舞いと、この作業が扱う範囲。設計を変える場合は、その判断の所在。>

## 読む設計書

- <設計書の相対パスと節。写した後の場所から辿れるリンクにする。>
- <依存する作業の文書と、関係する既存のモジュール。>

## この作業が認める型の変更

<共有する型とシグネチャの変更。なければ「なし」。>

## 作るもの

<振る舞い、誤りの扱い、入力と出力、依存する作業との接続。>

## 触るファイル

- <変更するファイルと、新しく作るファイル。>

## テスト

<test-audit の作成時の関門で選んだ契約と、その契約を持つ境界。>
<本物の LLM を呼ばず、利用者の設定と資格情報を使わずに確かめる方法。>

## 確かめること

<実装時に一次資料または測定で確かめ、報告に答える問い。>

## 完了条件

- <利用者または呼び出し元から確認できる振る舞い。>
- scripts/check.sh --inside-codex が通る。
- <オーケストレータが外で走らせる検査と、必要な環境。>
```

個人の絶対パス、接続先、費用の残高、秘密の値は雛形を埋めた公開文書に書かない。依存を足す作業では実行ファイルの大きさの差を測る条件を加える。結果を文書に残す場合は、保存先と、実装担当が変えてよい文書の範囲も指定する。
