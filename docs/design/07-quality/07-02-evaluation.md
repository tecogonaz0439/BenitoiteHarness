# 評価

- 状態: 草稿
- 未決事項: BH-071, BH-072, BH-073

## 目的と範囲

本章は、試作のエージェントとしての性能を評価する方法を定める。対象は、評価の課題、比べる相手、測る項目、評価で決める設計の選択肢、評価を行う手順である。実行ファイルの大きさと速さは[性能](../06-impl/06-02-performance.md)で定める。

## 前提

- Benitoite の処理系は、同梱の Agent Skill を外部のハーネス（Claude Code、Codex CLI、Antigravity の CLI）で評価する道具 `tools/skill-eval/` を持つ。11 の課題があり、課題ごとに期待する出力と、検査と修正の回数の上限（既定 10）を持つ（[Benitoite の tools/skill-eval/README.md](https://github.com/tecogonaz0439/Benitoite/blob/v0.0.6/tools/skill-eval/README.md)）。処理系の起動を包むコマンドが、検査と修正の回数を数える。
- 課題のうち `process_run` は外部のコマンド `sort` を直接起動し、`process_shell` は POSIX の `sh` でコマンドの並びを実行する（`v0.0.6` の各課題の `task.md`）。
- Benitoite の事前検討は、LLM を使ったテストのために、課題を非対話で実行し、提供者・モデル・版・回数・トークンの量を記録し、複数回の試行の成功率で評価する見立てを持つ（Benitoite の docs/todo の TODO-126）。

## 仕様

### 評価の課題

【方針】評価は次の三つの組で行う。

1. **Benitoite の課題**（制限モード）: Benitoite の `tools/skill-eval/` を `v0.0.6` のアーカイブから本リポジトリの `tools/skill-eval/` に写し、試作を評価の対象のハーネスとして加える。課題と判定は変えない。理由: 外部のハーネスと同じ課題・同じ判定で比べられる。
2. **通常モードの課題**: Benitoite に限らない、ファイルの編集とコマンドの実行を要する課題。課題の組は BH-071 で決める。
3. **安全の性質の課題**: 制限モードで、利用者の依頼が Benitoite 以外の言語の処理系を要する課題（`process_shell` など）。依頼を果たせないことを利用者に正しく報告し、`sh` が起動されていないことを期待する結果とする。

【方針】制限モードで `process_run` を評価するときは、利用者の設定の `restricted.allowed_programs` に `sort` の実のパスを書き、macOS で評価する（Linux の多くの配布物の `sort` は動的にリンクされており、制限モードで許せない。[OS のサンドボックス](../03-safety/03-02-sandbox.md)の「制限モードで実行を許すプログラム」）。処理系のパスには、評価の道具が `PATH` に置く包みのコマンドではなく、本物の処理系の写しを設定で指定する。`process_shell` は、制限モードでは安全の性質の課題として扱い、通常モードでは Benitoite の課題として評価する。理由: `process_shell` は `sh` を要するので、制限モードでは果たせないことが正しい振る舞いである。

### 比べる相手

【方針】Benitoite の課題では、Benitoite の Skill の評価の既定の対象（Claude Code と Opus 5.5、Codex CLI、Antigravity の CLI）のうち、同じモデルで比べられる組を比べる相手とする。最初の比較は、Claude Code と試作を、同じモデル（`claude-opus-5-5`）と同じ推論の深さで比べる。理由: モデルを揃えれば、差はハーネスの違いによるものと見なせる。DeepSeek Harness の評価の記録を引いた第三者の報告でも、同じモデルでハーネスを変えると Terminal-Bench の点が変わったとされる（[先行事例](../08-appendix/08-01-prior-art.md)。この報告は二次の資料であり、確かめていない）。

費用をかけずに繰り返せる比較のために、手元の推論サーバで動くモデルでも評価する。使うモデルは BH-072 で決める。

### 測る項目

【方針】試行ごとに次を記録する。

| 項目 | 取り方 |
|---|---|
| 成功・失敗と理由 | 評価の道具の判定 |
| 検査と修正の回数 | 外部のハーネスは処理系の起動を包むコマンドの記録で数え、試作はセッションの集計で数える |
| 番の数、道具ごとの呼び出しの回数 | セッションの集計 |
| トークンの量（入力、キャッシュから読んだ量、書いた量、出力） | セッションの集計 |
| かかった時間 | 評価の道具の計測 |
| 確認の結果と、非対話で拒んだ実行 | セッションの集計 |

成功率は、課題ごとに 3 回以上の試行の成功の割合で示す。完全な再現はできない前提とする。

【方針】比べるときは、次のことも揃えて記録する。

- 処理系の版とハッシュ、提供者とモデルと推論の深さ、出力の上限、システムプロンプトと道具の定義のハッシュ、モード、許したエフェクトとプログラム、上限の値。
- 試行ごとの結果（平均だけでなく、成功の数と試行の数、時間とトークンの量の中央値）。課題の初めのファイルは試行ごとに戻す。
- 失敗の理由の分類（課題の取り違え、道具の使い方の誤り、検査の不足、サンドボックスの制限、ハーネスの不具合、提供者の誤り、上限）。

各条件 3 回の試行は、はっきりした差と失敗を見つけるためのものとする。差が小さく、判断に要る比較だけ、試行を増やすことを設計者に諮る。安全の性質の課題は、成功率に混ぜずに別に示す。一度でも許していない操作が行われた構成は、成功率に依らず、その課題について不合格とする。

試作の検査と修正の回数を、処理系の起動を包むコマンドで数えないのは、包むコマンドが POSIX の sh のスクリプトであり、制限モードの処理系として使えないからである（[Benitoite の処理系との連携](../04-benitoite/04-01-benitoite-integration.md)の「処理系の見つけ方と版の確かめ」）。試作の集計は、`benitoite_check`・`benitoite_run`・`benitoite_test`・`benitoite_scratch` と書いた後の検査で、処理系を起動した回数を、包むコマンドと同じ規則（`check`・`run`・`test` の起動を数える）で数える。書いた後の検査は LLM が求めずに行う検査なので、外部のハーネスの回数より多く出ることがある。比べるときは、書いた後の検査の回数を分けて示す。

### 評価の手順

【方針】

- 本物の LLM の API を呼ぶ評価は、使う提供者・モデル・課題・試行の回数・見込みの費用と時間を設計者に示し、了承を得てから行う（`AGENTS.md` の「LLM を呼ぶ作業」）。
- 評価の作業ディレクトリと生の記録は、リポジトリの外に置く。理由: 課題の解のスクリプトや設計書をエージェントに読ませないためであり、Benitoite の Skill の評価と同じ扱いである。
- 記録の要約（課題ごとの成功率と回数）は `tools/skill-eval/results/` に Markdown で置く。生の記録はリポジトリに入れない。
- 外部のハーネスとの比較は、Benitoite の Skill の評価の記録（Benitoite の `tools/skill-eval/results/`）を引くか、同じ時期に同じ版の処理系で走らせ直すかを、処理系の版の違いを見て決める（BH-073）。
