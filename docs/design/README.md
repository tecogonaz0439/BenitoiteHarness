# 設計書

関数型スクリプト言語 [Benitoite](https://github.com/tecogonaz0439/Benitoite)（ベニトアイト）の、独自のエージェントハーネスの試作 `benitoiteh`（仮の名前）の設計書である。試作は Rust で書き、Benitoite の処理系（`benitoite`）とは別のプログラムとする。

本設計書は設計の段階の版であり、試作が実装する予定の内容を書く。試作の実装はまだない。設計の前提にした Benitoite の版は、最新のリリース `v0.0.7`（コミット `63de89a2`）である。`v0.0.5`（コミット `5ef09b51`）を前提に書き、2026-10-17 に `v0.0.6`（コミット `f31dacd3`）に、2026-10-18 に `v0.0.7` に合わせて見直した。

## 構成と読み方

- `00-overview/` は、目的、全体像、段階、用語である。最初に[目的と設計原則](00-overview/00-01-goals.md)を読む。
- `01-agent/` は、エージェントとしての振る舞い（ループ、モード、道具、文脈、セッション）を定める。
- `02-providers/` は、LLM の提供者との通信を定める。
- `03-safety/` は、脅威モデル、OS のサンドボックス、利用者の確認を定める。
- `04-benitoite/` は、Benitoite の処理系との連携を定める。
- `05-interface/` は、CLI、設定ファイル、対話の画面を定める。
- `06-impl/` は、クレートの構成と性能の目標を定める。
- `07-quality/` は、テストと評価を定める。
- `08-appendix/` は、参考にしたハーネスの調査、Benitoite の事前検討との対応、外部のレビューの記録とその資料である。
- 本文には現在の決定を書き、判断の理由を決定の直後に「理由: 〜。」として短く添える。
- 未決と要検証の事項は [open-issues.md](open-issues.md) で `BH-nnn` の番号を付けて管理する。

Benitoite の設計書と事前検討へのリンクは、設計の前提にした版（`v0.0.7`）のタグを指す GitHub の URL で書く。前の版についての事実（「`v0.0.6` の時点で」など）の出典は、その版のタグを指したまま残す。ただし、[外部のレビューの記録](08-appendix/08-03-external-review.md)が確かめた事実の出典は、確かめたときの版のタグを指したまま残す。Benitoite の docs/todo（非公開）の項目は、「Benitoite の docs/todo の TODO-124」のように文字で示す。

## 凡例

- 【決定】設計者と合意した
- 【方針】暫定の既定路線。設計者の確認を待つか、試作で確かめてから【決定】にする
- 【未決】選択肢を検討中（`BH-nnn` を添える）
- 【要検証】試作・実測・一次資料の確認が要る（`BH-nnn` を添える）

章の状態は「草稿」「確定」の二段階で、各章の冒頭に記す。各章の冒頭の「未決事項」には、その章で決める項目を挙げる。本文はほかの章の項目にも触れる。
