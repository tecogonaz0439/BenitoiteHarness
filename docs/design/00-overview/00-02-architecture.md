# 全体像

- 状態: 草稿

## 目的と範囲

本章は、`benitoiteh` を構成する部分と、それらの間のデータの流れを示す。各部分の詳細は、表に示す章で定める。

## 前提

- モードは[モード](../01-agent/01-02-modes.md)で、道具は[道具](../01-agent/01-03-tools.md)で定める。
- スレッドの構成とモジュールの分け方は[クレートの構成](../06-impl/06-01-crate-structure.md)で定める。

## 仕様

### プロセスの構成

```text
利用者の端末
   │ 入力・確認の答え / 画面
   ▼
benitoiteh（主のプロセス。信頼する）
   ├─ 対話の画面（05-02）・exec の出力（05-01）
   ├─ エージェントのループ（01-01）
   │    ├─ 文脈の管理（01-04）── セッションの記録（01-05）
   │    ├─ 提供者の層（02-01）──── HTTPS ───▶ LLM の提供者
   │    └─ 道具（01-03）
   │         ├─ read / glob / grep / write / edit / web_fetch（主のプロセスの中で実行）
   │         └─ 子プロセスを起動する道具 ── 利用者の確認（03-03）
   │                 │
   │                 ▼
   │        サンドボックスを掛ける（03-02）
   │          macOS: /usr/bin/sandbox-exec -p <方針> -- …
   │          Linux: benitoiteh __sandbox <方針> -- …（Landlock・seccomp を掛けて exec）
   │                 │
   │                 ▼
   │        子プロセス（信頼しない内容を動かす）
   │          制限モード: benitoite check / run / test（04-01）
   │          通常モード: bash -c <コマンド>
   └─ 処理系の版の確かめ（起動のとき一度。04-01）
```

- 主のプロセスはサンドボックスの外で動く。主のプロセスが行うファイルの読み書きは、道具の規則（パスの範囲、`.bnt` の制限、読まないファイル）で限る。
- 子プロセスとその子孫は、サンドボックスの方針の範囲でだけ動く。制限モードでは、子孫が起動できるプログラムも限る。

### 一連の処理のデータの流れ

1. 利用者が依頼を入力する。対話の画面が、エージェントのスレッドへ送る。
2. エージェントのループが、文脈（システムプロンプト、道具の定義、環境の情報、会話）を組み立て、提供者の層へ要求を渡す。
3. 提供者の層のアダプタが、共通の形を提供者の要求に変えて送り、ストリームを共通の形のイベントに変えて返す。イベントは画面とセッションの記録にも流れる。
4. 応答に道具の呼び出しがあれば、エージェントのループが検証し、並べてよいものを並べて実行する。確認が要るものは、画面に確認を求めて答えを待つ。
5. 子プロセスを起動する道具は、サンドボックスの方針を作り、子プロセスを起動し、出力を受け取って切り詰める。
6. 道具の結果を会話に加え、2 に戻る。LLM が道具を呼ばずに応答を終えたら、一連の処理を終える。

### 状態の置き場所

| 状態 | 置き場所 | 圧縮で失われるか |
|---|---|---|
| 会話 | エージェントのループのメモリと、セッションの記録 | 古い側が要約に置き換わる |
| 確認したエフェクト、許可したコマンドとドメイン | 確認の記録（セッションのメモリと記録） | 失われない |
| 読んだファイルの版 | 道具の実行器のメモリ | 失われない |
| 検査と修正の回数 | エージェントのループのメモリ | 失われない |
| 巻き戻しの記録 | セッションのディレクトリの `objects/` と時点の一覧 | 失われない |
| 切り詰めた出力の全体 | セッションのディレクトリの `spill/` | 失われない |
