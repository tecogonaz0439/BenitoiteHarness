# 用語集

- 状態: 草稿

## 目的と範囲

本章は、本設計書で使う術語を定義する。Benitoite の設計書の用語集（[00-04「用語集」](https://github.com/tecogonaz0439/Benitoite/blob/v0.0.12/docs/design/00-overview/00-04-glossary.md)）にある語（エフェクト、処理系、根のディレクトリなど）は、同じ意味で使い、ここでは本設計書に固有の語と、意味を限って使う語だけを挙げる。

## 前提

- Benitoite の設計書では、「ハーネス」は Claude Code、Codex CLI、OpenCode などの外部のプログラムを指し、処理系が持つ予定の自前のものを「エージェントハーネス」と呼んで区別している。

## 仕様

| 用語 | 英語 | 定義 | 主な章 |
|---|---|---|---|
| `benitoiteh` | — | 本プロジェクトで試作するハーネスの実行ファイル（仮の名前）。本設計書では「試作のハーネス」とも書く | 00-01 |
| ハーネス | harness | Claude Code、Codex CLI、Pi、DeepSeek Harness など、LLM を動かして道具を実行させるプログラム一般。Benitoite の設計書と同じく、外部のプログラムを指すときに使う | 08-01 |
| エージェントハーネス | agent harness | Benitoite の事前検討が、処理系の機能として検討した自前のハーネス。試作は、その設計を確かめるためのものである | 00-01 |
| 制限モード | restricted mode | LLM に許す操作を、Benitoite のスクリプトの作成・検査・実行とプロジェクトの中の読み取りに限るモード | 01-02 |
| 通常モード | normal mode | シェルとファイルの編集の道具を持ち、一般的なハーネスと同じく振る舞うモード | 01-02 |
| 道具 | tool | LLM が呼び出しを要求でき、`benitoiteh` が実行する操作 | 01-03 |
| 依頼 | request | 利用者が入力欄から送る一つの文 | 01-01 |
| 番 | turn | LLM への一回の要求と、その応答と、応答の道具の呼び出しの実行まで | 01-01 |
| 一連の処理 | run | 一つの依頼を受けてから、LLM が道具を呼ばずに応答を終えるまでの番の並び | 01-01 |
| 提供者 | provider | LLM の API を提供するサービスと、手元の推論サーバ | 02-01 |
| アダプタ | adapter | 提供者の通信の形（wire API）ごとに、共通の形と要求・応答を相互に変える部分 | 02-01 |
| 共通の形 | common model | 提供者に依らない、会話・道具の定義・イベントの表し方 | 02-01 |
| 提供者の元の項目 | native items | 提供者が返した応答の項目（Anthropic の content block、Responses の output の item）を、順序と識別子と不透明なデータを変えずに持ったもの。同じ送り先へは、これから送る内容を作る | 02-01 |
| 送り先 | destination | 提供者の設定の名前、ベースの URL、モデルの組。推論の内容を送り返してよいかの判定に使う | 01-04、02-01 |
| 推論の内容 | reasoning content | モデルが返す推論の文と、送り返しを求められる不透明なデータ（Anthropic の thinking のブロックと署名など） | 01-04、02-01 |
| プロンプトのキャッシュ | prompt cache | 提供者が、要求の先頭の一致する部分の処理を使い回す仕組み | 01-04、02-01 |
| 圧縮 | compaction | 文脈が大きくなったときに、会話の古い側を要約に置き換えること | 01-04 |
| 超過したときの圧縮 | overflow compaction | 提供者が文脈の超過を返したときに、会話を文字にした別の要求で要約を作る圧縮 | 01-04 |
| プロジェクトのディレクトリ | project directory | セッションが対象とするディレクトリ。既定は作業ディレクトリ | 01-02、05-01 |
| 一時ディレクトリ | session temp directory | セッションごとに作り、終わりに消すディレクトリ。一時的なスクリプトと子プロセスの一時ファイルを置く | 01-05 |
| 一時的なスクリプト | scratch script | `benitoite_scratch` で一時ディレクトリに書いて実行する Benitoite のスクリプト | 01-03 |
| OS のサンドボックス | OS sandbox | カーネルが範囲の外の操作を拒否する仕組み。試作では macOS の Seatbelt と、Linux の bubblewrap と Landlock と seccomp | 03-02 |
| サンドボックスの方針 | sandbox policy | 子プロセスに許す、読める範囲・書ける場所・ネットワーク・起動できるプログラムの組 | 03-02 |
| 書ける場所 | writable roots | サンドボックスの方針で、子プロセスが書き込めるディレクトリ | 03-02 |
| 守る場所 | protected paths | 書ける場所の中で、子プロセスにも道具にも書かせない場所（`.git` と `.benitoiteh`） | 03-02 |
| 書ける場所の検査 | writable-root check | 起動のときと `create_project` のときに、書ける場所がホームディレクトリや `benitoiteh` の設定・データのディレクトリと重ならないかを確かめること | 03-02 |
| 外部の Unix IPC | external Unix IPC | サンドボックスの外のプロセスとの、Unix ドメインのソケットによる通信 | 03-02 |
| 補助のプロセス | sandbox helper | Linux で、`benitoiteh` が bubblewrap の中で自分を `__sandbox` で起動し直し、サンドボックスを自分に掛けてから目的のプログラムを `exec` するプロセス | 03-02 |
| 実行の前の確認 | pre-run confirmation | 制限モードで、スクリプトを実行する前に、`main` の宣言したエフェクト（テストでは選んだテストの関数の和）を利用者に示して承認を受けること | 03-03 |
| 実行の前の検査の報告 | inspection report | 処理系が、スクリプトを実行せずに検査し、宣言したエフェクトの上限、読み込んだソースとそのハッシュ、診断を一つの JSON で返したもの（`check --report=json`・`test --check --report=json`）。確認とサンドボックスに使うエフェクトをここから得る | 04-01 |
| 確認なしの範囲 | auto-run effects | 一時的なスクリプトを確認なしで実行してよいエフェクトの集合 | 03-03 |
| 承認の方針 | approval policy | 通常モードで、どの操作に利用者の承認を求めるかの規則 | 03-03 |
| 書いた後の検査 | check after write | 制限モードで、`.bnt` のファイルを書いた後に `benitoiteh` が行う検査 | 01-03 |
| 検査と修正の回数 | check-fix count | 同じスクリプトについて、検査が誤りを返した回数 | 01-01 |
| 巻き戻し | rewind | 記録した時点のプロジェクトのファイルと会話に戻すこと | 01-05 |
| 非対話 | non-interactive | `benitoiteh exec` で、確認を対話で受けずに一つの依頼を処理する使い方 | 05-01 |
| 事前検討 | pre-study | Benitoite のリポジトリにある、エージェントハーネスの検討（初回リリース版の設計書の写しの 06-08 と ADR、docs/todo の項目） | 00-01、08-02 |
