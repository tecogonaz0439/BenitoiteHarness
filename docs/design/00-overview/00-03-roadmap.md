## 目的と範囲

本章は、設計から試作の完了までの段階、各段階の完了条件、作業の分担、試作の後の判断の基準を定める。

## 前提

- 設計から試作までを Claude Code で行い、Codex を使わない（利用者の要件。`AGENTS.md`）。
- Benitoite の処理系は、設計書と実装プランを Claude Code が作り、実装を LLM のサブエージェントが実装プランに従って行い、Claude Code がオーケストレータとしてすべての作業を確かめる形で作られた（Benitoite の AGENTS.md の「プロジェクトの概要」）。

## 仕様

### 進め方

【方針】

1. 設計書（本書）を作り、外部のレビュー（ChatGPT Pro）を受けて直す。
2. 段階ごとに、実装プラン（`docs/plan/`）を作る。実装プランは、設計書と実装プランだけを読めば実装できる粒度で書く。
3. Claude Code がオーケストレータとして、実装の作業をサブエージェントに配る。作業ごとに git のブランチと作業ツリー（git worktree）を分け、オーケストレータが確かめてから `main` に取り込む。
4. 段階の完了条件を確かめたら、設計書の【方針】を、確かめた内容に合わせて【決定】に改めるか、直す。

### 作業の分担

【方針】

- 設計書、実装プラン、作業の確かめ、取り込み、設計書の更新は、オーケストレータ（Claude Code）が行う。
- 実装は、実装プランの作業ごとにサブエージェントが行う。サブエージェントの定義は、Benitoite の `impl-medium`・`impl-low` に倣って、P0 で `.claude/agents/` に置く。
- 本物の LLM の API を呼ぶ確かめと評価は、設計者の了承を得てから行う。

### 試作の後の判断

試作を終えたら、Benitoite の処理系にマージするか、独立したままとするかを設計者が決める（BH-080）。判断の材料として、次の点を P6 で報告する。

- **安全の性質**: 制限モードの保証（[セキュリティモデル](../03-safety/03-01-security-model.md)の R1〜R5）が、macOS と Linux で確かめられたか。確かめられなかった点は何か。
- **性能**: 実行ファイルの大きさと速さの目標を満たしたか。Benitoite の課題での成功率と回数が、同じモデルの Claude Code と比べてどうか。
- **事前検討との差**: サーバモードの代わりに OS のサンドボックスを掛けた作りで、事前検討がサーバモードに求めた性質（エージェント用のプロファイル、承認の画面での認証、監査の記録）のうち、何が欠けているか。
- **マージの形の候補と代償**:
  - (a) 処理系の `agent` のサブコマンドとして取り込む。利用者に配る実行ファイルが一つになる。代償は、処理系の実行ファイルに提供者の層と画面の依存が加わること（処理系は約 30 MB なので、大きさの比は小さい）、事前検討の ADR 0342 の決定 3 を改めるか、サーバモードを先に作る必要があること。
  - (b) 同じリポジトリの別のクレートと別の実行ファイルにする。処理系と同じ版で配れ、実行ファイルは小さいまま保てる。
  - (c) 独立したリポジトリのままとする。処理系の版との対応を、取り込んだ文書の版で管理し続ける。
- **処理系への要望**: 試作で見つけた、処理系に欲しい機能（[Benitoite の処理系との連携](../04-benitoite/04-01-benitoite-integration.md)の「処理系への要望」）。

### サーバモードの実装の後の見直し

【決定】Benitoite にサーバモードと、エフェクトに基づく実行時の権限制御が実装された後に、その実装を確かめて、試作のハーネスの作りを見直す（2026-10-16 の設計者の方針）。見直す点は、[目的と設計原則](00-01-goals.md)の「事前検討との関係」の表の点、特に次のものである。この見直しは試作の後の判断（前節）とは別に、サーバモードの実装の時期に合わせて行う（BH-081）。

- 処理系の CLI を子プロセスとして起動する作りを、デーモンの通信口に直接つなぐ作り（ADR 0346）に改めるか。
- `benitoiteh` が掛ける OS のサンドボックスと、サーバモードのエージェント用のプロファイル（ADR 0192）の分担。
- 実行の前の確認と、サーバモードの承認の画面の関係（ADR 0345 の決定 2）。
- `main` のエフェクトの読み取りを、サーバモードの実行前の判定の結果に置き換えるか。
