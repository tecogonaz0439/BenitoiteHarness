# 秘密の入力

- 状態: 草稿
- 未決事項: BH-103, BH-105, BH-107

## 目的と範囲

本章は、`benitoiteh` が起動するプログラムやスクリプトが、利用者の秘密（パスワード、SSH の鍵のパスフレーズ、ハードウェアの鍵（YubiKey など）の PIN、パスワードの管理の道具（KeePass など）の主のパスワード）を要するときの扱いを定める。手段は三つの段に分けて順に用意する。MCP とプラグインをこの用途に使わない理由も本章に書く。

本章の内容は 2026-10-19 に設計者が承認した方向である。段 1 と段 2 は P6 の前に作り、段 3 と、サンドボックスの中からの仲介は後に回す。

## 前提

- 道具が起動する子プロセスは、新しいセッションで起動し、制御の端末を持たせない（[OS のサンドボックス](03-02-sandbox.md)の「端末からの切り離し」）。このため、`ssh` などが端末からパスフレーズを読もうとしても、今は利用者が答えられない。
- Linux のサンドボックスは、seccomp で Unix ドメインのソケットの作成を常に拒否する（同章の「方針の要素」）。このため、サンドボックスの中から `ssh-agent` などのソケットに接続できない。macOS の Seatbelt の方針で接続できるかは確かめていない。
- LLM の文脈に入った内容は、提供者へ送られ、セッションの記録に残る（[文脈の管理](../01-agent/01-04-context.md)の「送る内容の表示」）。

## 仕様

### 秘密を LLM に通さない

【決定】秘密は、利用者から、それを要するプログラムへ直接渡す。LLM の文脈、道具の結果、セッションの記録、画面の履歴、提供者への要求のどれにも入れない（2026-10-19 に設計者が承認した）。理由: LLM の文脈に入った秘密は提供者へ送られ、記録に残り、後の要求でも送られ続ける。LLM の出力は信頼しない（[セキュリティモデル](03-01-security-model.md)の「関係する者と信頼」）ので、LLM に秘密を扱わせる作りは、秘密を信頼しない者に渡すことになる。

### 段 1: すでにある秘密の仲介役を使う

【方針】まず、利用者がすでに使う秘密の仲介役（エージェントと GUI の入力の窓）を、子プロセスから使えるようにする。秘密はハーネスの外の窓や仲介役の中だけで扱われ、`benitoiteh` を通らない。

- SSH: `ssh-agent` に、利用者が前もって鍵を読み込ませる（macOS のキーチェーンとの連携や、KeePassXC の SSH エージェントの機能を含む）。
- ハードウェアの鍵: `gpg-agent` と GUI の PIN の入力の窓（macOS の `pinentry-mac` など）。FIDO の鍵（`ed25519-sk` の形の SSH の鍵）のタッチと PIN も、同じく仲介役か GUI の窓で受ける。
- パスワードの管理の道具: KeePassXC の SSH エージェントの機能など、管理の道具が持つ仲介の仕組み。

【決定】段 1 は、サンドボックスに穴を開けず、通常モードの「範囲の外の実行の要求」（`bash` の `escalate`。利用者がその一回を承認し、サンドボックスの外で起動する。[OS のサンドボックス](03-02-sandbox.md)の「通常モードの方針」、[利用者の確認](03-03-approval.md)の「通常モードの承認の方針」）で、仲介役を使う（2026-10-19 に設計者が決めた）。サンドボックスの中から仲介役の窓口へ接続することは、今までどおりどの OS でも許さない（03-02 の「方針の要素」の、外部の Unix の IPC を拒む規則）。制限モードは、今までどおり `ssh` などのほかの仕組みにプロセスを起動させるプログラムを許さない（03-02 の「制限モードで実行を許すプログラム」）。理由: 仲介役の窓口をサンドボックスの中に開くと、LLM が打ったコマンドが、利用者の承認なしに利用者の鍵で署名できるようになる。範囲の外の実行の要求なら、鍵を使う一回ごとに利用者が承認する。

- 2026-10-19 に、macOS で、`benitoiteh` の端末から切り離す補助（`benitoiteh __session`。新しいセッションで、制御の端末を持たず、標準入力は空）を通して起動した `ssh-add -l` が、利用者の `ssh-agent` に接続できることを確かめた（終了状態 0。範囲の外の実行の要求は、サンドボックスを掛けずにこの補助だけを通して起動する）。
- 【要検証】Linux で同じく接続できるか、GUI の入力の窓（`pinentry-mac`、`ssh-askpass`、FIDO の鍵のタッチ）が、制御の端末を持たない範囲の外の実行から出せるかは、確かめていない（BH-103）。

### 段 2: `benitoiteh` が秘密の入力を仲介する

【決定】最初の版は、通常モードで、範囲の外の実行の要求（`escalate`）を利用者が承認してサンドボックスの外で起動したコマンドと、サンドボックスを掛けない設定（`danger-full-access`）で起動したコマンドだけを仲介する（2026-10-19 に設計者が決めた。BH-104 を閉じた）。サンドボックスの中のコマンドからの求めは仲介せず、制限モードと非対話の実行（`exec`）でも仲介しない。理由: サンドボックスの中のコマンドは `~/.ssh` などの鍵を読めず、仲介役への Unix のソケットも使えないので、秘密を要する操作のほとんどは、もともとサンドボックスの外で行う（段 1 と同じ）。サンドボックスの中から主のプロセスへ届く通り道（名前付きのパイプなど）は、ほかのプロセスの横取りや、確かめの残る点が多いので、後に回す。

- **求めの形**: OpenSSH の `SSH_ASKPASS`、Git の `GIT_ASKPASS`、`sudo -A` の `SUDO_ASKPASS` を仲介する。どれも、求めの文を一つ目の引数として補助のプログラムを起動し、補助が標準出力に書いた一行を答えとして読み、補助が 0 以外で終われば失敗とする（openssh/openssh-portable のコミット `26b1363c` の `readpass.c`、git/git の `c5140888` の `prompt.c`、sudo-project/sudo の `5e3b8b04` の `src/tgetpass.c`）。OpenSSH は、端末も `DISPLAY` もないときに補助を使わないので、`SSH_ASKPASS_REQUIRE=force` を添える。OpenSSH の確かめの求め（`SSH_ASKPASS_PROMPT=confirm`。答えなしで 0 なら許す）と、FIDO の鍵のタッチの知らせ（`SSH_ASKPASS_PROMPT=none`。タッチが済むと終了の合図で止められる）も扱う。`gpg` の `pinentry` は、`gpg-agent` が起動するもので、求めた者を見分けられないので仲介しない（段 1 のまま）。
- **補助**: 補助は `benitoiteh` 自身とし、セッションごとに作る、利用者だけが読み書きできるディレクトリ（パスは Unix のソケットの名前の上限に収まる短さにする）に、`benitoiteh-ssh-askpass`・`benitoiteh-git-askpass`・`benitoiteh-sudo-askpass` の名前で実行ファイルへのシンボリックリンクを置く。`benitoiteh` は、起動の名前（`argv[0]` の最後の要素）がこれらのときに補助として動く。理由: `SSH_ASKPASS` は引数を足せない。ディレクトリは、利用者ごとの親（`bha-<実効の利用者の ID>`。自分の持ち物、0700、リンクでないことを確かめる）の下に、セッションごとに作る。親は、Linux では `$XDG_RUNTIME_DIR`（自分の持ち物で 0700 のとき）、なければ一時の根（`TMPDIR`）の下に置き、ソケットのパスが上限を超えるときか、サンドボックスから書ける場所の下になるときだけ `/tmp` の下に置く。macOS では、パスを短くするため、子の名前をセッションの ID の乱数の部分とする。【方針】子を作ったら、リンクとソケットを置く前に、子の中に、セッションの ID の全体と改行を書いたファイル `id` を置く（新しく作り、リンクを辿らず、0600。2026-10-20 の点検で加えた）。子を作り直すときと後始末のときは、`id` を、リンクを辿らずに、自分の持ち物の 0600 の通常のファイルでリンクの数が 1、64 バイトまでであることを確かめて読み、後始末ではその ID で錠と記録を確かめる。作り直すときに、同じ名前の子の `id` が自分のセッションの ID でなければ（`id` がないときと読めないときを含む）、その子を消さずに仲介を止める。`id` のない子（前の版が作ったもの）は、後始末だけ、名前とセッションの記録が一つだけ対応するときに消す（今までの形）。理由: 乱数の部分だけでは、ほかのセッションと名前が重なりうるので、名前から ID を一つに決められない。ID の全体を子の名前にしないのは、macOS の一時の根が長く、ソケットのパスが上限を超えうるからである。親と子は、仲介する呼び出しの前と後始末のたびに、作ったときと同じもの（dev と inode）であることを確かめ、違えば仲介を止める。サンドボックスから書ける場所の下には置かない（サンドボックスの中から補助を起動しても、決まった文で失敗するだけにするため）。【方針】共有の `/tmp` では、ほかの利用者が先に同じ名前の親を作ると、仲介を使えなくなる（乗っ取りは所有者の確かめで防ぐ）。この場合は、その旨と、`TMPDIR` を利用者だけの場所に向ける案を示す。
- **子プロセスの環境**: 通常モードの `bash` の子プロセスには、いつも `SSH_ASKPASS`・`SSH_ASKPASS_REQUIRE=force`・`GIT_ASKPASS`・`SUDO_ASKPASS` を補助に向け、`GIT_TERMINAL_PROMPT=0` を加える。仲介する呼び出し（上の範囲の、対話の実行）にだけ、主のプロセスの窓口（同じディレクトリの Unix のソケット）のパスと、その呼び出しに限る乱数の合言葉（32 バイト）を加える。合言葉は呼び出しが終わったら無効にする。利用者が自分の `SSH_ASKPASS`（段 1 の GUI の窓など）を使いたいときのために、設定で補助を向けないようにできる。理由（合言葉）: GitHub Desktop と JetBrains の IDE が、操作ごとの乱数の合言葉で求めを確かめる（desktop/desktop の `bebc062c` の `app/src/lib/trampoline/trampoline-tokens.ts`、JetBrains/intellij-community の `cd567b2b` の `ExternalProcessHandlerService.kt`）。合言葉がなければ、同じ利用者のほかのプロセスが、生きている呼び出しの名で求めを出せる。
- **補助の振る舞い**: 補助は標準入力を読まない。合言葉か窓口がなければ（サンドボックスの中、制限モード、非対話の実行、仲介しない呼び出し）、`Secret input is only available for commands approved to run outside the sandbox in interactive sessions.` の形の一行を標準エラー出力に書き、1 で終わる（LLM はこの文を見て、範囲の外の実行の要求を出せる）。窓口があれば、合言葉、求めの種類（起動の名前と `SSH_ASKPASS_PROMPT`）、求めの文（4 KiB まで）、自分と親のプロセスの番号を送り、答えに従って、秘密と改行を標準出力に書いて 0 で終わるか、確かめに許されて何も書かず 0 で終わるか、1 で終わる。
- **主のプロセス**: 窓口は別のスレッドで受け、読む時間と大きさに上限を掛ける。知らない合言葉と無効にした合言葉は断る。Linux では、つないできたプロセスの利用者の ID が自分と同じことも確かめる。求めは一度に一つずつ画面に出し、一つの呼び出しで出せる求めは 3 回までとする（OpenSSH の `NumberOfPasswordPrompts` の既定と同じ）。答えを覚えて使い回さない。利用者の答えを待つ時間は、`bash` の時間の上限に数えない。呼び出しが終わるか、取り消されるか、時間の上限に達したら、合言葉を無効にし、出している求めを閉じる。
- **入力の欄**（[対話の画面](../05-interface/05-02-tui.md)）: `benitoiteh` が示す事実として、サンドボックスの外のコマンドが秘密を求めていること、道具の呼び出しの番号とコマンドの全体（制御文字は確認の画面と同じく見える形にする）、モード、作業のディレクトリを示す。補助が送ったプロセスの番号と求めの種類は、「補助の報告で、確かめていない」として示す。求めの文は、子プロセス（や、その先の SSH のサーバ）が決める信頼しない文として、事実と区別した枠に、10 行までで示す。理由: 秘密を受け取るのは、LLM が打ったコマンドでありうる。偽りの求めの文で秘密を聞き出すことを、利用者が見分けられるようにする。入力は伏せ字とし、見せる操作を別に設ける。確かめの求めは「はい」「いいえ」で、タッチの知らせは答えを求めない知らせで示す。ESC は取り消しとする。欄を示す前と、示してから 300 ミリ秒の間のキーの入力は捨てる（[利用者の確認](03-03-approval.md)の「確認の共通の規則」と同じ考え）。利用者の操作のほかの理由（補助の切断、呼び出しの終わり）で欄が閉じたときは、閉じたことを示す欄を残し、ESC を押すまでのキーと貼り付けをすべて捨てる。取り消しで閉じた後も、300 ミリ秒の間のキーは捨てる。理由: コマンドは欄を閉じる時刻を選べるので、打ちかけの秘密の残りが、ふだんの入力の欄に入って LLM へ送られるのを防ぐ。
- **秘密の扱い**: 秘密は主のプロセスのメモリーに、補助へ渡すまでの間だけ置き、渡したら消す（`zeroize` クレートで上書きする。依存を加えるので、大きさを測って記録する）。セッションの記録、画面の履歴、道具の結果には、求めを示した・答えた・取り消したことだけを書く。加えて、その呼び出しの出力を LLM と記録に渡す前に、秘密と同じ並びを伏せ字に置き換える。置き換えは、出力を切り詰める前に、標準出力と標準エラー出力のそれぞれと、混ぜた並びの両方に掛ける。秘密そのものは補助に渡したら消すので、照合には秘密の長さと SHA-256 と、呼び出しごとの乱数を使う rolling hash の値を残し、rolling hash で候補を絞ってから SHA-256 で確かめる。【方針】照合のために留めておく出力は、ストリームごとに、最も長い秘密の長さより 1 バイト短い分までとし、さらに、留めた中の最後の改行（`\n`）・復帰（`\r`）・NUL までは留めずに渡す（2026-10-20 の点検で改めた）。照合の値は、これらのバイトを含む秘密には作らない（入力の欄と窓口は、これらのバイトを含む秘密をもともと受け付けない）。理由: 秘密がこれらのバイトを含まないので、秘密と一致する並びはこれらのバイトをまたがず、その手前までを渡しても見逃さない。決まった長さだけ留める形では、行の終わりまで届いた出力も次の出力まで示されず、標準出力と標準エラー出力を混ぜた並びの順も、実際に書かれた順と違ってしまう。【方針】照合の値（長さ、SHA-256、rolling hash）も、秘密と同じく `zeroize` クレートで上書きして消し、呼び出しの状態は、呼び出しが終わったときに手放す（今は次の呼び出しまで残る）。SHA-256 を計算する途中の状態も消す（`sha2` の機能 `zeroize`。`sha2` 0.11.0 の `src/block_api.rs` の `Sha256VarCore` の `Drop` が、この機能で状態を上書きする）。理由: 短いパスワードは、残った SHA-256 の値から総当たりで求めうる。秘密を受け取る前の出力は照合しない（秘密を含みえないため。受け取る前から秘密の一部を知っているコマンドの出力は、形を変えた出力と同じく防げない）。仲介した呼び出しの出力は、ディスク（`spill/`）に書かずメモリーだけに置く。ただし、受け取ったコマンドが形を変えて出力すれば防げないので、秘密を受け取ったコマンドは秘密を外へ出しうることを、入力の欄に示す。
- **調べた先行事例**: VS Code（microsoft/vscode の `7b3a37f0` の `extensions/git/src/askpass.ts`）と Zed（zed-industries/zed の `56934ec0` の `crates/askpass`）は、利用者だけが使えるディレクトリの Unix のソケットで補助とつなぎ、Zed は操作ごとに窓口を作る。どれもアプリ自身が始めた Git や SSH の操作を仲介するもので、エージェントが選んで打ったコマンドの求めを仲介するハーネスは見当たらなかった（Codex CLI は自分の Git の呼び出しに `GIT_TERMINAL_PROMPT=0` を加えるだけ。openai/codex の `89461ea`）。

### 段 3: Benitoite のスクリプトで秘密を受け取る

【未決】Benitoite の処理系に、秘密を伏せ字で読む標準の関数と、それを表すエフェクト（例えば `Console.ReadSecret`）を求め、その入力を段 2 の仲介で渡す（BH-105）。エフェクトとして宣言されるので、実行の前の確認で、そのスクリプトが秘密の入力を求めることを利用者に示せる（[利用者の確認](03-03-approval.md)の「制限モードの確認」）。処理系の変更が要るので、段 2 を作った後に、処理系への要望として出す（[Benitoite の処理系との連携](../04-benitoite/04-01-benitoite-integration.md)の「処理系への要望」の 9）。

### 制限モードでの SSH の接続

【方針】制限モードでは、`ssh` のプログラムを許さない（[OS のサンドボックス](03-02-sandbox.md)の「制限モードで実行を許すプログラム」）。制限モードで SSH の接続が要る作業は、Benitoite の処理系が SSH の接続のライブラリ（処理系の中で接続を実装し、外部のプログラムを起動しないもの）を持った後に、そのライブラリで行う（2026-10-19 に設計者が承認した）。理由: `ssh` は接続の設定（`ProxyCommand`・`LocalCommand`）やリモートでのコマンドの実行で任意のプログラムを起動できるので、許すと制限モードの保証（Benitoite 以外の言語の処理系を起動させない）を回り込める。処理系の中のライブラリなら、外部のプログラムを起動せず、接続はエフェクトとして宣言されて実行の前の確認に現れる。処理系の側は、git などと同じく SSH の接続のライブラリを作る予定である（設計者による）。

ライブラリの形が決まった後に、`benitoiteh` の側で次を設計する（BH-107）。

- **エフェクトとサンドボックスの対応**: SSH の接続のエフェクトを実行の前の確認に示し、許したときだけ OS のサンドボックスでネットワークを開く（今は `Http.Connect`・`Http.Listen` だけをネットワークに対応させている。[OS のサンドボックス](03-02-sandbox.md)の「制限モードの方針」）。
- **鍵の扱い**: 制限モードのサンドボックスは `~/.ssh` を読ませず、仲介役のソケットにも接続させない。ライブラリが鍵のファイルを読むなら読ませる場所の扱いを、`ssh-agent` を使うなら特定のソケットだけを許す形を、パスフレーズを求めるなら段 3 の秘密の入力のエフェクトとの組み合わせを決める。
- **接続先の確かめ**: ホストの鍵（`known_hosts`）を誰がどこで確かめ、初めての接続先をどう扱うか。

### MCP とプラグインを秘密の入力に使わない理由

【方針】秘密の入力のために MCP やプラグインを使わない。理由: MCP の道具の結果は LLM の文脈に入るので、例えばパスワードの管理の道具の MCP サーバでパスワードを取り出すと、そのまま提供者へ送られ、「秘密を LLM に通さない」に反する。MCP とプラグインは、試作の範囲の外のままとする（[目的と設計原則](../00-overview/00-01-goals.md)の「範囲」）。試作の後に、通常モードに限って加えるかを考える。外部の道具は Benitoite の型とエフェクトの検査を通らないので、制限モードには加えない。
