# モード

- 状態: 草稿
- 未決事項: BH-001, BH-002

## 目的と範囲

本章は、`benitoiteh` の二つのモード（制限モードと通常モード）を定義し、モードごとに LLM に与える道具、書き込める範囲、子プロセスに掛ける OS のサンドボックス、確認の規則の組み合わせを一つの表にまとめる。各項目の詳細は、[道具](01-03-tools.md)、[OS のサンドボックス](../03-safety/03-02-sandbox.md)、[利用者の確認](../03-safety/03-03-approval.md)で定める。

## 前提

- 制限モードは、Benitoite の事前検討が採った操作の範囲（[ADR 0344](https://github.com/tecogonaz0439/Benitoite/blob/v0.0.7/docs/archive/2026-10-09-design-first-release/decisions/0344-agent-harness-operation-scope-and-tools.md) の (γ)。スクリプトの作成・検査・実行と、プロジェクトの中のファイルの一覧と読み取り）に当たる。
- 通常モードは、事前検討になかったものであり、利用者の要件（一般的なハーネスと同じく振る舞うモード）による。
- モードはセッションの間変えない（[セキュリティモデル](../03-safety/03-01-security-model.md)の「モードを変える操作」）。

## 仕様

### 制限モード

【決定】制限モードは、LLM に許す操作を、Benitoite のスクリプトの作成・検査・実行と、プロジェクトの中のファイルの読み取りに限るモードである。シェルを道具として持たせず、Benitoite 以外のスクリプト言語（sh、Python など）の処理系を起動させない。

制限モードの「Benitoite 以外の言語の処理系を起動させない」は、次の三層で守る。どれか一つが破れても、残りの層で起動を防ぐことを狙う。

1. **道具の層**。LLM に与える道具に、シェルと、任意のプログラムを起動する道具がない。書ける道具は `.bnt` のファイルにしか書けない（[道具](01-03-tools.md)の「モードごとの道具の一覧」）。
2. **確認の層**。スクリプトの実行の前に、`main` のエフェクトを利用者に示して確認を受ける。`Process.Run`（外部コマンドの起動）を含むスクリプトは、確認の画面で強く警告する（[利用者の確認](../03-safety/03-03-approval.md)の「制限モードの確認」）。
3. **OS の層**。処理系の子プロセスに OS のサンドボックスを掛け、処理系自身と利用者の設定で許したコマンドのほかは、実行ファイルの起動を拒否する（[OS のサンドボックス](../03-safety/03-02-sandbox.md)の「制限モードで実行を許すプログラム」）。

理由: 道具の層だけでは、`Process.Run` を使うスクリプトから `sh` を起動できる。確認の層は利用者が誤って承認しうる。OS の層は、利用者が許すプログラムの設定を誤らない限り、LLM の出力と確認の誤りに依らずに働く。ほかの二層は、OS の層に達する前に止めて、利用者に理由を示すためにある。

### 通常モード

【決定】通常モードは、シェルのコマンドの実行とファイルの編集の道具を持つ、一般的なコーディングエージェントのハーネスとして振る舞うモードである。Benitoite の検査と参照の道具も使える。

【方針】通常モードの既定は、プロジェクトのディレクトリと一時ディレクトリにだけ書け、ネットワークを使えない OS のサンドボックスの中でコマンドを動かし、その範囲を超える要求だけを利用者に確認する形とする。この既定は Codex CLI の既定（workspace-write のサンドボックスと on-request の承認）に倣う（[先行事例](../08-appendix/08-01-prior-art.md)）。理由: 既定で確認を多く求めると利用者は確認を読まずに承認するようになり、確認の意味が薄れる。サンドボックスの中の操作を確認なしで許し、外に出る操作だけを確認すれば、確認の回数を減らしつつ守るものを守れる。

### モードごとの組み合わせ

| 項目 | 制限モード | 通常モード |
|---|---|---|
| ファイルの読み取り（道具） | プロジェクトの下と、セッションの一時ディレクトリと、切り詰めた出力の置き場所（`spill/`）だけ。読まないファイルの規則に従う | 読まないファイルの規則に従う。プロジェクトの外も読める |
| ファイルの書き込み（道具） | プロジェクトの下と一時ディレクトリの `.bnt` だけ | サンドボックスの方針の範囲（既定はプロジェクトの下と一時ディレクトリ） |
| シェルのコマンド | なし | `bash` の道具 |
| Benitoite の検査・参照 | あり | あり |
| Benitoite の実行 | 道具で行い、実行の前の確認を受ける | `bash` の道具で `benitoite run` を打つ。サンドボックスの方針に従う |
| 子プロセスの書き込み | 一時ディレクトリ。プロジェクトの下は `File.Write` を確認したときだけ | サンドボックスの方針の範囲 |
| 子プロセスのネットワーク | `Http.Connect`・`Http.Listen` を確認したときだけ | サンドボックスの方針の範囲（既定は使えない） |
| 子プロセスが起動できるプログラム | 処理系と、利用者が許したコマンド（`Process.Run` を確認したときだけ）だけ | 制限しない |
| 確認 | 実行の前の確認（エフェクト） | 承認の方針（サンドボックスの外に出る要求） |
| OS のサンドボックスを掛けられないとき | 起動しない | 利用者が明示したときだけ、サンドボックスなしで動く |
| プロジェクトの指示のファイル | 読むかは BH-042 で決める | 読む |

### モードの選び方

【方針】モードは起動のときのオプション（`--mode restricted` か `--mode normal`）で選ぶ。オプションを省いたときの既定は、利用者の設定ファイルの `default_mode` に従い、設定もなければ制限モードとする（[CLI と設定ファイル](../05-interface/05-01-cli.md)）。理由: 指定を忘れたときに、狭い方のモードに収まるようにする。Benitoite の事前検討が非対話の `--allow` を省いたときに狭い範囲に収めると定めたこと（ADR 0345 の決定 4）と同じ考え方である。

プロジェクトの設定ファイルでは既定のモードを変えられない（[セキュリティモデル](../03-safety/03-01-security-model.md)の「信頼の境界」）。

### 道具の一覧を固定する理由

【方針】一つのセッションの中では、LLM に見せる道具の一覧と、システムプロンプトを変えない。理由: 道具の定義とシステムプロンプトは、LLM の提供者の要求の先頭に置かれ、プロンプトのキャッシュの単位になる。セッションの途中で変えると、以後の要求でキャッシュが効かなくなり、応答の時間と費用が増える。DeepSeek Harness は同じ理由で、計画のモードでも道具の一覧を変えずに実行の側で拒否している（[先行事例](../08-appendix/08-01-prior-art.md)）。モードをセッションの間変えないことは、この性質も満たす。

モードの名前と、モードの数を二つに限るかは、試作の評価の後に見直す（BH-001）。制限モードに、Benitoite のスクリプトから道具を呼ぶ形（DeepSeek Harness の PTC モードに当たる、スクリプトの中から `read` などを呼ぶ形）を加えるかは BH-002 で扱う。
