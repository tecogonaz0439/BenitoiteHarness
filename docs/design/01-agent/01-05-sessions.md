# セッション

- 状態: 草稿
- 未決事項: BH-016, BH-098

## 目的と範囲

本章は、`benitoiteh` のセッション（一度の起動で続ける会話と、それに伴う状態）の記録、再開、巻き戻し、一時ディレクトリの扱いを定める。記録の置き場所の全体は[CLI と設定ファイル](../05-interface/05-01-cli.md)の「データの置き場所」で定める。

## 前提

- Benitoite の事前検討は、巻き戻しをプロジェクトのディレクトリの状態をまるごと記録して戻す形（型 2）と定め、会話の保存と再開は初めは設けないとした（[ADR 0348](https://github.com/tecogonaz0439/Benitoite/blob/v0.0.7/docs/archive/2026-10-09-design-first-release/decisions/0348-agent-harness-rewind-and-git.md)、Benitoite の docs/todo の TODO-134・TODO-140）。
- LLM を使ったテストの用途では、提供者・モデル・処理系の版、検査と修正の回数、LLM とのやり取りの全体、トークンの量を記録する見立てがある（Benitoite の docs/todo の TODO-126）。
- Codex CLI、Pi、DeepSeek Harness は、どれもセッションを追記だけの JSON Lines のファイルに記録し、再開できる（[先行事例](../08-appendix/08-01-prior-art.md)）。

## 仕様

### セッションの記録

【方針】セッションごとに一つの JSON Lines のファイル（`session.jsonl`）を、セッションのディレクトリに置く。ファイルには追記だけを行い、書いた行を書き換えない。理由: 途中で `benitoiteh` が異常に終わっても、それまでの記録が残る。

- 1 行目はヘッダの行とし、記録の形式の版、セッションの ID、開始の時刻（UTC）、`benitoiteh` の版、モード、プロジェクトのディレクトリ、提供者の設定の名前とベースの URL とモデル、処理系のパスと、その実行ファイルの SHA-256 の値、`--version=json` の版とビルドの情報、処理系から得た `SKILL.md` の SHA-256 の値、システムプロンプトと道具の定義の SHA-256 の値を書く。評価のための切り替え（`restricted.after_write_check`、`read.line_numbers`。[道具](01-03-tools.md)）を既定と違う値にしたときは、その値も書く。
- 2 行目以降は、[エージェントのループ](01-01-agent-loop.md)の「イベント」を、ストリーミングの途中の差分（`text_delta`・`reasoning_delta`）を除いて書く。応答は、一つの応答を受け取り終えた時点で一行にまとめる。
- 応答は、共通の形に変えたものに加えて、提供者が返した項目を、順序と識別子を変えずに記録する（[提供者の層](../02-providers/02-01-provider-layer.md)の「共通の形」）。推論の内容のうち暗号化された項目と署名（再開のときに送り返すのに要る）も含む。
- 確認の要求と結果、圧縮の要約、巻き戻し、プロジェクトのディレクトリの変更、利用者の入力を記録する。
- 子プロセスを起動する道具と書く道具は、実行を始める前に、始めたことを一行書く。結果は、実行が終わった後に一行書く。理由: 実行を始めた後、結果を書く前に `benitoiteh` が異常に終わったとき、その呼び出しが実行されたかもしれないことを、再開のときに知るためである。
- 各行は書いたらすぐにファイルに書き出す（`flush`）。一つの行の大きさの上限は 16 MiB とし、超える内容（大きな道具の結果など）は `spill/` に置いて、行にはその場所を書く。
- API キーとトークンは書かない。HTTP の要求のヘッダも書かない。

記録の形式は試作の途中で変わりうるので、ヘッダの行の版で区別し、試作の間は前の版の読み込みを保証しない。利用者に約束する JSON の形（BH-012）とは別に、再開に要る記録の形は、P1 で形式の版 1 として定めた（[実装プラン](../../plan/tasks/P1-05-session.md)）。各行は `type` の欄で種類を分け、`header`・`session_start`・`turn_start`・`user`・`assistant`（提供者の元の項目を含む）・`tool_call`・`tool_start`・`tool_result`・`approval`・`retry`・`error`・`turn_end`・`session_end`・`summary` と、後の段階で使う `project_dir_changed`・`rewind`・`compaction` を持つ。16 MiB を超える行は、元の JSON を `spill/` の下のファイルに分けて置き、行には `spilled` の種類でその場所を書く。

### LLM を使ったテストのための記録

【方針】非対話の実行（[CLI と設定ファイル](../05-interface/05-01-cli.md)の「exec の出力」）では、セッションの記録に加え、終わりに一行の集計を書く。集計は、番の数、道具ごとの呼び出しの回数、検査と修正の回数、確認の結果、トークンの量（入力、キャッシュから読んだ量、キャッシュに書いた量、出力）、かかった時間、終わり方を含む。理由: Benitoite の Skill の評価の記録（Benitoite の設計書 06-06「Skill の評価」）と同じ項目を、ハーネスの側で直接数えられる。評価の道具はこの集計を読む（[評価](../07-quality/07-02-evaluation.md)）。

### 再開

【方針】`benitoiteh --resume <ID>` で、記録したセッションを再開する。`--continue` は、同じプロジェクトのディレクトリの最も新しいセッションを再開する。

- 再開したセッションは、同じセッションの ID のまま、同じ記録のファイルに追記する。ヘッダの行は書き直さず、再開したことを `session_start` の行に、そのときの提供者の設定の名前、ベースの URL、モデル、モード、システムプロンプトと道具の定義のハッシュとともに書く。理由: 一つの作業の記録が一つのファイルにまとまり、前に示した `spill/` のパスをそのまま読める。
- 動いているセッション（セッションのディレクトリのロックのファイルの錠が取れないもの）は再開しない。`--continue` は、記録の最後のプロジェクトのディレクトリ（実のパス）が今のプロジェクトのディレクトリと同じセッションのうち、動いていない最も新しいもの（ID の順）を選ぶ。
- プロジェクトのディレクトリは、記録の最後のものを使う。`--resume` に `--project` を添えて、それと違うディレクトリを示したときは、使い方の誤りとする。
- 提供者の設定の名前とモデルは、起動のときに明示しなければ、記録の最後のもの（再開の `session_start` があればそのもの）を既定とする。その名前の提供者が今の設定になければ、誤りとして示す。推論の深さ、サンドボックスと承認の方針、書ける場所、上限は、今の起動の指定と設定による。
- 番の番号と道具の呼び出しの ID は、記録の続きから数える。理由: `spill/` のファイルの名前は呼び出しの ID から作るので、重なると前の出力を上書きしうる（`spill/` は排他に作るので、重なれば書けない）。
- このセッションで許したコマンド（[利用者の確認](../03-safety/03-03-approval.md)の「通常モードの承認の方針」）と、読んだファイルの版（[道具](01-03-tools.md)の「読んでから直す規則」）は戻さない。理由: 版は記録に残しておらず、時間を置いた後に、前に読んだ内容を前提に書き換えさせないためである。LLM は直す前に読み直す。
- 非対話の `exec` でも `--resume` と `--continue` を使え、一つの依頼を処理して終わる。
- 環境の情報は記録の会話のものを使い、今の値と違う項目（日付など）を、[文脈の管理](01-04-context.md)の「環境の情報」の変化の形で次の依頼の前に加える。プロジェクトの指示のファイルは起動のときに読み直し、記録の会話のものと違えば、同じく変化として加える。理由: 会話の先頭を書き換えずに（同章の「文脈の構成」）、今の状態を LLM に伝える。
- 再開では、記録から会話（最後の圧縮があればその後）を組み立て直す。確認したエフェクトの記録は再開しない。理由: 前のセッションで利用者が確認した範囲を、時間を置いた後の別の作業に当てはめないためである。
- モードは、記録したモードを既定とする（設定の `default_mode` は使わない）。起動のときに別のモードを明示したときは、そのモードで再開する。制限モードのセッションを通常モードで再開するときは、利用者の確認を受ける（[セキュリティモデル](../03-safety/03-01-security-model.md)の「モードを変える操作」）。
- 記録の最後の行が途中で切れていれば（異常な終わり）、その行を捨てる。
- 実行を始めた記録があって結果の記録がない道具の呼び出しには、`Tool call was interrupted before its result was recorded. Its effects are unknown; check the files before retrying.` を結果として補う。実行を始めた記録もない呼び出しには、取り消しと同じ結果（[エージェントのループ](01-01-agent-loop.md)の「取り消し」）を補う。どちらも、再開で自動的に実行し直さない。理由: 外部への操作は、二度実行して同じ結果になるとは限らない。
- 提供者の設定の名前、ベースの URL、モデル、システムプロンプトと道具の定義のハッシュのどれかが記録と違うときは、推論の内容を送らない（[文脈の管理](01-04-context.md)の「推論の内容の扱い」）。

Pi はセッションを木の形で記録し、途中から枝分かれできる。試作では枝分かれを設けず、巻き戻しは記録を一本のまま進める（後述）。木の形にするかは BH-016 で扱う。

### 巻き戻し

【方針】ADR 0348 の決定 1・2 を引き継ぎ、巻き戻しは、プロジェクトのディレクトリの状態を記録して戻す形とする。

- **記録する時点**: 【決定】依頼を受けたとき（一連の処理の前）、制限モードの `benitoite_run`・`benitoite_test`・`benitoite_scratch` の実行の前、通常モードの `bash` の実行の前、書く道具（`write`・`edit`）が書く前、戻す操作の前とする（2026-10-17 に設計者が決めた。BH-017 を閉じた）。道具の前の時点は、確認を受けた後、実行の直前に記録する。Benitoite の事前検討の見立て（Benitoite の docs/todo の TODO-140）に、通常モードの `bash` と書く道具を加えた。理由: 一つの依頼の中の書き換えを、一つずつ戻せる。前の時点から変わっていないファイルは読み直さないので、時点を増やしても、記録の量は変化の分だけ増える。プロジェクトを辿る時間は、評価で測る。
- **記録の作り方**: プロジェクトのディレクトリの下のファイルを、シンボリックリンクを辿らずに辿り、各通常のファイルの中身の SHA-256 の値をキーとして、中身をセッションのディレクトリの `objects/` に一度だけ保存する。時点ごとに、パスと種類と、通常のファイルではキーと実行の権限を、シンボリックリンクではリンクの先の文字列を保存する。前の時点から、大きさ、更新の時刻、変更の時刻（ctime）、inode が変わっていないファイルは、中身を読み直さずに前のキーを使う。ただし、更新の時刻が前の時点の記録の時刻と同じ秒のファイルは読み直す。理由: 記録と同じ秒の中に変えられたファイルは、時刻を比べても変化を見分けられない（git も同じ問題を同じ形で避けている。[racy-git](https://git-scm.com/docs/racy-git)）。
- **除く範囲**: `.gitignore` の規則に当たるファイル、守る場所（`.git` と `.benitoiteh`。どの深さでも、ASCII の大文字と小文字を区別せずに、ファイルでもディレクトリでも）、読まないファイルの規則（[道具](01-03-tools.md)の「読まないファイル」）に当たるファイル、1 ファイル 8 MiB を超えるファイル。一つの時点の合計が 256 MiB を超えたら、それ以上を記録しない。除いたパスと除いた理由、合計の上限で記録しなかったことも、時点の一覧に記録する。
- **ハードリンクの表示**: 辿るときに、ハードリンクの数が 2 以上の通常のファイルを見つけたら、その一覧を画面に示す（[セキュリティモデル](../03-safety/03-01-security-model.md)の「保証しないこと」）。
- **戻す操作**: 利用者が `/rewind` で時点を選び、「ファイルと会話」「ファイルだけ」「会話だけ」から選ぶ。ファイルを戻すときは、選んだ時点の一覧に合わせて、変わったファイルを書き戻し、増えたファイルを消す。戻す前の状態も新しい時点として記録し、戻したことも戻せるようにする（ADR 0348 の決定 5 と同じ考え方）。
- **消してよいファイル**: 「増えたファイル」として消すのは、選んだ時点でそのパスが辿った範囲にあり、ファイルがなかったと記録で確かめられるものだけとする。選んだ時点で除いたパス、今の規則で除くパス、合計の上限で記録しなかった時点のパスは消さず、戻せなかったものとして一覧に示す。理由: 記録に中身がないことは、ファイルがなかったことを意味しない。8 MiB を超えていたファイルが後に小さくなったときなどに、元からあったファイルを消してしまう。
- **書き戻しの仕方**: 戻すときは、一覧と `objects/` の中身を信頼しない（サンドボックスを掛けずに動くコマンドは、セッションのディレクトリを書き換えうる）。一覧のパスは、絶対のパス、`..`、空の要素、守る場所の名前を含むものを拒み、中身は SHA-256 の値を確かめてから書く。書き戻すときは、すでにあるファイルの今の権限（下位の 9 ビット）を保ち、実行の権限のビットだけを時点に合わせる。新しく作るファイルは 0644 か 0755 とする（setuid などは付けない）。種類、中身、実行の権限、リンクの先が戻す前の状態と同じ項目は、操作しない。理由: 変えていないファイルを書き直すと、時刻と inode が変わり、権限が広がりうる（0600 のファイルが 0644 になる）。今ハードリンクの数が 2 以上のファイルは、書き戻さずに戻せなかったものとして示す。消す操作を深い方から先に行い、作る操作と書き戻しを浅い方から後に行う（大文字と小文字を区別しないファイルシステムで、書き戻したファイルを消さないため）。書き戻しと削除は、書く道具と同じパスの規則（[道具](01-03-tools.md)の「書く道具のパスの規則」と「道具の定義の共通の規則」）で行い、シンボリックリンクを辿らない。シンボリックリンクは、リンクとして作り直す。理由: プロジェクトの中のシンボリックリンクが外を指しているとき、リンクを辿って書き戻すと、プロジェクトの外を書き換える。
- **戻せないものの表示**: 戻す区間に含まれる実行（スクリプト、コマンド、ウェブの取得）を一覧にして、プロジェクトの外への書き込みと外部への操作は戻らないことを示す（ADR 0348 の決定 2）。
- **会話を戻すとき**: 選んだ時点より後の会話を、次の要求に含めない。記録のファイルには、戻したことを一行加える（書いた行は消さない）。会話を戻せるのは、依頼を受けた時点（その依頼を会話に加える前）だけとし、道具の前の時点と戻す操作の前の時点は「ファイルだけ」を戻す選択肢としてだけ示す。理由: 道具の前の時点は、道具の呼び出しに結果のない応答の途中にあり、そこで切ると提供者が受け付けない会話になる。圧縮をまたいで会話を戻すことはできない。時点の後に圧縮か、その時点より前まで会話を戻したことがあれば、その時点は「ファイルだけ」の選択肢としてだけ示す。理由: 圧縮の前の会話は、要約に置き換えて送らなくなっており、戻すと会話の先頭が変わってキャッシュと推論の内容の送り返しが崩れる。
- **時点の一覧の置き場所**: 時点ごとの一覧は、中身と同じく SHA-256 の値を名前として `objects/` に置き（同じ一覧は重ねて保存しない。大きさは記録の上限に数える）、記録のファイルには時点を記録したことを一行書く。理由: 一覧は大きくなりうるので、記録の行に入れない。道具の前ごとに時点を記録するので、一覧の量も上限に数える。
- **辿り方**: シンボリックリンクを途中の要素でも最後の要素でも辿らず、プロジェクトのディレクトリを開いた記述子から一要素ずつ開いて辿る。`.gitignore` も同じ口で、待たない形で開き、通常のファイルで 1 MiB 以下のものだけを読む。一つの時点で辿る項目は 20 万まで、時間は 10 秒までとし、超えたら打ち切って、その時点を不完全とする。理由: サンドボックスの中のコマンドが、`.gitignore` を `/dev/zero` へのリンクや名前付きのパイプにして、時点の記録（依頼と道具の前ごと）で主のプロセスを止めることを防ぐ。
- **大きなプロジェクト**: 時点の記録は、前の時点から変わっていないファイルを読み直さないが、辿る時間はファイルの数に比例する。2026-10-17 の試作の P4-03 の測定（macOS、変化なしの 2 回目）では、1,000 ファイルで約 25 ミリ秒、1 万で約 250 ミリ秒、10 万で約 2.5 秒だった。1 万を超えるプロジェクトで軽くする方法は BH-098 で扱う。
- **不完全な時点**: 辿ることを打ち切った時点、読めなかったディレクトリのある時点、一覧を保存できなかった時点は、不完全と記録する。不完全な時点に戻すときは、ファイルを消さない。戻す前の状態の時点が不完全なときは、利用者が明示しない限り戻さない（戻した後に、今の状態を取り戻せなくなるため）。大きさの上限で除いたファイルと、上限で中身を保存しなかったファイルは、時点を不完全にせず、そのパスだけを除いた項目か中身のない項目として一覧に載せる（載っているので消す対象にならず、中身のない項目は戻せなかったものとして示す）。理由: 大きなファイルが一つあるだけで、すべての時点が不完全になり、何も消せなくなることを避ける。
- **戻した後の読んだ版**: ファイルを戻したパスの、読んだファイルの版の記録を消す。LLM は直す前に読み直す（[道具](01-03-tools.md)の「読んでから直す規則」）。

git のリポジトリを使わない形にしたのは、プロジェクトが git のリポジトリとは限らず、git のライブラリを依存に加えると実行ファイルが大きくなるからである。ADR 0348 は git の操作に git のライブラリを使うと定めたが、巻き戻しの記録の形は定めていない（Benitoite の docs/todo の TODO-140 の残る点）。記録は、セッションの記録と同じ期間だけ残し、大きさはセッションの記録の上限に含める（後述の「記録を残す期間」）。

### 一時ディレクトリ

【方針】セッションごとに一時ディレクトリを作り、一時的なスクリプト（`benitoite_scratch`）と、子プロセスの一時ファイル（`TMPDIR`）を置く。セッションが終わったら消す（ADR 0344 の決定 3）。`benitoiteh` が異常に終わって残った一時ディレクトリは、次の起動のときに、作ったセッションが動いていないことを確かめてから消す。動いているかは、各セッションがセッションのディレクトリの中のロックのファイルに掛けて持ち続けるファイルのロックが取れるかで判定する。ロックのファイルを一時ディレクトリに置かないのは、子プロセスが一時ディレクトリに書けるので、ロックのファイルを消すか差し替えて、動いているセッションの一時ディレクトリを消させうるからである。消すときは、シンボリックリンクを辿らない削除（Rust の標準の [`remove_dir_all`](https://doc.rust-lang.org/std/fs/fn.remove_dir_all.html)。シンボリックリンクはリンクそのものを消す）を使い、`benitoiteh-<ID>` の形の名前のディレクトリだけを対象にする。理由: プロセスの番号は使い回されるので、番号だけでは動いているかを確かめられない。子プロセスが一時ディレクトリにホームディレクトリへのシンボリックリンクを作っていても、辿らずに消せば、リンクの先を消さない。

切り詰めた出力（[道具](01-03-tools.md)の「出力の切り詰め」の `spill/`）は、一時ディレクトリではなくセッションのディレクトリに置き、セッションの記録と同じ期間だけ残す。理由: 再開したセッションで、LLM が前に示されたパスを読めるようにする。

### 記録を残す期間

【方針】セッションのディレクトリは、既定では 30 日残し、起動のときに古いものを消す。期間は、記録のファイルの最後の更新の時刻から数える（再開して使い続けている記録を消さないため）。設定ファイルで変えられる。期間とは別に、一つのセッションの `spill/` と `objects/` の合計と、すべてのセッションの合計に上限を設ける（【決定】一つのセッションは 1 GiB、すべてのセッションの合計は 10 GiB とする。2026-10-17 に設計者が決めた。BH-063 を閉じた。上限に達したときの扱いは[道具](01-03-tools.md)の「出力の切り詰め」）。上限は次のように掛ける。起動のときに、すべてのセッションのディレクトリの大きさの合計を数え、このセッションの `spill/` と `objects/` に書ける量を、1 GiB と「10 GiB − ほかのセッションの合計」の小さい方とする。書ける量を超える `spill/` と `objects/` への書き込みは行わず、そのことを道具の結果（[道具](01-03-tools.md)の「出力の切り詰め」）と画面に示す。記録のファイル（`session.jsonl`）は、再開に要るので、この上限で止めない。合計が 10 GiB を超えているときは、起動のときにそのことと、古いセッションを消す方法（期間を短くする）を示す。古いセッションを消すのは、期間を過ぎたものだけとする。期間を過ぎたセッションでも、動いているもの（ロックの錠が取れないもの）は消さない。記録には読んだファイルの中身とコマンドの出力が含まれうるので、ディレクトリの権限は利用者だけが読める形（0700、ファイルは 0600）にする。入力の履歴（Benitoite の docs/todo の TODO-139）は、プロジェクトごとに残す（[対話の画面](../05-interface/05-02-tui.md)の「入力の操作」。BH-018 を閉じた）。
