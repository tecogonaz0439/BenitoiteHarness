# CLI と設定ファイル

- 状態: 草稿
- 未決事項: BH-050, BH-051, BH-012

## 目的と範囲

本章は、`benitoiteh` のコマンドライン（サブコマンド、オプション、終了状態）、非対話の実行（`exec`）の出力、利用者の設定ファイルとプロジェクトの設定ファイル、データの置き場所を定める。対話の画面は[対話の画面](05-02-tui.md)で定める。

## 前提

- Benitoite の事前検討は、エージェントハーネスを `benitoite agent` のサブコマンドとし、設定を TOML の利用者単位の設定ファイルに書き、決まった場所に置いて探さないと定めた（[ADR 0343](https://github.com/tecogonaz0439/Benitoite/blob/v0.0.7/docs/archive/2026-10-09-design-first-release/decisions/0343-agent-harness-user-config-file.md)）。プロジェクトごとの設定ファイルは、書ける欄を限る方向とした（Benitoite の docs/todo の TODO-133）。
- 試作は処理系とは別の実行ファイル `benitoiteh` とする（利用者の要件）。
- Codex CLI の `exec` は、進み具合を標準エラー出力に、最後の応答だけを標準出力に書き、`--json` で JSON Lines のイベントを出す（[先行事例](../08-appendix/08-01-prior-art.md)）。

## 仕様

### コマンドラインの形

【方針】

```text
benitoiteh [オプション] [依頼]            # 対話の画面を開く。依頼を書けば最初の依頼として送る
benitoiteh exec [オプション] <依頼>       # 非対話で一つの依頼を処理して終わる
benitoiteh doctor                         # 処理系・サンドボックス・提供者の設定を確かめて示す
benitoiteh sessions                       # 記録したセッションの一覧を示す
benitoiteh --help | --version | --licenses
```

- `exec` の `<依頼>` に `-` を書いたときは、標準入力から依頼を読む。
- `benitoiteh __sandbox ...` は、OS のサンドボックスを掛ける補助のプロセスのための内部の形であり、利用者に示さない（[OS のサンドボックス](../03-safety/03-02-sandbox.md)の「サンドボックスの掛け方」）。
- 引数の解釈は、依存のクレートを使わずに自前で行う。理由: 引数の解釈のクレート（`clap` など）は実行ファイルを大きくし、試作のオプションの数は自前で扱える範囲である。Benitoite の処理系も自前で解釈している。

### オプション

| オプション | 意味 | 既定 |
|---|---|---|
| `--mode restricted\|normal` | モード | 設定の `default_mode`、なければ `restricted` |
| `--project <dir>` | プロジェクトのディレクトリ | 作業ディレクトリ |
| `--provider <名前>` | 設定に書いた提供者の名前 | 設定の `default_provider` |
| `--model <名前>` | モデル | 提供者の設定の `model` |
| `--effort <値>` | 推論の深さ（提供者が持つときだけ） | 提供者の設定の `effort` |
| `--resume <ID>`・`--continue` | セッションの再開 | — |
| `--sandbox read-only\|workspace-write\|danger-full-access` | 通常モードのサンドボックスの方針 | 設定の値、なければ `workspace-write` |
| `--approval untrusted\|on-request\|never` | 通常モードの承認の方針。非対話では `never` だけを受け付け、ほかは使い方の誤りとする（確認に答える者がいないため） | 対話は `on-request`、非対話は `never` |
| `--allow <エフェクト,...>` | 非対話の制限モードで許すエフェクト（処理系の `--allow-effects` と同じ原子の名前） | なし（確認なしの範囲だけ） |
| `--project-parent <dir>` | 非対話で `create_project` が作ってよい場所 | なし（作れない） |
| `--max-turns <n>` | 一連の処理の番の数の上限 | 設定の `limits.max_turns`、なければ 200 |
| `--max-check-fix <n>` | 検査と修正の回数の上限（制限モード。1 以上。0 は誤り） | 設定の `limits.max_check_fix`、なければ 10 |
| `--max-run-tokens <n>` | 一連の処理のトークンの量の上限（モデルの出力の上限とは別のもの） | 設定の `limits.max_run_tokens`、なければなし |
| `--json` | `exec` でイベントを JSON Lines で出す | 出さない |
| `--output-last-message <file>` | `exec` で最後の応答をファイルにも書く | 書かない |
| `--no-sandbox` | OS のサンドボックスを掛けられない環境で、通常モードをサンドボックスなしで動かす | 動かさない |

オプションの正確な名前と、プロジェクトの設定から変えられるかどうかは、試作の中で見直す（BH-050）。

### 終了状態

【方針】`exec` の終了状態は、Benitoite の処理系の値の意味に揃える。

| 値 | 意味 |
|---|---|
| 0 | 一連の処理が終わった（LLM が道具を呼ばずに応答を終えた） |
| 1 | 一連の処理が失敗した（上限に達した、提供者の誤りでやり直せなかった、非対話で許していない実行が続いた、提供者が拒否した） |
| 2 | 使い方の誤り、設定ファイルの誤り、処理系が見つからない、制限モードでサンドボックスを掛けられない |
| 3 | `benitoiteh` の不具合 |
| 130 | 中断の要求（`SIGINT`・`SIGTERM`）を受けて終えた |

「一連の処理が終わった」は、依頼を果たしたことを意味しない。依頼を果たしたかは、評価の道具が課題ごとに判定する（[評価](../07-quality/07-02-evaluation.md)）。対話の画面の終了状態は、利用者が終えたら 0、使い方と設定の誤りは 2 とする。

### exec の出力

【方針】

- `--json` がないときは、最後の応答の文を標準出力に書き、道具の呼び出しの一行の要約と確認の結果を標準エラー出力に書く。標準エラー出力に書く要約は、端末の制御の文字を目に見える形に変える（[対話の画面](05-02-tui.md)の「出力の示し方」と同じ規則）。
- `--json` があるときは、[エージェントのループ](../01-agent/01-01-agent-loop.md)の「イベント」を一行一件の JSON で標準出力に書く。最後の行は、セッションの集計（[セッション](../01-agent/01-05-sessions.md)の「LLM を使ったテストのための記録」）とする。
- 非対話では確認ができないので、[利用者の確認](../03-safety/03-03-approval.md)の「非対話での扱い」に従う。

JSON の欄を利用者に約束する形にするか（版を付けて互換を保つか）は BH-012 で決める。

### 設定ファイル

【方針】利用者の設定ファイルは `$XDG_CONFIG_HOME/benitoiteh/config.toml`（`XDG_CONFIG_HOME` がなければ `~/.config/benitoiteh/config.toml`）とし、macOS でも同じ場所を使う。作業ディレクトリや親のディレクトリを辿って探さない（ADR 0343 の決定 4 を引き継ぐ）。理由: Benitoite の事前検討も `~/.config/benitoite/` の下を例に挙げており、端末で使う道具として、OS に依らない一つの場所の方が説明が簡単である。

形の例を次に示す。

```toml
default_mode = "restricted"
default_provider = "anthropic"

[providers.anthropic]
kind = "anthropic-messages"
model = "claude-opus-5-5"
effort = "high"
api_key = { env = "ANTHROPIC_API_KEY" }

[providers.deepseek]
kind = "anthropic-messages"
base_url = "https://api.deepseek.com/anthropic"
model = "<モデルの名前>"
api_key = { env = "DEEPSEEK_API_KEY" }
capabilities = { cache_control = false, strict_tools = false, eager_input_streaming = false, reasoning_replay = "same-destination" }

[providers.local]
kind = "openai-chat"
base_url = "http://localhost:11434/v1"
model = "<モデルの名前>"
context_window = 131072

[benitoite]
path = "/Users/me/src/Benitoite/target/release/benitoite"

[restricted]
allowed_programs = []
scratch_auto_effects = []

[normal]
sandbox = "workspace-write"
approval = "on-request"
network = false
writable_roots = []

[limits]
max_turns = 200
max_check_fix = 10

[web_fetch]
allowed_domains = ["docs.rs"]

[read]
exclude = []

[sessions]
retention_days = 30
```

- 知らない欄があれば、誤りとして起動を止め、欄の名前を示す。理由: 綴りの誤りで、利用者が掛けたつもりの制限が効いていない状態を避ける。
- `providers.<名前>.kind` は、[提供者の層](../02-providers/02-01-provider-layer.md)のアダプタの名前である。`capabilities` は同章の「提供者ごとの機能の表」の欄である。

### プロジェクトの設定ファイル

【方針】プロジェクトの設定ファイルは、プロジェクトのディレクトリの直下の `.benitoiteh/config.toml` だけとし、親を辿らない。書ける欄は次に限る。

| 欄 | 意味 |
|---|---|
| `model` | 使う提供者のモデルを変える |
| `read.exclude` | 読まないファイルを足す（減らせない） |

- 【決定】提供者は選べない。提供者は、起動のときのオプションか利用者の設定で決める。理由: 利用者が、手元の推論サーバを普段使い、クラウドの提供者を別の用途のために設定に書いていることがある。信頼しないリポジトリの設定が提供者を選べると、利用者が送るつもりのない提供者へ、そのプロジェクトの内容が送られる。モデルを変えても、送り先の提供者は変わらない。
- ほかの欄（提供者、ベースの URL、キーの参照、モード、サンドボックスと承認の方針、許すプログラム、確認なしの範囲、許すドメイン）は書けない。書いてあれば、無視せずに誤りとして示し、プロジェクトの設定ファイル全体を使わずに続ける。理由: 他人のリポジトリの設定で、ベースの URL を攻撃者のサーバに向けてキーや文脈を送らせる攻撃と、制限を緩める攻撃を防ぐ。Benitoite の事前検討の対策 (a)（Benitoite の docs/todo の TODO-133）を引き継ぐ。Codex CLI も、プロジェクトの設定で提供者の URL を設定させない（[先行事例](../08-appendix/08-01-prior-art.md)）。
- プロジェクトの設定ファイルを読んだことと、選んだ提供者とモデルを画面に示す。

書ける欄を増やすかは BH-051 で扱う。

### データの置き場所

【方針】

| データ | 置き場所 |
|---|---|
| セッションのディレクトリ | `$XDG_STATE_HOME/benitoiteh/sessions/<ID>/`（`XDG_STATE_HOME` がなければ `~/.local/state/benitoiteh/sessions/<ID>/`） |
| セッションの一時ディレクトリ | `$TMPDIR/benitoiteh-<ID>/` |
| Linux の塞ぐ場所の錠と記録 | `$XDG_STATE_HOME/benitoiteh/placeholders/`（[OS のサンドボックス](../03-safety/03-02-sandbox.md)の「Linux のファイルシステムの見え方」） |
| 入力の履歴 | `$XDG_STATE_HOME/benitoiteh/history/<プロジェクトの実のパスの SHA-256>`（[対話の画面](05-02-tui.md)の「入力の操作」） |
| 利用者の指示のファイル | `$XDG_CONFIG_HOME/benitoiteh/AGENTS.md` |

セッションの ID は、開始の時刻（UTC）と乱数から作り、時刻の順に並ぶ形とする。ディレクトリとファイルの権限は[セッション](../01-agent/01-05-sessions.md)の「記録を残す期間」で定める。

### sessions

【方針】`benitoiteh sessions` は、記録したセッションを新しい順に一行ずつ示す。各行は、セッションの ID、開始の時刻（UTC）、モード、記録の最後のプロジェクトのディレクトリ、最初の依頼の先頭の 60 文字（制御の文字は[対話の画面](05-02-tui.md)の「出力の示し方」と同じく目に見える形に変える）、動いているかの印を持つ。`--project <dir>` を添えると、そのディレクトリのセッションだけを示す。`--json` を添えると、一行一件の JSON で示す。記録が読めないセッションは、ID と読めない理由だけを示して続ける。

### doctor

【決定】`benitoiteh doctor` は、次のことを確かめて結果を示し、どれかが失敗したら終了状態 1 で終わる。LLM の提供者には要求を送らない（2026-10-18 に設計者が承認した）。

- 処理系が見つかり、`--version=json` が読め、要る出力の形式を持つこと（[Benitoite の処理系との連携](../04-benitoite/04-01-benitoite-integration.md)の「処理系の見つけ方と版の確かめ」）。版とビルドの情報（`null` は不明として示す）と実行ファイルの SHA-256 を示し、版がシステムプロンプトの対応の説明を確かめた版と一致するかを示す。`skill show` で `SKILL.md` を得られること。処理系に問い合わせるのは、制限モードの規則の確かめが通ったときだけとし、サンドボックスの中で行う（[Benitoite の処理系との連携](../04-benitoite/04-01-benitoite-integration.md)の「処理系の起動」）。通らないときは、版と `SKILL.md` の項目を「確かめていない」とする。処理系が見つからないときは「使えない」とする（通常モードだけを使う利用者でも、終了状態は 1 になる）。
- OS のサンドボックスを掛けられること。制限モードの規則（処理系だけを起動できる）が働くことを、処理系の `--version` を許し、`/bin/sh` を拒む小さな確かめで示す。Linux では処理系が静的にリンクされていること。
- OS のサンドボックスの機能を、項目ごとに示す。Linux では、bubblewrap のパスと版、特権を持たない利用者の名前空間を作れるか、Landlock の ABI の版、seccomp を使えるか。Linux では、守る場所の範囲が macOS より狭いこと（[セキュリティモデル](../03-safety/03-01-security-model.md)の「Linux での保証の範囲」）も示す。項目ごとに「確かめた」「使えない」「確かめていない」を分けて示し、制限モードを起動できるかを示す。`/bin/sh` を一つ拒めたことだけで、制限モードを起動できると示さない。
- 設定ファイルを読めること。各提供者のキーの参照が値を得られること（値は示さない）。
- 各提供者の `context_window` の設定の有無。設定がなければ、番の前の圧縮が働かないことを注意として示す（[文脈の管理](../01-agent/01-04-context.md)の「圧縮」）。
- データの置き場所の権限と、すべてのセッションの記録の合計の大きさ（[セッション](../01-agent/01-05-sessions.md)の「記録を残す期間」）。

【方針】項目ごとの状態は「確かめた」「使えない」「確かめていない」「注意」の四つとし、「使えない」が一つでもあれば終了状態 1 で終わる。`--json` を添えると、項目ごとに一行一件の JSON で示す。`--project <dir>` を添えると、そのディレクトリのプロジェクトの設定と通常モードの方針を確かめる。制限モードの規則の確かめは、処理系の `--version=json` を許し、問い合わせと同じ方針で行う。処理系が見つからないか、実行ファイルの形の確かめを通らないときだけ、`benitoiteh` 自身の `--version` を許す方針で確かめ、処理系の確かめでないことを示す。
