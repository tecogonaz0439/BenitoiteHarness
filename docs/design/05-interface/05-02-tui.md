# 対話の画面

- 状態: 草稿
- 未決事項: BH-052

## 目的と範囲

本章は、`benitoiteh` の対話の画面（端末の中の画面）の構成、入力の操作、確認の画面、`/` で始まるコマンドを定める。

## 前提

- Benitoite の事前検討は、エージェントハーネスの画面が、依頼、進み具合、差分、実行の前の確認、結果を示すとし、TUI の部品に既存の OSS を使うと定めた（Benitoite の docs/todo の TODO-125、ADR 0194 の決定 4）。サーバモードの承認の画面と見た目を揃える定め（ADR 0342 の決定 2）は、試作にサーバモードがないので当てはまらない。
- Pi は、端末の代替の画面（alternate screen）を使わず、出力を端末の履歴にそのまま流し、下の部分だけを差分で描き直す画面を持つ。差分の描き直しには、端末の同期した出力（CSI 2026）を使う（[先行事例](../08-appendix/08-01-prior-art.md)）。Codex CLI は `ratatui` で画面を作る。

## 仕様

### 画面の構成

【方針】代替の画面を使わず、出力を端末の履歴に流す形（インラインの形）とする。画面の下に、次の二つの部分を置き、この部分だけを描き直す。

- **入力欄**: 複数行を書ける。
- **状態の行**: モード、提供者とモデル、文脈の大きさの見積もりと上限の比、サンドボックスの方針、実行中なら経過の時間。

理由: 出力が端末の履歴に残るので、利用者は端末の検索と写しをそのまま使える。描き直す範囲が小さいので、ストリーミングの文を速く示せる。

【方針】画面の部品は `crossterm`（端末の制御と入力の読み取り）だけを使い、描画は自前で行う。`ratatui` は使わない。理由: インラインの形では、描き直す範囲が入力欄と状態の行だけであり、画面の全体を枠組みで組む `ratatui` の機能の多くが要らない。依存を減らして実行ファイルを小さくする。Benitoite の事前検討は TUI の部品に既存の OSS を使うと定めており、`crossterm` を使うことはこれに沿う。描画の部品を自前で持つ量が増えすぎるときは、`ratatui` に切り替えるかを見直す（BH-052）。

### 出力の示し方

【方針】

- LLM の応答の文は、届いた順に示す。Markdown は、見出し、箇条書き、強調、コードのブロックだけを端末の装飾に変え、ほかはそのまま示す。構文の色付けは試作では行わない。
- 道具の呼び出しは、一行の要約（`read src/main.bnt (1-120)`、`bash: cargo test` など）と、結果の一行の要約（行数、終了状態、誤りの有無）で示す。
- `write`・`edit` は差分（unified diff の形、色付き）を示す。
- 推論の文は、要約だけを薄い色で示す（[文脈の管理](../01-agent/01-04-context.md)の「推論の内容の扱い」。BH-015 を閉じた）。
- 確認の画面と、取り消しで止めたことは、目立つ色で示す。
- 信頼しない文字列（LLM の文、道具の結果、ファイルの名前と中身、子プロセスの出力、診断、ウェブのページ）は、端末に書く前に、制御の文字を目に見える形に変える。対象は、ESC、改行とタブを除く C0 の制御の文字、DEL、C1 の制御の文字、文字の向きを変える文字（U+202A〜U+202E、U+2066〜U+2069、U+200E、U+200F、U+061C）であり、`\x1b`・`\u{202e}` のような形で示す。確認の画面と、行の折り返しを止めて描く部分（入力欄の下の部分）では、さらに、目に見えない文字と幅の定まらない文字（Unicode の Default_Ignorable_Code_Point、書式の文字（一般カテゴリ Cf）、異体字セレクタ、ハングルの埋め字 U+115F・U+1160・U+3164・U+FFA0）も同じ形で示す。文字の幅は、端末より小さく見積もらない側に数える（曖昧な幅の文字と未割り当ての文字は 2 列、絵文字と異体字セレクタの組は 2 列）。理由: 行の折り返しを止めた端末では、`benitoiteh` が幅を小さく見積もった行の右側が、右端の列に重ね書きされて消える。空白に見える文字で幅をずらし、確認の画面のコマンドの後半を見えなくできる（2026-10-18 の試作の P4-07 の点検で、U+3164 で確かめた）。形の似た別の文字（ホモグリフ）による偽装は、この変換では防がない。Markdown を端末の装飾に変えるときは、変えた後の文字列に、`benitoiteh` が作った装飾の制御の列だけを加える。理由: 信頼しない文字列の中の制御の列（カーソルの移動、画面の消去、端末の題名の設定など）で、画面を書き換え、本物の確認の画面や入力欄に見える表示を作らせないためである（[xterm の制御の列](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)）。

### 入力の操作

【方針】

| 操作 | 働き |
|---|---|
| Enter | 依頼を送る。一連の処理の途中なら、操縦として送る（[エージェントのループ](../01-agent/01-01-agent-loop.md)の「利用者の割り込み」） |
| Alt+Enter | 一連の処理の途中なら、後続として送る |
| Shift+Enter、Ctrl+J | 入力欄の中で改行する（Shift+Enter は、端末が区別して送るときだけ） |
| ESC | そのときの処理を取り消す。二度続けて押すと一連の処理を止める |
| Ctrl+C | 入力欄が空でなければ空にする。空なら、二度続けて押すと終える |
| ↑・↓ | 入力欄が一行のとき、そのセッションの前の入力を辿る |
| Ctrl+G | 【方針】入力欄を外部のエディタ（`VISUAL`、なければ `EDITOR` を空白で分けたコマンド）で書き、閉じたら書いた文で入力欄を置き換える。下書きは、サンドボックスから読めない入力の履歴のディレクトリに利用者だけが読める権限で置き、終えたら消す。エディタが失敗したときと 1 MiB を超えたときは、元の入力を保つ。一連の処理の途中では使えない。理由: 一時ディレクトリに置くと、サンドボックスの中のコマンドが下書きを読み書きでき、利用者の依頼に文を足せる |
| 画像のパスの貼り付け | 【方針】一連の処理の途中でないときに、画像の拡張子（`png`・`jpg`・`jpeg`・`gif`・`webp`）を持つ一つの実在するファイルの絶対パスを貼ったら、文として入れず、次の依頼の添付にする（2026-11-02 に設計者が決めた。クリップボードの画像は扱わない）。端末が付ける引用符、`file://`、空白の前の `\` を外す。添付の名前を状態の行に示し、Ctrl+C で入力欄とともに外す。送るときに `read` の道具と同じ処理（範囲、読まないファイル、縮小の補助、`objects/` への保存）で読み、一つでも読めなければ依頼を送らずに理由を示す（[提供者の層](../02-providers/02-01-provider-layer.md)の「画像の受け渡し」）。理由: 利用者の添付でも、読ませない場所の画像を送る道筋を作らない。添えたつもりの画像を黙って欠いて送らない |
| Tab | 【方針】カーソルの直前の語が `@` で始まるとき、プロジェクトのファイルのパスに替える。続けて押すと次の候補に替える。候補は、プロジェクトの下のファイルのうち、`@` の後の文字を順に含むもの（大文字と小文字を区別しない）を、名前の部分に含むもの、間の飛びが少ないもの、短いものの順に並べる。リンクを辿らず、`.` で始まる名前と根の `.gitignore` が除くものを飛ばし、集めるのは 20,000 件か 2 秒までとする。パスの文字を入れるだけで、ファイルの中身は読まない。理由: 中身は LLM が道具で読むので、読まないファイルなどの規則がそのまま効く |

【決定】入力の履歴は、セッションをまたいでプロジェクトごとに残す（2026-10-17 に設計者が決めた。BH-018 を閉じた）。データのディレクトリの `history/`（[CLI と設定ファイル](05-01-cli.md)の「データの置き場所」）の下に、プロジェクトのディレクトリの実のパスの SHA-256 の値を名前としたファイルを置き、利用者だけが読み書きできる権限（0600）で、新しい 500 件までを保存する。Benitoite の事前検討の見立て（残すなら利用者だけが読めるファイルに件数の上限を設けて保存する。利用者がパスワードを貼ることがあるため）を引き継ぐ。理由: 同じプロジェクトで続けて作業するときに、前の依頼を辿れる。プロジェクトごとに分ければ、別のプロジェクトの依頼が混ざらない。

### 確認の画面

【方針】確認の画面は、出力の流れの中に枠付きで示し、答えを一つのキーの入力で受ける。

```text
╭─ Run Benitoite script?
│ Targets:
│   /Users/me/proj/src/main.bnt
│ Effects:
│   + File.Write   creates, changes, moves, or deletes files and directories
│     File.Read    reads files and directories
│ Sandbox:
│   can write: /Users/me/proj and the session temporary directory
│   network: blocked
│ [y] run and allow these effects for this session  [n] decline  [m] decline with a message
╰─
```

- 示す中身は[利用者の確認](../03-safety/03-03-approval.md)で定める。
- 【決定】`[y]` は、その対象について、示したエフェクトの範囲をセッションの間許すことを兼ねる（中身が変わっても、範囲に収まれば次からは確認しない。[利用者の確認](../03-safety/03-03-approval.md)の「制限モードの確認」）。キーの文にそのことを書く（2026-10-18 に設計者が承認した）。理由: 利用者が、次から確認されないことを知った上で許せるようにする。
- 前に確認したエフェクトがあるときは、増えたエフェクトに `+` を付けて先に並べる。
- 【決定】確認の画面の事実のうちファイルのパス（対象など）は、改行とタブも `\x0a`・`\x09` の形で示し、一つのパスを一行にする（2026-10-18 に設計者が承認した）。理由: LLM は名前に改行を含むファイルを書けるので、改行を残すと、本物の事実の値の行と同じ形の行を作れる（2026-10-18 の試作の P2-10 の点検で確かめた）。
- 答えを待つ間は、ほかの入力を受けない。ESC は「拒否」として扱う。
- 確認の画面を示す前に届いていたキーの入力と、貼り付け（bracketed paste）の入力は、答えに使わずに捨てる（[利用者の確認](../03-safety/03-03-approval.md)の「確認の共通の規則」）。
- 【決定】試作では、確認の画面を含め、利用者に示す文言を英語だけとする。日本語などへの対応は、Benitoite の処理系を含めた多言語化の検討と合わせて行う（2026-10-17 に設計者が決めた。BH-053 を閉じた）。

### 秘密の入力の欄

【決定】サンドボックスの外で起動したコマンドが `SSH_ASKPASS` などで秘密を求めたときは、確認の画面と同じく、ほかの入力を止めて入力の欄を出す。示す内容、伏せ字、捨てるキーの入力、取り消しは、[秘密の入力](../03-safety/03-04-secrets.md)の「段 2」の「入力の欄」による。入力した値は画面の履歴に残さない。

### `/` で始まるコマンド

【方針】

| コマンド | 働き |
|---|---|
| `/help` | コマンドと操作の一覧を示す |
| `/status` | セッションの ID、モード、提供者とモデル、処理系のパスと版、サンドボックスの方針、使ったトークンの量、読んだプロジェクトの指示のファイルを示す |
| `/compact [指示]` | 圧縮する。指示を書けば要約の指示に加える |
| `/rewind` | 巻き戻しの時点を選んで戻す（[セッション](../01-agent/01-05-sessions.md)の「巻き戻し」）。会話を戻すと新しい枝を始める |
| `/tree` | セッションの木を示し、選んだ枝や依頼の直前に移る（[セッション](../01-agent/01-05-sessions.md)の「セッションの木」）。既定では利用者の依頼と枝の先端だけを、字下げした一覧で示す |
| `/fork` | 今の枝（または選んだ依頼の直前まで）を新しいセッションに写し、そちらに移る |
| `/new` | 今のセッションを終え、同じ設定で新しいセッションを始める。【決定】モード、プロジェクト、サンドボックス、承認の方針、ネットワーク、書ける場所、許すプログラム、処理系のパス、一時的なスクリプトの確認なしの範囲は、今のセッションの値を引き継ぎ、設定ファイルから読み直さない（2026-10-18 に設計者が承認した） |
| `/init` | 【方針】プロジェクトを調べて `AGENTS.md` を書くよう求める、決まった依頼を送る（2026-11-02 に設計者が決めた。Codex の `/init` に当たる）。書き込みは通常の `write` の道具と確認を通る。制限モードでは書く道具がないので使えず、プロジェクトのディレクトリに `AGENTS.md` があれば送らずに知らせる。依頼の文は `prompts/init.md` に置く |
| `/export [パス]` | 【方針】今の枝を Markdown に書き出す（[セッション](../01-agent/01-05-sessions.md)の「会話の書き出し」）。相対のパスはプロジェクトのディレクトリから数え、パスがなければプロジェクトのディレクトリに `benitoiteh-<セッションの ID>.md` を作る。既にあるファイルは上書きせず、誤りとして示す。ファイルは利用者だけが読める権限（0600）で作る |
| `/quit` | 終える |

モードを変えるコマンドは設けない（[セキュリティモデル](../03-safety/03-01-security-model.md)の「モードを変える操作」）。提供者やモデルを途中で変えるコマンドも設けない。理由: 道具の定義とシステムプロンプトと同じく、モデルを変えるとプロンプトのキャッシュが効かなくなり、推論の内容を送れなくなる（[文脈の管理](../01-agent/01-04-context.md)の「推論の内容の扱い」）。変えたいときは `/new` か再開で行う。

### 利用者の定義するコマンド

【方針】利用者は、プロンプトの雛形を `/名前` のコマンドとして使える（2026-11-02 に設計者が決めた。Pi の雛形（`earendil-works/pi` の `packages/coding-agent/src/core/prompt-templates.ts`）に当たる）。

- **置き場所**: 利用者の雛形は設定のディレクトリの `prompts/<名前>.md`、プロジェクトの雛形は探す範囲（指示のファイルと同じ範囲）の各ディレクトリの `.agents/prompts/<名前>.md` とする。プロジェクトの雛形は、プロジェクトを信頼したときだけ読む（[セキュリティモデル](../03-safety/03-01-security-model.md)の「プロジェクトの信頼」）。理由: 雛形の文は利用者の依頼として送るので、信頼しないリポジトリに、利用者の名で指示を足させない。
- **名前**: ファイルの名前から `.md` を除いたものとし、英小文字で始まり、英小文字・数字・`-` だけを含む 64 文字までとする。組み込みのコマンドの名前（`/model`・`/export` のように後で加える予定のものを含む）は使えない。同じ名前は、先に読んだもの（利用者、範囲の根に近いディレクトリの順）を使い、後のものは読まなかったことを示す。理由: プロジェクトの雛形で、利用者の決めた同じ名前のコマンドを置き換えさせない。
- **読み方**: リンクを辿らず（プロジェクトの `.agents` と `prompts` をリンクにした場合も含む）、ハードリンクが一つでない、64 KiB を超える、UTF-8 でない、読まないファイル（[道具](../01-agent/01-03-tools.md)の「読まないファイル」）に当たるファイルは読まない。読む数は 200 までとする。読まなかったものは、理由とともに起動のときに示す。理由: リンクや別名で、範囲の外のファイルや秘密を依頼として送らせない。
- **形**: 先頭の `---` で囲んだ部分の `description:` を説明として `/help` に示し、残りを本文とする。本文の `$ARGUMENTS` を引数の全体に、`$1`〜`$9` を空白で分けた各引数に、`$$` を `$` に替える。埋める場所がない雛形に引数を書いたときは、本文の後に段落を分けて加える。理由: 書いた引数を黙って捨てない。
- **送り方**: 引数を埋めた文を、利用者の依頼として送り、画面にもその文を示す。一連の処理の途中では、ほかのコマンドと同じく使えない。`exec` では読まない。理由: 送る文を利用者が見られるようにする。雛形は対話の画面の操作である。

### 通知

【方針】端末が前面にないときに、確認（承認と秘密の入力）を開いたことと、依頼の一連の処理を終えたことを知らせる（2026-11-02 に設計者が決めた。Codex の通知の設定に当たる。`openai/codex` の `codex-rs/config/src/types.rs`）。

- **前面の判定**: 起動のときに端末の前面の報告（focus reporting。`CSI ? 1004 h`）を有効にし、終えるときに戻す。前面を離れたと報告された後、前面に戻ったと報告されるまでの間だけ知らせる。報告のない端末では知らせない。前面に戻ったら、まだ送っていない知らせは捨てる。理由: 前面にあるかを推し量って、利用者が見ている画面に余計な知らせを出さない。
- **知らせ方**: 利用者の設定の `[notifications]`（[CLI と設定ファイル](05-01-cli.md)の「設定ファイル」）で選ぶ。`terminal` が真なら、描いた後に OSC 9 の列（`ESC ] 9 ; 文 BEL`）と BEL を一つ書く。`command` があれば、その引数の最後に知らせの文を加えて起動し、終わりを待たない。コマンドはサンドボックスの外で、標準入出力を閉じて起動し、失敗しても画面を止めない。設定は起動のときのものを、`/new` の後も使う。
- **知らせの文**: 決まった英文（確認を待っていること、依頼を終えたこと）だけとし、LLM の文、コマンド、ファイルの名前を含めない。理由: 端末の制御の列とコマンドの引数に、信頼しない文字列を入れない。
