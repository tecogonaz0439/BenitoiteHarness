# 対話の画面

- 状態: 草稿
- 未決事項: BH-018, BH-052, BH-053

## 目的と範囲

本章は、`benitoiteh` の対話の画面（端末の中の画面）の構成、入力の操作、確認の画面、`/` で始まるコマンドを定める。

## 前提

- Benitoite の事前検討は、エージェントハーネスの画面が、依頼、進み具合、差分、実行の前の確認、結果を示すとし、TUI の部品に既存の OSS を使うと定めた（Benitoite の docs/todo の TODO-125、ADR 0194 の決定 4）。サーバモードの承認の画面と見た目を揃える定め（ADR 0342 の決定 2）は、試作にサーバモードがないので当てはまらない。
- Pi は、端末の代替の画面（alternate screen）を使わず、出力を端末の履歴にそのまま流し、下の部分だけを差分で描き直す画面を持つ。差分の描き直しには、端末の同期した出力（CSI 2026）を使う（[先行事例](../08-appendix/08-01-prior-art.md)）。Codex CLI は `ratatui` で画面を作る。

## 仕様

### 画面の構成

【方針】代替の画面を使わず、出力を端末の履歴に流す形（インラインの形）とする。画面の下に、次の二つの部分を置き、この部分だけを描き直す。

- **入力欄**: 複数行を書ける。
- **状態の行**: モード、提供者とモデル、文脈の大きさの見積もりと上限の比、サンドボックスの方針、実行中なら経過の時間。

理由: 出力が端末の履歴に残るので、利用者は端末の検索と写しをそのまま使える。描き直す範囲が小さいので、ストリーミングの文を速く示せる。

【方針】画面の部品は `crossterm`（端末の制御と入力の読み取り）だけを使い、描画は自前で行う。`ratatui` は使わない。理由: インラインの形では、描き直す範囲が入力欄と状態の行だけであり、画面の全体を枠組みで組む `ratatui` の機能の多くが要らない。依存を減らして実行ファイルを小さくする。Benitoite の事前検討は TUI の部品に既存の OSS を使うと定めており、`crossterm` を使うことはこれに沿う。描画の部品を自前で持つ量が増えすぎるときは、`ratatui` に切り替えるかを見直す（BH-052）。

### 出力の示し方

【方針】

- LLM の応答の文は、届いた順に示す。Markdown は、見出し、箇条書き、強調、コードのブロックだけを端末の装飾に変え、ほかはそのまま示す。構文の色付けは試作では行わない。
- 道具の呼び出しは、一行の要約（`read src/main.bnt (1-120)`、`bash: cargo test` など）と、結果の一行の要約（行数、終了状態、誤りの有無）で示す。
- `write`・`edit` は差分（unified diff の形、色付き）を示す。
- 推論の文の示し方は BH-015 で決める。
- 確認の画面と、取り消しで止めたことは、目立つ色で示す。
- 信頼しない文字列（LLM の文、道具の結果、ファイルの名前と中身、子プロセスの出力、診断、ウェブのページ）は、端末に書く前に、制御の文字を目に見える形に変える。対象は、ESC、改行とタブを除く C0 の制御の文字、DEL、C1 の制御の文字、文字の向きを変える文字（U+202A〜U+202E、U+2066〜U+2069）であり、`\x1b`・`\u{202e}` のような形で示す。Markdown を端末の装飾に変えるときは、変えた後の文字列に、`benitoiteh` が作った装飾の制御の列だけを加える。理由: 信頼しない文字列の中の制御の列（カーソルの移動、画面の消去、端末の題名の設定など）で、画面を書き換え、本物の確認の画面や入力欄に見える表示を作らせないためである（[xterm の制御の列](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)）。

### 入力の操作

【方針】

| 操作 | 働き |
|---|---|
| Enter | 依頼を送る。一連の処理の途中なら、操縦として送る（[エージェントのループ](../01-agent/01-01-agent-loop.md)の「利用者の割り込み」） |
| Alt+Enter | 一連の処理の途中なら、後続として送る |
| Shift+Enter、Ctrl+J | 入力欄の中で改行する（Shift+Enter は、端末が区別して送るときだけ） |
| ESC | そのときの処理を取り消す。二度続けて押すと一連の処理を止める |
| Ctrl+C | 入力欄が空でなければ空にする。空なら、二度続けて押すと終える |
| ↑・↓ | 入力欄が一行のとき、そのセッションの前の入力を辿る |

入力の履歴をセッションをまたいで残すかは BH-018 で決める。Benitoite の事前検討は、残すなら利用者だけが読めるファイルに件数の上限を設けて保存するとしている（利用者がパスワードを貼ることがあるため）。

### 確認の画面

【方針】確認の画面は、出力の流れの中に枠付きで示し、答えを一つのキーの入力で受ける。

```text
╭─ Run src/main.bnt? ────────────────────────────────────────────╮
│ Effects (from the signature of main):                          │
│   File.Read    reads files and directories                     │
│   File.Write   creates, changes, moves, or deletes files       │
│ Sandbox: can write in /Users/me/proj and the session temp dir; │
│          no network; can start only benitoite                  │
│ [y] run  [n] decline  [m] decline with a message               │
╰────────────────────────────────────────────────────────────────╯
```

- 示す中身は[利用者の確認](../03-safety/03-03-approval.md)で定める。
- 答えを待つ間は、ほかの入力を受けない。ESC は「拒否」として扱う。
- 確認の画面を示す前に届いていたキーの入力と、貼り付け（bracketed paste）の入力は、答えに使わずに捨てる（[利用者の確認](../03-safety/03-03-approval.md)の「確認の共通の規則」）。
- エフェクトの説明の言葉を、利用者の言語（日本語など）で示すかは BH-053 で決める。

### `/` で始まるコマンド

【方針】

| コマンド | 働き |
|---|---|
| `/help` | コマンドと操作の一覧を示す |
| `/status` | セッションの ID、モード、提供者とモデル、処理系のパスと版、サンドボックスの方針、使ったトークンの量、読んだプロジェクトの指示のファイルを示す |
| `/compact [指示]` | 圧縮する。指示を書けば要約の指示に加える |
| `/rewind` | 巻き戻しの時点を選んで戻す（[セッション](../01-agent/01-05-sessions.md)の「巻き戻し」） |
| `/new` | 今のセッションを終え、同じ設定で新しいセッションを始める |
| `/quit` | 終える |

モードを変えるコマンドは設けない（[セキュリティモデル](../03-safety/03-01-security-model.md)の「モードを変える操作」）。提供者やモデルを途中で変えるコマンドも設けない。理由: 道具の定義とシステムプロンプトと同じく、モデルを変えるとプロンプトのキャッシュが効かなくなり、推論の内容を送れなくなる（[文脈の管理](../01-agent/01-04-context.md)の「推論の内容の扱い」）。変えたいときは `/new` か再開で行う。
