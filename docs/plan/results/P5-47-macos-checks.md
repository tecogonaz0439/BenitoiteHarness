## 通信の中継

`tests/sandbox_bash.rs` に `macos_proxied_bash_needs_the_token_and_cannot_bypass_the_relay` を加えた。本物の Seatbelt の中の `bash` で、次のことを確かめる。

- プロキシの変数に合言葉を含む URL が入り、`/usr/bin/curl` がそれに従って、許したドメインと尋ねて許したドメインに届く。
- 断ったドメインは 403 と記録になる。
- 合言葉のない要求は 407 になる。
- `::1` の同じ番号にも中継が待ち受ける。
- 中継を通さない手元のほかのポートへの接続は、Seatbelt が拒む。

レビューで、Seatbelt の `(remote ip "localhost:<番号>")` が `127.0.0.1` だけでなく `::1` の同じ番号も許すことが分かった。レビューの担当が `sandbox-exec` で確かめ、こちらでもテストで確かめた。中継は `127.0.0.1` だけで待ち受けていた。このため、ほかのプロセスが `::1` の同じ番号で待ち受けると、サンドボックスの中のコマンドが中継を通らずにそこへ届いた。番号はカーネルが選ぶので LLM は狙えないが、同じ番号で `::1` にも待ち受けるように直した。

あわせて、レビューの次の指摘を直した。

| 指摘 | 直し方 |
|---|---|
| 確認がコマンドの終わりに縛られない。終わったコマンドの古い確認に `[s]` と答えると、セッションの許可に入る | コマンドが終わったら、答えを待つ接続を断り、遅れた答えを捨てる |
| 同じコマンドの中で断ったドメインを、再試行のたびに尋ね直す | 断ったドメインを覚え、尋ね直さずに断る |
| 答えを待つ接続に上限がなく、呼び出しを重ねると主のプロセスの記述子を枯らせる | セッションの全体で 16 までとする |
| 合言葉を確かめる前に、解釈で断った記録を残す。手元のほかのプロセスが道具の結果に文を差し込める | 合言葉を、要求の頭を読んだ直後に、ほかのどの判断よりも先に確かめる |
| 合言葉がセッションで一つで、コマンドの後に残った背景のプロセスが後の中継を使える | 合言葉を呼び出しごとに作る |
| 頭の読み取りの待ちが一回の読み取りごとで、少しずつ送る接続が枠を塞げる | 待ちを頭の全体に掛ける（30 秒） |
| 正しくない長いホストで、断った記録を膨らませられる | 記録に載せるホストを、表示できる ASCII の 64 文字までに切り詰める |
| 機械自身の口に付いたアドレス（大域の IPv6 など）を拒まない。`web_fetch` も同じ | そのアドレスで bind できるものを拒む |
| 許可はドメインのすべてのポートに効くが、確認の文はポートを一つだけ示す | 確認の文に、すべてのポートに効くことを書く |
| 要求の行の対象の制御の文字を拒まない | 拒む |

それぞれのテストは、直したところを元に戻すと失敗することを確かめた。

## 主のプロセスの環境

試験用のプロセスと、`benitoiteh exec` の模擬の提供者で確かめた。

- ad-hoc の署名の実行ファイル（`benitoiteh` と同じ形）の環境は、同じ利用者のほかのプロセスから `KERN_PROCARGS2` で読める。Apple の署名の `/bin/sleep` などの環境は返らない。
- `danger-full-access` の `bash` からは、`ps -E -p $PPID` と `KERN_PROCARGS2` の両方で、主のプロセスの環境の提供者のキーを読めた。`escalate` の一回も、同じ利用者でサンドボックスの外で動くので、同じく読めると見られる（`escalate` の場合は試していない）。
- `workspace-write` のサンドボックスの中の `bash` からは読めなかった。`KERN_PROCARGS2` は `EPERM` を返し、`ps` は起動できなかった。
- 記憶は、資格のない Python からの `task_for_pid` が `KERN_FAILURE` で拒まれた。`lldb` は、開発者の道具の使用の許可の画面を出して止まり、許可しないまま時間切れになった。

対策は設計者が決める（BH-118 を【未決】にした）。サンドボックスの外で同じ利用者で動くコマンドは、主のプロセスの環境を読めなくても、提供者のキーを置いた設定のファイルを直に読める。このため、環境だけを守る効果は限られる。

## .agents の守り

段 1 のレビューが、`.agents` を一回ごとの確認なしに書ける道を二つ挙げた。どちらも直す前のコードで再現し、直した。

- APFS の大小文字を区別しない比べは、長い s（U+017F）を `s` に畳む。このため、書く道具に `.agentſ/skills/...` を渡すと、確認なしに作れた。こうして作ったディレクトリは `.agents` として開ける。こちらでも APFS で、`.agentſ` が `.agents` と同じ名前になり、幅の広い `ｓ` やゼロ幅の文字を挟んだ綴りは別の名前になることを確かめた。守る名前の比べで、U+017F を `s` とみなすようにした。
- 根の直下の `.agents` がシンボリックリンク（例: `.agents -> tools/agents`）のとき、Seatbelt はリンクを解いた後のパスに名前を当てる。そのため、リンクの先に書けた。Linux と同じく、守る名前（3 段まで）がシンボリックリンクなら macOS のサンドボックスを掛けない形にした。書く道具も、リンクの先に書くことを `.agents` への書き込みとして確認する。

あわせて、プロジェクトを作る道具が `.agents` の下に作ることを拒むようにした。そこに作ると、書ける場所の根が `.agents` の中になり、以後の書き込みが `.agents` の確認を受けないからである。

## キーチェーン

`~/Library/Keychains` の読み書きだけを拒む Seatbelt の方針の下で、`curl`、`git`（HTTPS）、`/usr/bin/python3` の `urllib`、`nscurl`（Security.framework）の TLS の検証を試した。どれも、方針がない場合と同じく通った。読めなくなるのは利用者の login のキーチェーンで、`security default-keychain` は既定のキーチェーンを見つけられなかった。利用者が login のキーチェーンに加えた独自のルート証明書を、サンドボックスの中の検証が使えるかは確かめていない。

## 秘密の名前の正規表現

制限モードでは、プロジェクトの中の秘密の名前（`.env` など）を、起動のたびに根から 3 段まで探して塞いでいる。[P5-43-stage1](P5-43-stage1.md)は、macOS で Seatbelt の正規表現の規則に改めるかを、macOS での確かめのときに決めるとしていた。

`sandbox-exec` で、読み取りを拒む正規表現の規則の後に、例外（`.env.example`・`.env.sample`・`.bnt`）を許す規則を置く形を試した。この形で、6 段の深さの `.env`、`.env.local`、`.pem`、`id_*` を拒み、例外とふつうのファイルを読めた。規則が壊れて制限モードの起動がすべて止まるという懸念は、この形では当たらなかった。改めるかは設計者が決める。改めれば、子プロセスが動いている間に作られたファイルと 4 段より深いファイルも塞げる。

## 直さなかったレビューの指摘

次の指摘は、設計の判断が要るか、規模が大きいので、まだ直していない。

| 指摘 | 内容 |
|---|---|
| macOS の gitdir の指す先 | 根の `.git` ファイルの `gitdir:` が書ける場所の中を指すとき、macOS はその先を守らない（Linux は守る） |
| Linux のまだない入れ子の `.agents` と場所ごとの信頼 | サンドボックスの中から `pkg/.agents` を作れる。信頼済みの根の下で後に `pkg` から起動すると、尋ねずに読み込む |
| Linux の `.agents` のリンクでの起動の失敗 | `.agents` がシンボリックリンクのプロジェクトでは、サンドボックスの中のコマンドがすべて起動しない。macOS も今回同じ形にした。設計書の代償に書くかを決める |
| 読ませないホームの場所の追加 | `~/.config/gh`、`~/.cargo/credentials.toml`、ほかのエージェントの認証の場所、いくつかの履歴などが一覧にない |
| `escalate` の環境 | `PATH` のほかの、ライブラリやモジュールを探す変数（`DYLD_*`・`PYTHONPATH` など）の書ける場所の項目を除いていない |
| 制限モードの秘密の名前のリンク | 先がどこでも塞ぐので、`.ssh -> ..` のようなリンクで制限モードの実行がすべて止まる |
| 秘密に見える環境変数の名前 | `MYSQL_PWD`・`*_PAT` などが判定から漏れる |
| 外部のエディタと通知のコマンド | 提供者のキーを含む環境をそのまま継ぐ |
