# Linux で進められる残件

> 2026-11-04 に、`docs/2026-11-02/` の `09-linux-followups.md` から本ディレクトリへ移した。本文は当時の記録のままとし、リンクだけを張り直した。

[README](../../2026-11-02/README.md)の「残っていること」のうち、本物の LLM も macOS の実機も要らない三つを、設計者の指示で進めた記録である。作業は 2026-11-03 に行った。確かめは、[P5-42-cloud-linux-check](P5-42-cloud-linux-check.md)の環境（x86_64 の Linux、Alpine 3.22.7 の rootfs、root でない利用者）で行った。本番のコードは変えていない。

## 時々失敗するテスト 2 件

[P5-42-other-test-files](P5-42-other-test-files.md)の「ほかの失敗」に挙げた 2 件を、負荷をかけて再現し、原因を確かめて、テストの側で直した。負荷は、同じテストを 6 本の並びで繰り返し走らせてかけた（4 コアの機械）。

| テスト | 原因 | 直し方 | 直す前 | 直した後 |
|---|---|---|---|---|
| `tests/exec.rs` の `closed_event_output_still_finishes_the_session_record` | 子は出力が閉じたと知った時点で終える。模擬の提供者は、要求を受け取る前の切断を `UnexpectedEof`、応答を書く途中の切断を `BrokenPipe` として返し、テストの最後の `server.shutdown()?` がそれを失敗にしていた。停止のときの誤りに、受け取った要求の数を添えて確かめた（前者は 0 件、後者は 1 件） | 停止のときの、この三つの切断の誤り（`UnexpectedEof`・`BrokenPipe`・`ConnectionReset`）を許す。確かめたい記録の形は変えない | 900 回で 8 回と 7 回 | 900 回で 0 回 |
| `tests/tui/commands.rs` の `accepted_rewind_finishes_before_quit_and_repeated_keyboard_interrupts` | 一つの入力の束の中で、`y` が巻き戻しを始め、続く Ctrl+C が「巻き戻しを待つ」の文を置く。巻き戻しが終わると、仕事の完了の受信がその文を消す（`src/ui/tui/worker.rs`）。受信は描く前に行うので、小さな巻き戻しが次の画面までに終わると、文は一度も描かれない | 描いた文は確かめない。束の中の Ctrl+C は巻き戻しの途中として扱われ、途中でなければ `/quit` の後の Ctrl+C で 130 を返すので、終了の状態の 0 が、取り消さずに待つ枝を通ったことを示す。常に 130 を返す変異でテストが失敗することを確かめた | 1,200 回で 838 回 | 1,200 回で 0 回 |

二つ目は、描いたかを確かめる手立てを、本番のコードに差し込み口を加えずには作れない（巻き戻しを止めておく口がない）。待ちの文を置く処理を消す退行は、このテストでは捕まえられなくなった。巻き戻しが次の画面までに終わる場合は、利用者に待たせる時間がないので、文が出ないことは振る舞いとして困らない。

## 評価の道具の Python のテストの 4 件の失敗

[P5-42-cloud-linux-check](P5-42-cloud-linux-check.md)の「結果」で原因を調べていないとした 4 件を確かめた。

| テスト | 原因 | 扱い |
|---|---|---|
| `test_security_json_recursion_special_files_and_record_redaction`（1 件） | Python 3.12 以降の `json` は、3,000 段の入れ子を `RecursionError` なしに読む。3.11 では `RecursionError` になる（3.11・3.12・3.13 で確かめた）。macOS の評価は Python 3.9.6 で行っており、そこでは通る | 入れ子を 100,000 段にした。3.11・3.12・3.13 のどれでも `RecursionError` になる。受け止めから `RecursionError` を除く変異で、3.13 でもテストが失敗する |
| `test_workspace_processes_stop_before_snapshot_and_judgment`（3 件） | 判定の道具は macOS を前提とし、`/usr/sbin/lsof` を呼び、`/tmp` を macOS の別名の `/private/tmp` に読み替える。Linux では `/tmp` が実のパスなので、読み替えた後の名前が、作業のディレクトリの実のパスと合わない | 直さない。道具は macOS 専用であり（`tools/skill-eval/README.md`）、macOS で確かめる |

直した後に、`TMPDIR` をリポジトリの外かつ `/tmp` の外に置き、`BENITOITEH_TEST_BENITOITE` を渡して走らせると、118 件のうち、失敗 2、誤り 9、飛ばし 42 だった。残りは、`judgment requires the macOS sandbox` の 8 件と、上の macOS を前提とするテスト（失敗 2、誤り 1）だけである。`TMPDIR` をリポジトリの中に置くと、`--work-root` の拒否とリポジトリの `AGENTS.md` を祖先として見ることで、誤りが増える。

## 端末を通した通しの試し

画面の部品のテストは、時刻と端末を差し替えて確かめている。本物の端末に固有の危険（擬似端末のバイト列からのキーと前面の報告の読み取り、確認を出した直後のキーの読み捨て、外部のエディタへの端末の明け渡しと復元）を、実行ファイルと擬似端末の境界で一度通すテストを、`tests/tui/pty.rs` に加えた（`terminal_confirmation_notification_and_external_editor_work_end_to_end`）。

- 前面を離れたと報告した後に、`.agents` への書き込みの確認が出る。出た直後に送った `y` は読み捨てられて書かれず、400 ミリ秒後の `y` で書く。
- 確認を開いたときと、処理を終えたときに、OSC 9 の通知が出る。
- Ctrl+G で外部のエディタ（`VISUAL` の試しのスクリプト）を開き、直した文を Enter で送る。送った要求にその文が入る。
- `/quit` で 0 で終え、端末の設定が戻り、前面の報告を切る列が出る。

確認の待ちを 0 ミリ秒にした変異と、OSC 9 を書かない変異で、テストが失敗した。負荷をかけた 240 回は通った。実際の端末のエミュレータ（iTerm2、Ghostty など）での OSC 9 の表示と、macOS での動きは確かめていない。
