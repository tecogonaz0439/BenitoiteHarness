# 段 4: 使い勝手

> 2026-11-04 に、`docs/2026-11-02/` の `07-stage4.md` から本ディレクトリへ移した。本文は当時の記録のままとし、リンクだけを張り直した。

[04-oss-feature-review](../../2026-11-02/04-oss-feature-review.md)の「段 4: 使い勝手」を、設計者の指示で進めた記録である。作業は 2026-11-02 から 2026-11-03 にかけて行った。確かめは、[P5-42-cloud-linux-check](P5-42-cloud-linux-check.md)の環境（x86_64 の Linux、Alpine 3.22.7 の rootfs、root でない利用者）で行った。macOS での確かめと、本物の LLM を呼ぶ確かめは行っていない。

## 設計者の決定

作業の前と途中に、設計者が次のとおり決めた。

| 問い | 決定 |
|---|---|
| `/model` | 再開と同じ規則で設ける。同じ提供者の設定の中でモデルと推論の度合いを替え、前のモデルの推論は送らない。途中の切り替えを設けないとしていた設計書の文は改める |
| `@` と画像 | `@` はパスを入れるだけとし、中身は LLM が道具で読む。外部のエディタは `VISUAL`・`EDITOR` で開く。画像は、画像のファイルのパスを貼ったときに添付する形に限り、クリップボードは扱わない |
| 画像の添付の規模 | 作り始めてから、三つのアダプタ、再開、fork、上限、圧縮のすべてに手が入ると分かり、改めて尋ねた。設計者は本来の添付（利用者の発言に画像を入れる）を作ると決めた |
| 利用者の定義するコマンド | 利用者の `prompts/` と、プロジェクトの `.agents/prompts/`（信頼の後だけ）から読む |
| 会話の書き出し | Markdown だけとする |
| 通知 | 端末の制御の列（OSC 9 と BEL）に加えて、利用者の指定するコマンドも起動する |
| `exec` の便宜 | 記録を残さない形に加えて、出力の型（JSON Schema）も作る |
| 送る入力を示すコマンド | 提供者へ送る要求の本文（認証の値を除く）を示す |
| `/init` | 決まった依頼を LLM に送り、`write` の道具と確認で書かせる |

| 項目 | 使い方 | 設計書 |
|---|---|---|
| 記録を残さないセッション | `exec --ephemeral`。記録のディレクトリを作った直後に墓標の名前へ替え、終えるときに消す。強制の終了で残っても次の起動で消える | 01-05「記録を残さないセッション」 |
| 送る入力を示すコマンド | `benitoiteh debug prompt-input [オプション] <依頼>`。`exec` と同じ準備で最初の要求を作り、URL・ヘッダ・本文を示す。鍵とトークンを読まず、送らず、記録を残さない | 05-01「debug prompt-input」 |
| 利用者の定義するコマンド | 設定のディレクトリの `prompts/<名前>.md` と、プロジェクトの `.agents/prompts/<名前>.md`。`/名前 引数` で、`$ARGUMENTS`・`$1`〜`$9` を埋めた文を依頼として送る | 05-02「利用者の定義するコマンド」、03-01「プロジェクトの信頼」 |
| `/init` | `AGENTS.md` を書く依頼（`prompts/init.md`）を送る。制限モードと、既に `AGENTS.md` があるときは送らない | 05-02「`/` で始まるコマンド」 |
| 通知 | 端末の前面の報告を有効にし、前面を離れたと報告された後だけ、確認を開いたときと処理を終えたときに知らせる。`[notifications]` の `terminal` と `command` | 05-02「通知」、05-01「設定ファイル」 |
| 会話の書き出し | `/export [パス]` と `benitoiteh sessions export <ID>`。今の枝を、圧縮の前の番も含めて Markdown にする | 01-05「会話の書き出し」 |
| 外部のエディタ | Ctrl+G。下書きはサンドボックスから読めない入力の履歴のディレクトリに置く | 05-02「入力の操作」 |
| `@` のパスの補い | `@` の後で Tab。プロジェクトのファイルのパスを補い、続けて押すと次の候補に替える | 05-02「入力の操作」 |
| 画像の添付 | 画像のファイルの絶対パスを貼ると添付になり、送るときに `read` と同じ処理で読む | 05-02「入力の操作」、02-01「画像の受け渡し」 |
| `/model` | `/model [名前 [推論の度合い]]`。次の依頼から新しいモデルで送り、新しい送り先の開始を記録する | 05-02「`/` で始まるコマンド」、01-04「推論の内容の扱い」 |

依存のクレートは加えていない。

## 安全の性質との関わり

どの項目も、確認と OS のサンドボックスを弱めない形にした。主な点は次のとおりである。

- プロジェクトの雛形は利用者の依頼として送るので、Skill と同じくプロジェクトの信頼の後にだけ読む。`.agents/prompts` があるだけで信頼を尋ねる。リンクを辿らず、固いリンクと読まないファイルを読まない。
- 画像の添付は `read` の道具の処理をそのまま通すので、範囲、読まないファイル、縮小の補助、保存の規則が同じに効く。読めない添付が一つでもあれば、依頼を送らない。
- 外部のエディタの下書きを一時ディレクトリに置くと、サンドボックスの中のコマンドが読み書きでき、利用者の依頼に文を足せる。入力の履歴のディレクトリ（サンドボックスから読めない）に置いた。
- 通知の文は決まった英文だけとし、LLM の文やファイルの名前を端末の制御の列とコマンドの引数に入れない。
- `debug prompt-input` は認証の値を読まず、印を付けたヘッダと認証の名前のヘッダを示さない。
- 書き出しは、道具の結果とファイルの中身を囲みの中に書く。依頼と応答の文は Markdown のまま書くので、表示する道具によっては LLM の文の HTML が描かれる（01-05 に書いた）。

## 確かめ

| 検査 | 結果 |
|---|---|
| `cargo test --workspace --target x86_64-unknown-linux-musl` | 805 件が通り、失敗 0、無視 16（`work/cloud-check/stage4-c.log`） |
| `cargo clippy --workspace --all-targets`（`x86_64-unknown-linux-musl`、`aarch64-apple-darwin`） | 通った。`aarch64-apple-darwin` は Linux からの検査だけである |
| `cargo fmt --check` | 通った |

新しいテストは、スキル `test-audit` の作成時の関門に従って加えた。要の部分は、実装を一時的に壊してテストが失敗することを確かめた（記録を消す印、プロジェクトの雛形の信頼の関門、`debug prompt-input` のヘッダの除き方）。

通知の変更（`d61a204`）で、端末の準備と復元のバイト列を確かめる既存の単体テストの期待値を直し損ね、全体のテストで見つけて別のコミット（`6bd00f8`）で直した。通知の変更の時点では、画面のテストだけを走らせていた。

## 確かめていないこと

- 本物の提供者が、利用者の発言の中の画像（BH-120）と、出力の型の指定（BH-121）を受け付けるか。模擬の提供者では本文の形だけを確かめた。どちらも本物の LLM を呼ぶので、設計者の了承を得てから確かめる。
- OpenAI の二つの口の出力の型の形は、`developers.openai.com` がこのセッションの通信の許可の外で読めなかったので、OpenAI の Python の SDK（`openai==1.109.1`）の、API の仕様から生成した型で確かめた。
- 端末ごとの OSC 9 と前面の報告の対応、外部のエディタを本物の端末で開くこと、macOS での動き。
