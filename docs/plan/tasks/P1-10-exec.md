# P1-10 `exec` の入口と P1 の完了の確かめ

## 目的

非対話の実行 `benitoiteh exec` を作り、P1 の部品（設定、セッション、文脈、提供者、道具、ループ）をつなぐ。P1 の完了条件を、`exec` の入口の境界のテストで確かめる。

## 作るもの

1. `cli` の `exec` のサブコマンド（P1-04 の引数の解釈を使う）。
   - 起動の順: 引数、利用者の設定、プロジェクトの設定、提供者とキー、書ける場所の検査、セッションのディレクトリと一時ディレクトリ（古いものの掃除を含む）、文脈、ループ。誤りは終了状態 2 で、標準エラー出力に一行で示す（05-01 の「終了状態」）。
   - 制限モードは、P1 ではサンドボックスと処理系を使わない（子プロセスを起動する道具がない）。起動のときの処理系とサンドボックスの確かめは P2 で加える。
   - プロジェクトの設定を読んだこと（と誤り）と、選んだ提供者とモデルを、標準エラー出力に示す（05-01）。
2. 出力（05-01 の「exec の出力」）。
   - `--json` がないとき: 最後の応答の文を標準出力に書く。道具の呼び出しの一行の要約と確認の結果を標準エラー出力に書く。標準エラー出力に書く要約の中の端末の制御の文字（`ESC`、C0 と C1 の制御の文字。改行は要約の中では空白に変える）を、目に見える形（`\x1b` など）に変える。
   - `--json` があるとき: `AgentEvent`（P1-09）を一行一件の JSON で標準出力に書き、最後の行を集計（P1-05 の `summary`、`"type": "summary"`）とする。
   - `--output-last-message <file>`: 最後の応答の文をファイルにも書く（書く先はプロジェクトの道具の範囲ではなく、利用者が指定したパスとして、標準のライブラリで書く）。
3. 終了状態（05-01）: 0（LLM が道具を呼ばずに応答を終えた）、1（上限、やり直せない提供者の誤り、非対話で許していない操作が続いた、拒否）、2（使い方と設定の誤り）、130（`SIGINT`・`SIGTERM` を受けて終えた。`signal-hook` で印を立て、ループの取り消しの印につなぐ）。非対話で許していない操作が同じ一連の処理で 3 回続いたら止める規則（03-03 の「非対話での扱い」）は、P1 では通常モードの書ける場所の外への書き込みに当てる。
4. panic のとき（06-01 の「ビルドの設定」）: panic hook で、セッションの記録に一行（`error`、`kind: "panic"`）を書いてから終える。対話の画面の端末の状態の復元は P4 で加える。
5. `--help` の文を、`exec` のオプションに合わせて更新する。

## テスト

`exec` の入口の境界（07-01 の「持ち主の境界」）で、実行ファイルを起動して確かめる（`tests/exec.rs`）。利用者の設定は、テストの中で作った設定ファイルを `XDG_CONFIG_HOME` で指し、提供者の `base_url` を模擬の提供者に向ける。`XDG_STATE_HOME` と `TMPDIR` もテストの一時ディレクトリに向ける。

- P1 の完了条件（00-03）: 模擬の提供者で、道具（`read`・`write`・`edit`）を使う一連の処理が `exec` で終わり、終了状態 0、標準出力の最後の応答、記録の行の列、`--json` の JSON Lines の列と最後の集計の行を確かめる。`anthropic-messages` と `openai-chat` の両方で行う。
- 提供者の元の項目が、2 回目以降の要求で、順序と識別子を変えずに送り返される（模擬の提供者が受け取った本文で確かめる）。
- ストリームの切断と出力の上限で、道具が実行されない（ファイルが変わらない、記録に `tool_start` がない）。
- 401 で終了状態 1、知らないオプションで 2、設定の知らない欄で 2、書ける場所の検査に当たるプロジェクト（`HOME` をプロジェクトにするなど）で 2。
- `SIGINT` で終了状態 130 になり、記録の最後が `session_end`（`cancelled`）である。
- 標準エラー出力の要約で、道具の結果に含まれた `ESC` が目に見える形に変わる。
- 記録のファイルとセッションのディレクトリの権限、終わった後に一時ディレクトリが消えていること。
- 記録とイベントに API キーが含まれない。
