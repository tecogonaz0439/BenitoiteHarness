# P5-48 macOS で、制限モードの秘密の名前をどの深さでも読ませない

- 状態: 完了
- 依存: P5-47

## 目的

制限モードで、プロジェクトの中の秘密の名前（`.env`、鍵と証明書の形の名前、`.ssh` など）を読ませない仕組みは、起動のたびに根から 3 段まで探し、見つけたものを読ませない場所に加える（P5-43、設計書 03-02「制限モードの方針」）。この仕組みは、4 段より深いものと、起動の後に作られたものを塞がない。macOS では、Seatbelt の正規表現の規則で、どの深さでも塞ぐ。

## 経緯

[P5-47](P5-47-post-merge-macos-checks.md) で、この形の規則が macOS で働くことを `sandbox-exec` で確かめた。2026-11-04 に設計者が、探す仕組みを残して規則を足す案（置き換えない案）に決めた。作業はオーケストレータ（Claude Code）が行った。

## 作ったもの

- `PolicyConfig` に `secret_name_roots` を加えた（JSON で省略できる。根は正規の絶対パスのディレクトリであることを確かめる）。制限モードの方針は、プロジェクトをここに入れる。確認なしの一時スクリプトの方針は、この方針から作るので同じく入る。
- macOS の Seatbelt の方針に、根ごとに二つの拒む規則を加えた。
  1. 最後の要素が秘密の名前で、例外（`.env.example`・`.env.sample`、`.bnt`）でないもの。例外は `require-not` で拒む規則に組み込む。許す規則を後に置くと、読める範囲の外まで読めるようにしうるからである。
  2. 秘密の名前のディレクトリの下のもの（例外の名前を含む）。
- Linux は名前の形で拒めないので、`secret_name_roots` を使わず、探す仕組みだけで守る。

名前の規則は `src/tools/exclude.rs` の `secret_component` と同じにした（`.git` は、探す仕組みと同じく除く）。

## テスト

`tests/sandbox_benitoite_run.rs` の `restricted_scripts_cannot_read_project_secret_names` に行を足した。本物の処理系とサンドボックスで、`File.Read` を確認したスクリプトが読めるかを確かめる。

| 行 | macOS | Linux |
|---|---|---|
| `a/b/c/.env`（4 段目） | 読めない | 読める（保証の外） |
| `a/b/c/d/e/keys/deploy.key`（6 段目） | 読めない | 読める（保証の外） |
| `a/b/c/d/.env.example`（深い例外） | 読める | 読める |
| `.ssh/helper.bnt`（秘密のディレクトリの中のソース） | 読めない | 読めない |
| `a/b/c/d/.ssh/helper.bnt`（深い秘密のディレクトリの中のソース） | 読めない | 読める（保証の外） |

作成時の関門の答えは次のとおりである。

1. 守る契約: macOS で、制限モードのスクリプトが、どの深さの秘密の名前も読めず、例外と普通のファイルは読める。
2. 捕まえる退行: 規則を掛けない、秘密のディレクトリの下の規則を落とす、例外を広げすぎる。
3. 既存のテストとの違い: 既存の行は 3 段までと、Linux と同じ結果だけを確かめていた。同じテストの表に行を足し、新しいテストは作っていない。
4. 本番のコードに差し込み口を加えていない。

壊した版で、次のように確かめた。

| 壊した箇所 | 結果 |
|---|---|
| 制限モードの方針に `secret_name_roots` を入れない | `a/b/c/.env` の行で失敗した |
| 秘密のディレクトリの下を拒む規則を落とす | `a/b/c/d/.ssh/helper.bnt` の行で失敗した（浅い `.ssh` の行は探す仕組みが塞ぐので通った。このため深い行を足した） |

## 確かめた結果

macOS で、`cargo clippy`（ホスト、`aarch64-unknown-linux-musl`、`x86_64-unknown-linux-musl`）と、`sandbox` の単体テスト、`sandbox_benitoite_run`・`sandbox_benitoite_test`・`sandbox_benitoite_scratch`・`sandbox_macos`・`sandbox_exec_restricted` が通った。全体の検査の結果は、取り込みの記録に書く。
