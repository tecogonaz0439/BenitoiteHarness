# P1-06 道具の枠組みと、読む道具（read・glob・grep）

## 目的

道具の枠組み（定義、引数の修復と検証、モードごとの一覧、実行の文脈、結果、切り詰め）と、読む道具 `read`・`glob`・`grep` と、読まないファイルの規則を作る。P1-07 が同じ枠組みに書く道具を加え、P1-09 のループが枠組みを通して道具を呼ぶ。

## 作るもの

`crates/benitoiteh/src/tools/`。

1. 枠組み（`mod.rs` ほか）。
   - 道具ごとに、名前、`ToolSpec`（引数）、システムプロンプトに載せる一行の説明と規則（0〜3 行。英文は P1-08 で `prompts/` に置くので、この作業では道具の識別子から引ける形の欄を置き、仮の英文を入れてよい。P1-08 が差し替える）、並行の可否の印、確認の要否を持つ。確認が要る操作（通常モードの書ける場所の外と守る場所への書き込み）は、道具が実行せずに「確認が要る」という結果（操作の要約を含む）を返し、P1-09 のループが確認を受ける側（`approval` のモジュールの `Approver`）に問い、許可されたら同じ呼び出しを確認済みとして実行し直す。
   - モードごとの道具の一覧 `ToolSet`: 制限モードは `read`・`glob`・`grep`・`write`・`edit`、通常モードも同じ五つ（P1 の範囲。`bash` は P3、`benitoite_*` は P2 で加える）。一覧の順はセッションの間変えない（01-02 の「道具の一覧を固定する理由」）。
   - 引数の修復と検証: 配列やオブジェクトの欄に JSON の文字列が来たら、文字列を JSON として読んで使う。OpenAI の strict の形で来た `null` は省いたものとする（P1-01 の関数）。そのうえで、`ToolSpec` の型と必須で検証する。知らない道具と検証の誤りは、実行せずに誤りの結果を返す。誤りの文は、何が違うかと、正しい形を示す。
   - 実行の文脈 `ToolContext`（P1-09 が `std::thread::scope` で最大 8 つの道具を並べて実行するので、共有の参照で呼べる形（`Sync`。変わる状態は内側の `Mutex` で持つ）にする）: モード、プロジェクトの `ScopeRoot`、一時ディレクトリの `ScopeRoot`、今のセッションの `spill/` の場所、読まないファイルの規則、読んだ版の記録（P1-07 が使う）。
   - 結果 `ToolOutput`: LLM に返す文、誤りの印、画面に示す付きの情報（差分など。P1 では文だけでよい）。
   - 切り詰めの共通の関数: 先頭か末尾を、行の数とバイト数の先に達した方で残す。切り詰めたときの末尾の一行の印。どの結果も 64 KiB を超えるときに中ほどを除く関数（01-03 の「出力の切り詰め」）。UTF-8 の文字の途中で切らない。
2. パスの受け取り: 道具の `path` を、プロジェクトからの相対か絶対のパスとして受け取り、読める範囲（制限モードの `read` はプロジェクトの下、一時ディレクトリ、`spill/`。制限モードの `glob`・`grep` はプロジェクトの下だけ（01-03 の表）。通常モードは読まないファイルの規則のほかは制限しない）に入るかを判定して、該当する `ScopeRoot` と `ScopeRelPath` に変える。通常モードでプロジェクトの外を読むときは、標準のライブラリで開いてよい（範囲を限らない読み取りであり、通常モードの読まないファイルの規則は保証ではない。01-03 の「読まないファイル」）。その場合も、読まないファイルの規則は実のパス（`std::fs::canonicalize`）で判定する。
3. 読まないファイルの規則（`tools/exclude.rs` など）: 01-03 の「読まないファイル」の既定と、利用者の設定・プロジェクトの設定（足すだけ）の追加。`benitoiteh` の設定のディレクトリとデータのディレクトリは、今のセッションの `spill/` を除いて読まない。判定は実のパスで行う。
4. `read`: 01-03 の「read」のとおり（`cat -n` の形、2,000 行か 50 KiB、続きの印、一行 2,000 文字の切り詰めの印、`offset` の誤り、画像は誤り、読んだ版の記録）。テキストかの判定は、先頭の 8 KiB に NUL を含むかで行い、含めば「バイナリのファイル」の誤りとする。UTF-8 でない部分は置き換えの文字にする。
5. `glob`: `ignore` クレートで `.gitignore` の規則に従って辿り（`WalkBuilder` の既定は、ドットで始まるファイルを隠し、`.git` のないディレクトリでは `.gitignore` を読まず、利用者の全体の gitignore と親のディレクトリの規則を読むので、`hidden(false)`・`require_git(false)`・`git_global(false)`・`git_exclude(false)`・`parents(false)` を指定する。`ignore-0.4.33/src/dir.rs` で確かめた）、`globset` でパターンに合わせ、読まないファイルを除き、更新の時刻の新しい順に最大 500 件を返す。シンボリックリンクは辿らない。
6. `grep`: `regex` で各行を探す。`path`・`glob`・`ignore_case`・`context`・`files_only` を扱う。`.gitignore` と読まないファイルの規則に従い、バイナリのファイルを飛ばす。最大 100 件か 50 KiB、一行 500 文字を超えるときの前後 500 文字の示し方と文字の位置（01-03 の「grep」）。

`ignore` の走査はリンクを辿らない設定にし、走査で見つけたファイルを開くときは `safe_fs` を通す。

## テスト

道具の呼び出しの JSON を入力にして、道具の実行器の境界で確かめる（07-01 の「持ち主の境界」）。

- `read`: 行の番号、`offset`・`limit`、続きの印、長い行の印、範囲の外（`..`、外を指すシンボリックリンク）の拒否、読まないファイルの拒否と理由、バイナリの誤り、`spill/` を読めること。
- `glob`・`grep`: `.gitignore` と読まないファイルに当たるものを返さない。件数の上限と印。長い一行の示し方。
- 引数の修復（配列の欄に JSON の文字列）と検証の誤り（型の違い、必須の欠け、知らない道具）。
- 制限モードと通常モードで読める範囲が違う（制限モードではプロジェクトの外を読めない）。
