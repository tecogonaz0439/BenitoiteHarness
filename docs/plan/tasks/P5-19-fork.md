# P5-19 `/fork`（今の枝を新しいセッションに写す）

## 目的

設計書 01-05「セッションの木」の `/fork` と、05-02 の `/fork` のコマンドを実装する。今の道（または選んだ依頼の直前までの道）を、新しいセッションに写し、対話の画面をそのセッションに移す。この作業で本物の LLM の提供者を呼ばない。P5-17 を取り込んだ `main` から始める。

## 作るもの

### 1. 写す処理（`session`）

- 新しいセッションの ID とディレクトリとロックを、今の新しいセッションと同じ作り方で作る。
- ヘッダの行は、元のセッションのヘッダの値（モード、プロジェクト、提供者、処理系、Skill など）を今の値で書き、加えて元のセッションの ID と、写した道の先端の節点の番号を書く（例: `forked_from: { session: <ID>, node: <番号> }`）。
- 写す記録は、道の上の節点の記録と、それを組み立てるのに要る記録（道の上の最後の圧縮の記録、その後の節点）とする。ほかの枝の記録、時点（巻き戻しの記録）、承認の記録は写さない。節点の番号は、写した先で 1 から振り直す（`branch` の記録は写さない）。
- 写した記録が参照する `spill/` のファイルと `objects/` の中身（画像）だけを、新しいセッションのディレクトリに写す。大きさは新しいセッションの上限に数え、上限を超えるなら写さずに誤りを示す（元のセッションは変えない）。
- 写している途中で失敗したら、作りかけの新しいセッションのディレクトリを消し（P5-18 の再帰しない削除）、元のセッションのまま続ける。

### 2. 画面

- `/fork` で、今の道を写す。`/fork` の後に、P5-17 の選択の画面と同じ形で依頼を選べば、その依頼の直前までの道を写す（引数の形は `/fork` と、選択の画面を開く操作の二つとし、決め方は P5-17 の画面の作りに合わせる）。
- 写したら、`/new` と同じ流れで、新しいセッションに移る（モード、サンドボックス、承認の方針などは今のセッションの値を引き継ぐ。このセッションで許したコマンドと、読んだ版は引き継がない）。移ったことと、元のセッションの ID を知らせる。
- ファイルの時点は写さないので、新しいセッションの `/rewind` は、写した後に記録した時点だけを示す。

### 3. 一覧

- `benitoiteh sessions` は、元のセッションを持つセッションに、元の ID を添えて示す（`--json` では欄を加える）。

## テスト

- 写す処理: 二つの枝を持つセッションから今の道を写すと、新しいセッションの記録が道の節点だけを持ち、番号が 1 から振り直され、再開すると同じ会話になること。依頼の直前までを写すと、その依頼より後を含まないこと。画像と `spill/` の中身が写され、元のセッションを消しても新しいセッションで読めること。写したものが上限を超えるときは、新しいセッションを作らずに誤りを示すこと。
- 画面: `/fork` の後に新しいセッションへ移り、元の ID が知らされ、承認と読んだ版が引き継がれないこと。
- 一覧: 写したセッションに元の ID が示されること。
