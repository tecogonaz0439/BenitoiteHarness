# P5-44 キャッチアップの案の段 3: 通信の中継

- 状態: 完了
- 依存: P5-43

## 目的

通常モードのサンドボックスの中の通信を、利用者が許したドメインにだけ届ける（BH-046）。制限モードの `Http.Connect`（BH-040）を同じ中継で限る方針を決める。

## 経緯

本作業は、2026-11-02 にオーケストレータ（Claude Code）が設計者の指示で、作業用のブランチ `claude/stoic-ride-otqoj5` の上で行った。中継の形は、設計者が 2026-11-02 に決めた。実装プランの外で行ったので、2026-11-04 に本書を作業の記録として起こした。

## 作ったもの

- `src/sandbox/proxy.rs`、`src/sandbox/proxy/http.rs`: ドメインを確かめる HTTP のプロキシ（中継）の核。依存のクレートは加えていない。
- Linux: ネットワークの名前空間の中で補助のプロセスが待ち受け、その記述子を親へ渡す。
- macOS: 主のプロセスがループバックで待ち受け、Seatbelt でそのポートへの接続だけを許す。
- `[normal] network = "proxy"` と `[normal] allowed_domains` の設定、`bash` への中継のつなぎ込み、通信の確認の画面。

対応する設計書は、03-02「通信の中継」、03-03「通信の確認」、04-01「処理系への要望」、05-01 である。BH-046 を閉じ、BH-040 に方針を書いた。

## 確かめた結果

[段 3 の記録](../results/P5-44-stage3.md)に書いた。macOS での確かめ（BH-119）と、2026-11-04 のレビューの指摘の直し（`::1` の待ち受け、呼び出しごとの合言葉、確認の寿命など）は [P5-47](P5-47-post-merge-macos-checks.md) で行った。

## 残したこと

- 制限モードの中継は、処理系がプロキシに従うようになるまで待つ（処理系への要望の R1。[要望の文書](../../2026-11-02/10-benitoite-requests.md)）。
- macOS の方針の拒否の記録から、拒否の理由を道具の結果に返すこと（キャッチアップの案の段 3 の 3）。
