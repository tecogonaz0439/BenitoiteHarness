# P0-02 範囲の根から相対に開くファイルの操作（BH-093）

## 目的

主のプロセスが範囲を限って行うファイルの操作（制限モードの読み取り、書く道具、巻き戻しの書き戻し、一時的なスクリプトの書き込み、`create_project`）の土台となるモジュール `safe_fs` を作る。あわせて、macOS でシンボリックリンクを範囲の中だけで辿って開く方法があるかを確かめる（BH-093）。

## 前提（オーケストレータが確かめたこと）

2026-10-17 に、手元の macOS 27.0.1 の SDK（`/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include/sys/fcntl.h`）と `man 2 open` で次のことを確かめた。

- `O_RESOLVE_BENEATH`（`0x00001000`）: 「path resolution must not escape the directory associated with the file descriptor」。`openat` で使う。
- `O_UNIQUE`（`0x00002000`）: 「ensure a file is opened only if it has a single hard link」。ハードリンクが複数あると `ENOTCAPABLE` で失敗する。
- `O_NOFOLLOW_ANY`（`0x20000000`）: パスのどこにもシンボリックリンクを許さない。
- `AT_RESOLVE_BENEATH`（`0x2000`）と `AT_SYMLINK_NOFOLLOW_ANY`（`0x0800`）が `*at` の関数の印としてある。
- `rustix` 1.1.5 は、Apple の対象では `OFlags::NOFOLLOW_ANY` を定義するが、`RESOLVE_BENEATH` は FreeBSD でだけ定義する（`rustix-1.1.5/src/backend/libc/fs/types.rs`）。`OFlags::from_bits_retain` に値を与えれば、`unsafe` なしに印を渡せる見込みである。

## 作るもの

`crates/benitoiteh/src/safe_fs/`（`mod.rs`、`text.rs`、OS ごとの実装のファイル）と、そのテスト。

1. `ScopeRelPath`: 根からの相対のパス。作るときに、空、絶対のパス、`.`・`..` の要素、NUL を含むものを拒む。道具が受け取るパス（プロジェクトからの相対か絶対）を、根の実のパスの下にあるかを字面で判定して `ScopeRelPath` に変える関数も置く（字面の判定は入口の早い拒否であり、安全の根拠は次の開き方である）。
2. `ScopeRoot`: 根のディレクトリを `O_DIRECTORY` で開いて保持した記述子と、その実のパス。次の操作を持つ。
   - 読むために開く（`File` を返す）。
   - メタデータを得る（リンクを辿らない。デバイス、inode、大きさ、更新の時刻、変更の時刻、種類、ハードリンクの数、権限）。
   - ディレクトリの一覧（名前と種類。リンクを辿らない）。
   - 書く: 親のディレクトリを開き、同じディレクトリに一時ファイルを `O_CREAT | O_EXCL | O_NOFOLLOW` で作って書き、`renameat` で名前を付け替える。親がなければ作る指定（`create_parents`）を持つ。書く先の最後の要素がシンボリックリンクなら、先がなくても拒む。すでにある通常のファイルのハードリンクの数が 2 以上なら拒む。権限は、置き換えるときは元のファイルの権限を保ち、新しく作るときは 0644 とする。
   - 新しいディレクトリを作る（すでにあれば誤り）。
   - ファイルを消す、空のディレクトリを消す、シンボリックリンクを作る、シンボリックリンクの先の文字列を読む。どれもリンクを辿らない。
3. 開き方は OS ごとに次のとおりとする。
   - Linux: `rustix::fs::openat2` に `ResolveFlags::BENEATH | ResolveFlags::NO_MAGICLINKS` を付ける。最後の要素のリンクを辿らない操作には、さらに `OFlags::NOFOLLOW` を付ける。`openat2` が `ENOSYS` を返すカーネルでは、開かずに誤りとする。
   - macOS: 確かめた結果（後述の「確かめること」）で選ぶ。`O_RESOLVE_BENEATH` が期待どおりに働けば、それを使い、範囲の中のシンボリックリンクを辿れるようにする。働かなければ、根の記述子から要素を一つずつ `O_NOFOLLOW`（途中の要素は `O_DIRECTORY` も）で開いて辿り、途中の要素のシンボリックリンクを誤りにする（設計書の現在の方針）。
4. 開いた記述子から実のパスを得る関数（10-interfaces の「`safe_fs`（P0-02）」）。範囲の中のシンボリックリンクを辿って開く形を採るときは、P1 の道具が、拡張子と守る場所（`.git`・`.benitoiteh`）の判定を、要求したパスの字面ではなく、開いた記述子の実のパスで行えるようにする。理由: 字面から求めた実のパスで判定してから開くと、その間にリンクを差し替えられる。
5. 字面の判定（1 の入口の早い拒否）は、根の実のパスと比べる前に、要求したパスの、存在する最も長い前の部分を正規の形（`std::fs::canonicalize`）に変えてから行う。理由: macOS の `/var` は `/private/var` へのリンクであり、字面のまま比べると範囲の中のパスを誤って拒む。
6. `SafeFsError` と、その英語の文言（`text.rs`）。範囲の外へ出るパス、途中の要素のシンボリックリンク、最後の要素のシンボリックリンク（書くとき）、ハードリンクの数、すでにある、ない、OS の誤り（`std::io::Error` の種類を保つ）を分ける。

`safe_fs` は、パスの規則のうちファイルシステムの操作だけを持つ。拡張子（`.bnt`）、守る場所（`.git`・`.benitoiteh`）、読まないファイル、読んでから直す規則は、P1 の `tools` が `safe_fs` の上で判定する。ただし、それらの判定に要る値（実のパス、メタデータ）は `safe_fs` から得られるようにする。

## 確かめること

1. macOS（手元の 27.0.1）で、`OFlags::from_bits_retain` で `O_RESOLVE_BENEATH` を `rustix::fs::openat` に渡せるか。範囲の中を指すシンボリックリンク（途中の要素と最後の要素）を辿って開けるか。範囲の外を指すリンク、`..` で外へ出るパス、絶対のパスのリンクで、どの `errno` で失敗するか。
2. 同じく `O_UNIQUE` が、ハードリンクの数が 2 以上のファイルを開くときに失敗するか。使えるなら、書く道具のハードリンクの判定を、メタデータを見てから開く形ではなく、開くときの印で行えるか（判定と開くことの間の差し替えを防げる）。
3. 上の印が、どの版の macOS から使えるか。手元の SDK のヘッダと man の記述の範囲で答え、分からなければ分からないと書く。
4. Linux の `openat2` は、P0-01 の `linux` の段（`container` の中）で走るテストで確かめる。Codex の中では走らないので、テストを書き、Linux 向けのビルドと clippy を通すところまでとする。

確かめた結果は、完了の報告の「確かめたこと」に、試したコードの要点と結果を添えて書く。オーケストレータが BH-093 と設計書 01-03 に反映する。

## テスト

`safe_fs` の公開の関数の契約を、本物のファイルシステムで確かめる（ユニットテストか `tests/safe_fs.rs`）。

- 範囲の中のファイルを読める。`..` と絶対のパスと、範囲の外を指すシンボリックリンク（途中の要素、最後の要素）では開けない。
- 範囲の中を指す途中の要素のシンボリックリンクの扱いが、採った開き方のとおりである（辿れる、または誤り）。
- 書くとき、最後の要素がシンボリックリンク（先がない場合を含む）なら拒み、リンクの先にファイルができない。ハードリンクの数が 2 以上のファイルを拒む。
- 書いた結果が、元のファイルの権限を保ち、途中で失敗したときに元のファイルが残る（一時ファイルが残らない）。
- 消す操作がリンクを辿らない（リンクの先のファイルが残る）。
