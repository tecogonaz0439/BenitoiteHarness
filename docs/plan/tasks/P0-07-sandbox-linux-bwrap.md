# P0-07 Linux の補助のプロセスを bubblewrap の形に作り直す（BH-049 の決定）

## 目的

P0-05 で作った Linux の補助のプロセスを、2026-10-18 の設計者の決定（BH-049 を閉じた）に合わせて作り直す。P0-05 の形（Landlock と seccomp だけ）は、書ける場所に新しいファイルを作れない。新しい形では、bubblewrap が名前空間とファイルシステムの見え方を作り、その中で起動した補助のプロセスが、Landlock と seccomp を掛けてから目的のプログラムを `exec` する。

## 作るもの

1. **bubblewrap の引数を作る部分**（`crates/benitoiteh/src/sandbox/linux/` の下。ファイルの分け方は任せる）
   - 方針（`SandboxPolicy`）から、03-02 の「Linux のファイルシステムの見え方」のとおりの bubblewrap の引数の並びを作る。
   - 全体: `--unshare-user`・`--unshare-pid`・`--unshare-ipc`・`--disable-userns`・`--new-session`・`--die-with-parent`・`--ro-bind / /`・`--dev /dev`・`--proc /proc`。IP の通信を許さない方針では `--unshare-net` を加える。
   - 書ける場所ごとに `--bind <場所> <場所>`。
   - 書ける場所の根の直下の `.git` と `.benitoiteh`:
     - あるときは `--ro-bind`。`.git` が `gitdir:` の行のファイルで、指す先が書ける場所の中にあるときは、指す先も `--ro-bind`。
     - まだないときは `--perms 555 --tmpfs <場所> --remount-ro <場所>`。
   - 入れ子の守る場所: 書ける場所の根から 3 段（`a/b/.git` まで）を、シンボリックリンクを辿らずに探す。すでにある `.git` と `.benitoiteh` を、名前の ASCII の大文字と小文字を区別せずに見つけ、`--ro-bind` で重ねる。深さは、方針の欄で変えられる形にしてよい（既定は 3）。
   - 読ませない場所:
     - すでにあるディレクトリは `--perms 000 --tmpfs <場所> --remount-ro <場所>`。
     - すでにあるファイルは、権限 000 の空のファイルで覆う。`--perms 000 --ro-bind-data <記述子> <場所>` を試す。記述子が補助のプロセスに残って手順 2 で失敗するなら、その結果を報告し、代わりの形を提案する。代わりの形は、読ませない場所を含まない部分木に Landlock の読み取りの権利を与える P0-05 の形などである（BH-094）。
     - まだない読ませない場所は覆わない。
   - 守る場所と読ませない場所に至るパスに、書ける場所の中のシンボリックリンクがあるときは、引数を作らずに失敗とする。
   - 引数の並びは、方針と、引数を作る時点のファイルシステムの状態から決まる値として返し、ユニットテストで確かめられる形にする。パスは引数として渡し、シェルの文字列に埋め込まない。
2. **起動の形**
   - Linux の `SandboxCommand` から、`/usr/bin/bwrap <引数...> -- <benitoiteh> __sandbox <方針の JSON> -- <プログラム> <引数...>` の `std::process::Command` を作る。
   - `bwrap` は `/usr/bin/bwrap` の固定のパスとし、`PATH` から探さない。テストのために、パスを差し替える公開の口は作らない。テストの環境に `/usr/bin/bwrap` を置く（後述の「テストの環境」）。
   - 塞ぐために bubblewrap が作るディレクトリの後始末: 子プロセスが終わった後に、親が、起動の前になかった根の直下の守る場所が、空のディレクトリとして残っていれば消す。消すのは、空であり、起動の前になかったものだけとする。後始末の呼び出しを忘れられない形（終わりを待つ関数が後始末も行う、など）にする。今の公開の型（`SandboxCommand::to_command` が `Command` を返す形）を変えてよい。変えたら、新しいシグネチャを報告に書く。
   - 並んで動く子プロセスどうしの競合と、強制終了で残ったものの扱い（BH-095）は、この作業では作らない。競合があることを、コメントと報告に書く。
3. **補助のプロセス**（`run_helper`）
   - 手順は 03-02 の 1〜6 のとおり（名前空間は作らない）。
   - Landlock の規則を、新しい形に合わせて改める。
     - 書ける場所には、作成・削除・名前の付け替え（`Refer` を含む）・`Truncate` を含む書き込みの権利をすべて与える。P0-05 の「すでにあるファイルの更新だけ」の規則（`grant_existing_files`）は除く。
     - 読み取りの権利は、読める範囲（`ReadAccess`）の根に与える。読ませない場所は bubblewrap で覆うので、P0-05 の部分木に分ける形（`grant_tree`）は、読ませない場所のファイルを覆う代わりの形に使うときだけ残す。
     - 実行の権利は、今のとおり許すプログラムだけに与える（読み取りの規則に `Execute` を含めない）。
   - seccomp のフィルタは今のまま使う。
4. **使えるかの確かめ**
   - Linux でサンドボックスを掛けられるかを判定する関数を置く。判定するのは、`/usr/bin/bwrap` があること、`bwrap` で特権を持たない利用者の名前空間を作れること、Landlock の ABI の版 3、seccomp である。
   - 判定は、補助のプロセスを実際の方針の形で一度起動して行う（03-02 の「サンドボックスを掛けられないとき」）。
   - 結果は、項目ごとに「使える」「使えない（理由）」を返す（05-01 の `doctor` で使う）。

## テスト

`tests/sandbox_linux.rs` を、07-01 の「安全の性質のテスト」の Linux の項目に合わせて改める。P0-05 のテストのうち、新しい形でも成り立つもの（実行の権利、動的リンクのローダ、外部の Unix IPC、IP の通信、補助のプロセスの各段階の失敗）は残す。期待が変わるもの（書ける場所に新しいファイルを作れないこと）は、新しい期待に改める。どのテストを改めたかを報告に書く。

- 書ける場所に、新しいファイルとディレクトリを作れ、消せ、一時のファイルから名前を付け替えて書けること。入れ子のディレクトリの中でも同じこと。
- 書ける場所の根の直下の `.git` と `.benitoiteh` について、次の 4 つの場合に、作れず、書けず、付け替えて作り直せないこと。
  - すでにあるディレクトリのとき。
  - `gitdir:` のファイルのとき。
  - まだないとき。
  - ほかの名前のディレクトリを `.git` に付け替えるとき。
- すでにある入れ子の `sub/.git`（`.GIT` の綴りを含む）に書けず、付け替えられないこと。4 段より深いものと、まだない入れ子のものは守らないこと（期待をその結果に合わせ、保証の範囲の外であることをコメントに書く）。
- 読ませない場所のディレクトリとファイルの、内容も一覧も読めないこと。
- サンドボックスの中から、守る場所と読ませない場所のマウントを外せないこと（`sandbox-probe` に `umount` の操作を足す。`rustix` の安全な関数で書けなければ、試さずに報告する）。
- 子プロセスが終わった後に、塞ぐために作らせた空のディレクトリが残らないこと。起動の前からあった空の `.git` のディレクトリは消さないこと。
- 書ける場所の中のシンボリックリンクを経て守る場所を指す方針で、起動せずに失敗すること。
- `bwrap` がない環境で、使えるかの確かめが「使えない」を返し、子プロセスを起動しないこと（`/usr/bin/bwrap` のない環境は、テストの中で作れないなら、引数を作る部分のユニットテストと、判定の関数の分岐のユニットテストで確かめる）。
- 引数を作る部分のユニットテスト: 方針ごとの引数の並び（期待の並びと比べる）。

## テストの環境

Linux のテストは、オーケストレータが、設計者の常設の x86_64 の機械の podman で走らせる（00-common の「検査」）。2026-10-18 に、オーケストレータが次のことを確かめた。

- `alpine:3.22` に `apk add bubblewrap` で入れた bubblewrap 0.12.0 は、`--security-opt unmask=ALL` を付けた rootless の podman の中で動く。付けないと、`/proc` のマウントで失敗する（`Can't mount proc on /proc: Operation not permitted`）。
- その中で、上の「全体」の引数と `--perms 555 --tmpfs /w/.git --remount-ro /w/.git` を渡して試した。中のプロセスは、`/w` に新しいファイルを作れた。`/w/.git` の中に作ると `Read-only file system`、付け替えと削除は `Resource busy`、`umount` は `Operation not permitted` になった。外から見ると、`/w/.git` に空のディレクトリが残った。

オーケストレータは、この作業の取り込みの前に次のことを行う。Codex は `scripts/` を変えない。

- bubblewrap を入れたテスト用のイメージを、その機械に作る。
- `scripts/remote-linux-run.sh` で、そのイメージと `--security-opt unmask=ALL` を使う。
- テストを root でない利用者で走らせるかを決める。理由: コンテナの中の root で走らせると、権限 000 の覆いの確かめが、特権によって意味を失うおそれがある。

aarch64 の `container` の中では、今のとおり `sandbox_linux` を走らせない。
