# P0-07 Linux の補助のプロセスを bubblewrap の形に作り直す（BH-049 の決定）

## 目的

P0-05 で作った Linux の補助のプロセスを、2026-10-17 の設計者の決定（BH-049 を閉じた）に合わせて作り直す。P0-05 の形（Landlock と seccomp だけ）は、書ける場所に新しいファイルを作れない。

新しい形では、bubblewrap が名前空間とファイルシステムの見え方を作る。その中で起動した補助のプロセスが、Landlock と seccomp を掛けてから、目的のプログラムを `exec` する。

## 作るもの

### 1. bubblewrap の引数を作る部分

`crates/benitoiteh/src/sandbox/linux/` の下に作る。ファイルの分け方は任せる。

方針（`SandboxPolicy`）と、引数を作る時点のファイルシステムの状態から、bubblewrap の引数の並びを作る。並びは 03-02 の「Linux のファイルシステムの見え方」のとおりとする。

引数を作る部分は、次の三つを返す値とする。ユニットテストで、期待の並びと比べられる形にする。

- 引数の並び。
- 塞ぐために作らせるディレクトリの一覧（後述の後始末に使う）。
- 覆いに使うファイルの場所（後述の読ませない場所のファイル）。

パスは引数として渡し、シェルの文字列に埋め込まない。

並びの順は次のとおりとする。bubblewrap は引数の順に処理し、後のマウントが前のものを覆うからである。

1. 全体の指定: `--unshare-user`・`--unshare-pid`・`--unshare-ipc`・`--disable-userns`・`--new-session`・`--die-with-parent`。IP の通信を許さない方針では `--unshare-net` を加える。
2. `--ro-bind / /`・`--dev /dev`・`--proc /proc`。
3. 書ける場所ごとの `--bind <場所> <場所>`。入れ子の書ける場所は、親を先にする。
4. 守る場所の `--ro-bind` と、塞ぐための tmpfs。
5. `gitdir:` の指す先の `--ro-bind`。
6. 読ませない場所の覆い（最後）。
7. `--chdir <作業ディレクトリ>`。理由: 作業ディレクトリが見えないと、bubblewrap は黙って `$HOME` に移る。

各要素の決まりは次のとおりとする。

**守る名前**

- 方針の `protected_names` のどの名前も、同じ規則で扱う。
- 方針の検査で、`protected_names` が、綴りどおりの `.git` と `.benitoiteh` を含むことを求める。今は、大文字と小文字を区別せずに含めばよい形なので、これを改める。

**書ける場所の根の直下**

- すでにある項目は、名前を ASCII の大文字と小文字を区別せずに守る名前と比べ、当たれば `--ro-bind` で重ねる（`.GIT` も重ねる）。
- 守る名前のうち、綴りどおりの名前の項目がまだないときは、`--perms 555 --tmpfs <場所> --remount-ro <場所>` で塞ぐ。
- まだない `.GIT` は塞がない。この結果、作れるようになる（03-02）。

**`gitdir:` の行のファイル**

根の直下の `.git` が、`gitdir:` の行のファイルのときの扱い。

- 指す先は、相対のパスなら、そのファイルのあるディレクトリから求める。
- 指す先が書ける場所の中にあれば、`--ro-bind` で重ねる。
- 読めない、形が違う、指す先がないときは、引数を作らずに失敗とする。
- worktree の `commondir`（hooks のある本体のリポジトリ）は、この作業では扱わない。扱わないことを、コメントと報告に書く。
- 入れ子の `.git` のファイル（サブモジュールなど）の指す先は辿らない。

**入れ子の守る場所**

- 書ける場所の根から 3 段（`a/b/.git` まで）を探す。
- 探すときにシンボリックリンクを辿らない。
- 名前は大文字と小文字を区別せずに比べ、当たればすでにあるものを `--ro-bind` で重ねる。
- 深さを方針の欄にするなら、次の形にする。
  - `#[serde(default)]` で既定を 3 とする。
  - 値の範囲を検査する。
  - `sandbox/tests.rs` の JSON の往復のテストに含める。

**読ませない場所**

- すでにあるディレクトリは、`--perms 000 --tmpfs <場所> --remount-ro <場所>` で覆う。
- すでにあるファイルは、権限 000 の空のファイルを `--ro-bind <そのファイル> <場所>` で重ねて覆う。
  - 空のファイルは、どの書ける場所の外にも作る（データのディレクトリか、テストの一時ディレクトリ）。
  - 排他に作り、作った後に、権限 000 の空の通常のファイルであることを確かめる。
  - 記述子を渡す `--ro-bind-data` は使わない。理由: 標準入出力のほかの記述子を子に渡さない規則（03-02）に反し、ほかのスレッドが同時に起動した子に記述子が漏れうる。
- 読ませない場所の下にある読ませない場所は、外側の覆いで見えなくなるので、引数に含めない。
- 読ませない場所の中にある書ける場所を含む方針は、誤り（`InvalidPolicy`）とする。
- 方針の検査は、今のとおり、読ませない場所がすでにあることを求めてよい。引数を作る時点で消えていたものは覆わない。

**シンボリックリンク**

- 次のパスの各要素（最後の要素を含む）を `lstat` で調べる。
  - 根の直下の守る場所。
  - 入れ子の守る場所。
  - `gitdir:` の指す先。
  - 読ませない場所。
- 書ける場所の中のシンボリックリンクがあれば、引数を作らずに失敗とする。

**補助のプロセスの実行ファイル**

- 補助のプロセスの実行ファイルのパス（実のパス）が書ける場所の中にあれば、`InvalidPolicy` とする（03-02 の「書ける場所の検査」）。

### 2. 起動の形と後始末

- Linux では、`/usr/bin/bwrap <引数...> -- <benitoiteh> __sandbox <方針の JSON> -- <プログラム> <引数...>` の形で起動する。
- `bwrap` は `/usr/bin/bwrap` の固定のパスとし、`PATH` から探さない。テストのために、パスを差し替える公開の口は作らない。
- **公開の型**
  - macOS の `SandboxCommand::to_command` は変えない。
  - Linux には、後始末を持つ型（例: 起動の前の準備を持ち、子プロセスを待つ関数が後始末も行う型）を加える。
  - その型は、テストが別のプログラム（`spawn-with-fd`）で包めるように、起動するプログラムと引数を取り出せる形にする。
  - 新しいシグネチャを報告に書く。オーケストレータが `docs/plan/10-interfaces.md` に写す。
- **後始末**
  - 子プロセス（bubblewrap）の `wait` が返った後にだけ行う。起動に失敗したときと、bubblewrap が早く失敗したときも行う。
  - 消すのは、引数を作った時点でなかった（`lstat` で確かめた）もののうち、空のディレクトリとして残ったものだけとする（`fs::remove_dir`）。
  - 動いている子プロセスがある間に消さない。理由: Linux 3.18 から、別のマウントの名前空間でマウントの場所になっているディレクトリを `rmdir` で消せ、消すとそのマウントが外れて塞ぎがなくなる。`Drop` で動いている子の分を消すことはしない。
  - 並んで動く子プロセスどうしの競合（一方の後始末が他方の塞ぎを外す）と、強制終了で残ったものの扱い（BH-095）は、この作業では作らない。このことをコメントと報告に書く。
  - 親がプロセスグループを終わらせた後、中の名前空間が `--die-with-parent` で終わるまでの短い間がある。このことを報告に書く。
- `--die-with-parent` は、子を起動したスレッドが終わると働く。起動したスレッドが子より先に終わる使い方をしないことを、コメントに書く。

### 3. 補助のプロセス（`run_helper`）

手順は、03-02 の 1〜6 のとおりとする。補助のプロセスは名前空間を作らない。

Landlock の規則を、次のとおり改める。

- **書ける場所**: `AccessFs::from_write(ABI::V3)` を与える（作成、削除、名前の付け替えの `Refer`、`Truncate` を含み、`Execute` を含まない）。`AccessFs::from_all` は使わない。P0-05 の「すでにあるファイルの更新だけ」の規則（`grant_existing_files`）は除く。
- **読み取り**: 読める範囲（`ReadAccess`）の根に、`ReadFile | ReadDir` を与える。読ませない場所は bubblewrap で覆うので、読み取りの規則から部分木に分ける形（`grant_tree` を読み取りに使う部分）は除く。
- **実行**: 今のとおりとする。読み取りの規則に `Execute` を含めない。`ProgramAccess::Unrestricted` で `deny_exec_in_writable` のときは、書ける場所を除いた部分木に `Execute` を与える。この処理には、今の `grant_tree` を使い続ける。
- **辿る途中で消えた項目**: `grant_tree` で木を辿る途中に消えた項目（`read_dir` の後の `ENOENT`）は、権利を与えずに飛ばす。理由: 2026-10-17 に、x86_64 の機械で、`/tmp` の下の別のテストの一時ディレクトリが辿る途中で消え、補助のプロセスが `Sandbox setup failed at Landlock: No such file or directory` で失敗した（`reading_excludes_secrets_and_confines_readable_roots`）。権利を与えないので、制限が弱まる方向には働かない。

seccomp のフィルタは、今のまま使う。

### 4. 使えるかの確かめ

Linux でサンドボックスを掛けられるかを判定する関数を置く。判定の仕方は次のとおりとする。

- 補助のプロセスを、実際の方針の形で一度起動する。
  - 書ける場所は一時ディレクトリだけとし、`ProgramAccess::Unrestricted` とする。
  - 目的のプログラムは、補助のプロセスの実行ファイル自身の、副作用のない起動（`--version` など）とする。
  - 終わったら、一時ディレクトリと塞ぐためのディレクトリを片付ける。
- 結果は、項目ごとに「使える」「使えない（理由）」「確かめていない」を返す。項目は次の 4 つである。
  - `/usr/bin/bwrap` があるか。
  - 特権を持たない利用者の名前空間を作れるか。
  - Landlock の ABI の版 3 を使えるか。
  - seccomp を使えるか。
- 失敗の分け方は次のとおりとする。
  - 起動の `ENOENT` は、bubblewrap がない。
  - 終了状態が 125 でなく、標準エラー出力が `bwrap:` で始まるときは、名前空間を作れない。
  - 終了状態が 125 で、段階が Landlock か seccomp のときは、その項目が使えない。
  - 失敗した段階より後の項目は、「確かめていない」とする。
- シグネチャは任せる。05-01 の `doctor` が使う。

## テスト

`tests/sandbox_linux.rs` を、07-01 の「安全の性質のテスト」の Linux の項目に合わせて改める。

**残すテスト**

P0-05 のテストのうち、新しい形でも成り立つものは残す。

- 実行の権利。
- 動的リンクのローダ。
- 外部の Unix IPC。
- IP の通信。
- 補助のプロセスの各段階の失敗。

**期待が変わるテスト**

次のものは、新しい期待に改める。どのテストのどの期待を改めたかを、報告に書く。

- 書ける場所に新しいファイルを作れないこと → 作れる。
- 読ませない場所の祖先のディレクトリの一覧を読めないこと → 読める。
- 根の直下のまだない `.GIT` を作れないこと → 作れる。03-02 を示すコメントを付ける。

**`sandbox-probe` の終了状態**

- `sandbox-probe` は、`EPERM` と `EACCES` のときだけ 10 を返す。`EROFS`・`EBUSY`・`EEXIST`・`EISDIR` は 11 になる。
- 守る場所のテストでは、終了状態の値か、`sandbox-probe` が示す誤りの種類で確かめる。
- いつも、サンドボックスの外から見たファイルの状態も確かめる。

**加えるテスト**

- 書ける場所に、新しいファイルとディレクトリを作れ、消せ、一時のファイルから名前を付け替えて書けること。入れ子のディレクトリの中でも同じであること。
- 書ける場所の根の直下の `.git` と `.benitoiteh` について、作れず、書けず、付け替えて作り直せないこと。次の場合を確かめる。
  - すでにあるディレクトリのとき。
  - `gitdir:` のファイルのとき（指す先も含めて）。
  - まだないとき。ディレクトリとしても、ファイルとしても作れないこと。
  - ほかの名前のディレクトリを `.git` に付け替えるとき。
  - すでにある `.GIT` のとき。
- すでにある入れ子の `a/.git`・`a/b/.git`（`.GIT` の綴りを含む）に書けず、付け替えられないこと。
- 3 段より深いもの（`a/b/c/.git` から先）と、まだない入れ子のものは、守らないこと。期待をその結果に合わせ、保証の範囲の外であることをコメントに書く。
- 読ませない場所のディレクトリとファイルの、内容も一覧も読めないこと。
- サンドボックスの中から、守る場所と読ませない場所のマウントを外せず、上に重ねられないこと。
  - `sandbox-probe` に、`umount` と、bind mount の操作を足す（`rustix::mount::unmount`・`mount_bind`。どちらも安全な関数で、Linux だけで作る）。
  - 期待は `EPERM`（Landlock か、特権のなさによる）。
- 子プロセスが終わった後に、塞ぐために作らせた空のディレクトリが残らないこと。起動の前からあった空の `.git` のディレクトリは消さないこと。
- 次の方針で、起動せずに失敗すること。
  - 書ける場所の中のシンボリックリンクを経て、守る場所か読ませない場所を指す方針。対象は、`/w/.git` がリンクのとき、入れ子の `/w/a/.git` がリンクのとき、`gitdir:` の指す先がリンクを経るとき。
  - 補助のプロセスの実行ファイルが書ける場所の中にある方針。
- 使えるかの確かめが、この機械で「使える」を返すこと。
  - `/usr/bin/bwrap` のない環境は、テストの中で作れない。分岐は、判定の関数の分け方のユニットテストで確かめる。
- 引数を作る部分のユニットテスト: 方針ごとの引数の並びを、期待の並びと比べる。
  - aarch64 の `container` の中でも、ユニットテスト（`--lib`）は走る。`/usr/bin/bwrap` と Landlock がなくても通る形にする。

## テストの環境

Linux のテストは、オーケストレータが、設計者の常設の x86_64 の機械の podman で走らせる（00-common の「検査」）。2026-10-17 に、オーケストレータが次のことを済ませた。Codex は `scripts/` を変えない。

- `scripts/remote-linux-run.sh` を、次の形にして `main` に取り込んだ。
  - イメージは、`alpine:3.22` に bubblewrap 0.12.0 を入れた `localhost/benitoiteh-test:alpine-3.22-bwrap`。
  - root でない利用者（`--userns=keep-id`）で走らせる。
  - `--security-opt unmask=ALL` を付ける。付けないと、bubblewrap が `/proc` をマウントできない。
- その中で、root でない利用者が、上の「全体の指定」と `--perms 555 --tmpfs /w/.git --remount-ro /w/.git` を渡して試した。
  - 中のプロセスは、`/w` に新しいファイルを作れた。
  - `/w/.git` の中に作ると `Read-only file system` になった。
  - 付け替えと削除は `Resource busy`、`umount` は `Operation not permitted` になった。
  - 外から見ると、`/w/.git` に空のディレクトリが残った。

aarch64 の `container` の中では、今のとおり `sandbox_linux` を走らせない。
