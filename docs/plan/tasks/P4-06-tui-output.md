# P4-06 対話の画面の土台と出力

## 目的

対話の画面（`benitoiteh [オプション] [依頼]`）の土台を作る（設計書 05-02 の「画面の構成」「出力の示し方」）。端末の履歴に出力を流し、画面の下の入力欄と状態の行だけを描き直すインラインの形とする。この作業では、依頼を送って結果を示すところまでを作る。操縦と後続、ESC の取り消し、入力の履歴の保存、確認の画面は P4-07、`/` で始まるコマンドは P4-08 で作る。

## この作業が認める型の変更と依存

- `crossterm`（`=0.29.0`）と `unicode-width`（`=0.2.2`）を、開発用から本体の依存に移す。機能は要るものだけにする。実行ファイルの大きさの変化を測り、完了の報告に書く（AGENTS.md の「実装の規約」）。
- `AgentEvent::ToolResult` に、画面に示す差分などの文（`ToolOutput.display`）を `display: Option<String>` で加える。

## 作るもの

### 1. 起動

- 引数に `exec`・`doctor`・`sessions` のどれもないときを対話の形とし、`cli/text.rs` の「Interactive mode ... not available yet」の文から対話の形を除く。最後の位置の引数があれば、最初の依頼として送る。
- 標準入力か標準出力が端末でなければ、対話の形を起動せずに、`exec` を使うよう示して終了状態 2（使い方の誤り）で終える。
- 起動の準備は `exec` と共有する（`cli/exec.rs` の `prepare` を、対話と非対話の両方から呼べる形に分ける）。対話の既定の承認の方針は `on-request` とするが、確認の画面は P4-07 で作るので、この作業では `on-request` を選んでも確認に答える者がいない。この作業の間は、承認の方針を `never` として動かし、起動のときに、確認が要る操作は拒否されることを一行で示す（英文は `text` に置き、P4-07 で除く）。
- 端末を raw のモードにし、bracketed paste を有効にする。終わるとき（正常、誤り、panic、`SIGTERM`・`SIGHUP`）に、必ず元に戻す（`cli/panic.rs` と `cli/signals.rs` を使う）。代替の画面（alternate screen）は使わない。

### 2. 画面の構成

- 画面の下に、入力欄（複数行）と状態の行を置き、この部分だけを描き直す。描き直しは、端末の同期した出力（`crossterm` の `BeginSynchronizedUpdate`・`EndSynchronizedUpdate`。CSI ? 2026）で囲む。
- 出力は、下の部分を消してから、端末の履歴に書き足し、下の部分を描き直す。一度履歴に書いた行は書き直さない。
- 入力欄は、表示の幅（`unicode-width`）で折り返し、端末の高さの半分を超える行数は、カーソルの周りだけを示す。
- 状態の行: モード、提供者とモデル、文脈の大きさの見積もりと上限の比（上限の設定がなければ見積もりだけ）、サンドボックスの方針、実行中なら経過の時間（1 秒ごとに描き直す）。文脈の見積もりは `Agent` から得る口を加える（P4-01 の見積もりを使う）。
- 端末の大きさが変わったら（`crossterm` の `Resize`）、下の部分を描き直す。

### 3. 出力の示し方

- 画面の描画は、状態から書く内容（文字列と装飾の指定）を作る純関数と、端末に書く部分に分ける。純関数をユニットテストで確かめる。
- 信頼しない文字列（LLM の文、道具の結果と要約、ファイルの名前と中身、子プロセスの出力、診断、ウェブのページ）は、端末に書く前に `terminal_text` で制御の文字を目に見える形に変える。装飾の制御の列は、変えた後の文字列に、`benitoiteh` が作ったものだけを加える（05-02 の「出力の示し方」）。
- LLM の応答の文: 届いた順に示す。改行で終わった行は履歴に書き、終わっていない行は下の部分の上に仮に示す。Markdown は、見出し、箇条書き、強調（`**`・`*`・`` ` ``）、コードのブロックだけを装飾に変え、ほかはそのまま示す（行ごとの変換で、ストリーミングに合う形にする）。
- 推論の文: 要約だけを薄い色で示す（BH-015）。`ReasoningDelta` を受け取ったら、最初の数行（例: 3 行）だけを示し、残りは示さない。
- 道具の呼び出し: 一行の要約（`read src/main.bnt (1-120)`、`bash: cargo test` など）と、結果の一行の要約（行数、終了状態、誤りの有無）で示す。`write`・`edit` の差分（`display`）は、unified diff の形で、追加を緑、削除を赤で示す。
- 誤り、取り消し、文脈の超過、圧縮、やり直しのイベントは、それぞれ一行で示す（誤りと取り消しは目立つ色）。
- セッションの初めに、提供者とモデル、要求を送るホスト、送る内容（01-04 の「送る内容の表示」）、読んだプロジェクトの指示のファイル、サンドボックスの方針を示す（`SessionStart` のイベントの内容）。

### 4. 入力（この作業の範囲）

- Enter: 一連の処理の途中でなければ、入力欄の文を依頼として送る。途中なら、P4-07 まで受け付けない（入力欄に残す）。空の入力は送らない。
- Shift+Enter（端末が区別して送るとき）と Ctrl+J: 入力欄の中で改行する。
- 文字の入力、左右の移動、Backspace、Delete、Home・End、貼り付け（bracketed paste の文を一度に入れる。貼り付けの中の改行は改行として入れる）。
- ↑・↓: 入力欄が一行のとき、このセッションの前の入力を辿る（保存は P4-07）。
- Ctrl+C: 入力欄が空でなければ空にする。空なら、続けて二度押すと終える（一度目で「もう一度押すと終える」を状態の行に示す）。一連の処理の途中の Ctrl+C は、P4-07 までは取り消しの印を立てる。
- Ctrl+D: 入力欄が空なら終える。

### 5. ループとの接続

- `Agent` を別のスレッドで動かし、画面のスレッドは、端末の入力のイベントと `AgentEvent` の受け取りを待つ。依頼ごとに `Agent::run` を呼び、結果（`RunReport`）を画面のスレッドに返す。
- `Agent` は `ui` を知らない（06-01 の依存の向き）。

## テスト

- 描画の純関数: 入力欄の折り返し（全角の文字を含む）、状態の行、Markdown の変換（見出し、箇条書き、強調、コードのブロック）、差分の色、道具の要約。
- 安全の性質（07-01）: 信頼しない文字列（ESC の列、`\x9b`、`\u{202e}`、画面の消去の列）を含む応答の文、道具の結果、ファイルの名前、差分を、端末に書く内容に変えたとき、`benitoiteh` が作った装飾の列のほかに制御の文字が残らない。
- 推論の文が最初の数行だけ示される。
- 入力の操作の状態の遷移（文字の入力、改行、貼り付け、Ctrl+C の二度押し、↑・↓）を、端末なしで、イベントの列から状態を作る形で確かめる。
- 標準入力が端末でないとき、対話の形を起動せずに終了状態 2 で終える（`tests/cli.rs` の形）。
- 模擬の提供者で、端末の代わりの書き先（`Vec<u8>`）に描画させ、依頼から結果までの出力に、応答の文と道具の要約が入る（端末を要さない形で、画面の部分を組み立てられるようにする）。
