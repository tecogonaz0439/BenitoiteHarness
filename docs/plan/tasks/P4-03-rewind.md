# P4-03 巻き戻しの記録と戻す処理

## 目的

プロジェクトのディレクトリの状態を時点ごとに記録し、選んだ時点に戻す仕組みを作る（設計書 01-05 の「巻き戻し」）。時点を選ぶ画面（`/rewind`）は P4-08 で作る。この作業では、記録と戻す処理を `Agent` の口として作り、模擬の提供者と一時のディレクトリで確かめる。戻す口は LLM の道具に出さない。

あわせて、シンボリックリンクを一切辿らずにディレクトリを辿る口を `safe_fs` に作る。今の `glob`・`grep` が使う `ignore::WalkBuilder` は、`.gitignore` を、リンクを辿り、待たない形を使わずに開くので、`.gitignore` を `/dev/zero` へのリンクや名前付きのパイプにされると主のプロセスが止まる。巻き戻しはこの辿り方を使わない（`glob`・`grep` を移すのは P4-09）。

## この作業が認める型の変更

- `safe_fs` に、リンクを一切辿らない口を加える（3）。
- `Record::Checkpoint` を加え、`Record::Rewind` の読み方を改める（`replay` で会話を切り詰める）。
- `AgentEvent` に、時点の記録とハードリンクの一覧のイベントを加える。
- `ToolContext` に、時点を記録する口と、読んだ版の記録を消す口を加える。
- P4-02 の `ResumeState` の推論の区間を、`Rewind` の行で一緒に切り詰める形に改める。

## 作るもの

### 1. 時点を記録する時機と書き方

- 時点を記録するのは、依頼を受けたとき（その依頼を会話に加える前）、`bash` の実行の直前、`write`・`edit` が書く直前、戻す操作の前（`before_rewind`）とする（01-05）。
  - `write`・`edit` では、確認が要らないこと（`approval()` が `None`）、読んでから直す規則の検査、`edit` の置き換えの計算がすべて済んだ後、`target.write` の直前に記録する。プロジェクトの外に書くときは記録しない。
  - `bash` では、確認の後、`run::run` の直前に記録する。
  - 道具は確認の前と後に二度呼ばれる（`execution.rs` の未確認の呼び出しと確認済みの呼び出し）。実際に実行する側の呼び出しでだけ記録する。
  - 辿っている途中で取り消しの印が立ったら、道具を実行しない。
  - 時点の記録が失敗しても（読めないファイルなど）、道具の実行は止めない。不完全な時点として記録し、イベントで示す。
- 口の形: 時点を記録する口（例: `CheckpointRecorder`）は、記録の書き手を共有して持ち、時点の行（`Record::Checkpoint`）を、道具が実行する前に書く（道具から戻った後に書く形にしない。異常に終わったときに行が失われるため）。口は `Agent::new`（と P4-02 の `Agent::resume`）で作り、`ToolContext` に取り付ける。
- 時点の ID は `cp-<連番>` とし、連番は記録の最大の続きから数える（再開でも重ならない）。読むときは形を正規表現で確かめ、渡された ID をそのままパスにつながない。
- `Record::Checkpoint` の欄: `id`、`reason`（`request`・`bash`・`write`・`edit`・`before_rewind`）、`turn`、`call_id`（道具の前のとき）、`created_at`、`items`（依頼の時点だけ。その依頼を加える前の会話の項目の数）、`generation`（圧縮と会話の巻き戻しのたびに 1 増やす世代の番号）、`manifest`（一覧の SHA-256）、`incomplete`（理由の一覧。読めなかったもの、項目の数か時間の上限、8 MiB と 256 MiB の上限、書ける量）。時点の一覧の画面は、この行だけから作る（一覧のファイルを走査しない）。

### 2. 辿り方と一覧

- 辿る処理は、3 の口で自前に書く（`ignore::WalkBuilder` を使わない）。プロジェクトのディレクトリの記述子から始め、各ディレクトリを一要素ずつ `O_NOFOLLOW|O_DIRECTORY|O_NONBLOCK` で開き、項目の種類と大きさと時刻は、持っているディレクトリの記述子から `fstatat(.., AT_SYMLINK_NOFOLLOW)` で調べる。
- `.gitignore`: 各ディレクトリの `.gitignore` を 3 の口で、待たない形で開き、通常のファイルで 1 MiB 以下のものだけを読み、`GitignoreBuilder::add_line` で組み立てる。リンク、名前付きのパイプ、大きすぎるものは使わず、不完全の理由に記録する。`.ignore` は使わない。
- 除く範囲（01-05）: `.gitignore` の規則に当たるもの、守る場所（`.git` と `.benitoiteh`。どの深さでも、ASCII の大文字と小文字を区別せずに、ファイルでもディレクトリでも。理由は `protected`）、`ExcludeRules` に当たるもの、8 MiB を超える通常のファイル、通常のファイル・ディレクトリ・シンボリックリンクのほかの種類。除いたディレクトリは、中を辿らずに一項目で記録する。
- 上限: 一つの時点で辿る項目は 20 万まで、時間は 10 秒までとし、超えたら打ち切って不完全とする。保存する中身の合計が 256 MiB を超えたら、それ以上の中身は保存しないが、名前と大きさと種類は一覧に記録し続ける（そのパスがあったことが分かるように）。上限の値は公開の `CheckpointLimits` にまとめ、既定値を持たせる（テストで小さくする）。
- 一覧の項目: パス（UTF-8 でなければ `path_hex` の 16 進）、種類、通常のファイルでは SHA-256 と大きさと実行の権限、シンボリックリンクではリンクの先（UTF-8 でなければ 16 進）、`dev`・`ino`・`mtime`（ナノ秒まで）・`ctime`（ナノ秒まで）・`nlink`、除いた理由、読めなかった誤り。一覧の先頭に、形式の版、プロジェクトのディレクトリの実のパス、辿り始めた時刻 T（秒とナノ秒）、完全かどうかを書く。項目はパスのバイト列の順に並べる。
- 中身を読み直さない条件: 前の時点の一覧の項目と、大きさ、`mtime`、`ctime`、`ino`、`dev` がすべて同じで、`mtime` と `ctime` の秒が前の時点の T の秒より前で、前の時点でその中身が実際に `objects/` に保存されているときだけ、前の値を使う。それ以外（T 以上の時刻、未来の時刻を含む）は読み直す。読むときは、読む前と後に開いた記述子で `fstat` し、変わっていれば、その値を次の時点で使わせない印を付ける。
- 中身と一覧の保存: `objects/<SHA-256 の 16 進>` に、session の側で（`session/mod.rs` と同じく rustix で）0600 で、一時の名前で書いてから付け替える。すでにあれば書かない。一覧も同じく SHA-256 を名前として `objects/` に置き、直前の時点と同じ一覧なら重ねて書かない。`objects/` への書き込みは P4-02 の書ける量（`Session::reserve`）に数え、超えたら保存せずに不完全とする。`objects/` のディレクトリは 0700 で作る。
- ハードリンクの一覧: `nlink` が 2 以上の通常のファイルを、示したパスの集合と比べ、新しく見つけたものだけをイベント（例: `AgentEvent::HardLinks { paths }`）で示す。

### 3. `safe_fs` の口

- リンクを一切辿らない解決の口を加える。Linux は `openat2` の `RESOLVE_NO_SYMLINKS|RESOLVE_BENEATH`、macOS は `O_NOFOLLOW_ANY`（値は SDK の `sys/fcntl.h` で確かめる）とする。知らない印を黙って無視する OS の版に備え、起動のときの自己の確かめ（`self_check` の形）で、範囲の中のリンクを辿る開き方が拒まれることを確かめる。
- この口で、辿る、読む、書き戻す、消す、ディレクトリを作る、リンクを作る、親を開く、のすべてを行う。
- 書き戻しの口（例: `write_from_with_mode`）: 一時の名前で書いてから付け替え、権限は 0o755 か 0o644 だけを許す（setuid などは付けない）。権限だけを `fchmod` で変えることはしない（ハードリンクの先の外のファイルの権限が変わるため）。リンクの数が 2 以上のファイルは書き換えない（今の `O_UNIQUE` と同じ）。
- 消す口: `unlinkat` と、空のディレクトリを消す `unlinkat(AT_REMOVEDIR)`。消す前に `fstatat(AT_SYMLINK_NOFOLLOW)` で種類を確かめ直す。

### 4. 時点の一覧を示す

- `Agent` に、時点の一覧を返す口を加える（ID、理由、番、時刻、会話を戻せるか、不完全か）。会話を戻せるのは、理由が `request` で、時点の世代が今の世代と同じものだけとする（その後に圧縮か、その時点より前まで会話を戻したことがあれば戻せない）。

### 5. 戻す

- `Agent` に、時点と範囲（「ファイルと会話」「ファイルだけ」「会話だけ」）と、不完全な `before_rewind` でも続けるか（`allow_incomplete`。P4-08 で利用者に確かめる）を受けて戻す口を加える（例: `pub fn rewind(&mut self, checkpoint: &str, scope: RewindScope, allow_incomplete: bool, events) -> Result<RewindReport, AgentError>`）。一連の処理の途中では呼べない。
- ファイルを戻すときは、戻す前に `before_rewind` の時点を記録する。その時点が不完全なら、`allow_incomplete` が偽のとき誤りにして戻さない。
- 一覧と中身は信頼しない（01-05 の「書き戻しの仕方」）。
  - 一覧のファイルを `objects/` から、NOFOLLOW で、通常のファイルでリンクの数が 1 で、大きさの上限（例: 256 MiB）以下であることを確かめて読み、SHA-256 が名前と合うことを確かめる。
  - 一覧のプロジェクトが今のプロジェクトのディレクトリと違えば、ファイルを戻さない。
  - 一覧のパスを `ScopeRelPath` に変え、絶対のパス、`..`、空の要素、NUL、守る場所の名前（大文字と小文字を区別せず）を含むものを拒む。
  - 中身は、`objects/` のファイルを同じ確かめで開き、一時の名前に写しながら SHA-256 を計算し、名前と違えば付け替えずに戻せなかったものとする。
- 消してよいのは、次をすべて満たすパスだけとする: `before_rewind` の一覧に、除いていない項目として載っている。選んだ時点の一覧にない。選んだ時点で、そのパスに最も近い、あった祖先のディレクトリを最後まで列挙できていた（読めなかったことがない）。祖先がどれも除かれていない。選んだ時点が完全である。「今の規則で除く」は、`before_rewind` を辿ったときの除外の判定と同じ関数で決める。満たさないものは消さず、戻せなかったものとして示す。
- 手順: まず消す操作を深い方から行い（増えたファイルとリンク、種類が変わったパスの今のもの、中が空になった増えたディレクトリ）、次にディレクトリを作る操作、ファイルの書き戻し、リンクの作り直し（`unlinkat` の後に `symlinkat`）を浅い方から行う。各操作の前に、今の種類を確かめ直し、`before_rewind` を辿った後に変わっていれば、その操作をやめて戻せなかったものとする。今ハードリンクの数が 2 以上のファイルは書き戻さず、戻せなかったものとする。除いたディレクトリは消さない。
- `RewindReport`: 書き戻した数、消した数、作った数、戻せなかったもの（パスと理由）、戻せないもの（選んだ時点より後の、理由が `bash` の時点の行の `call_id` と道具の要約。選んだ時点が `bash` の前の時点なら、その `bash` も入れる。プロジェクトの外に書いた `write`・`edit` と、除いたパスへの書き込みも入れる）。利用者が拒否したコマンドは入らない（時点の行は実行する直前にだけ書くため）。
- 会話を戻すとき: 4 の条件を満たす時点だけを受け付ける。会話を時点の `items` に切り詰め、記録に `Record::Rewind { items, checkpoint }` を書き、世代を 1 増やす。`previous_last_item`、最後の使用量、足したバイトの数、報告された入力の最大、同じ呼び出しの繰り返しの検出の状態を初期の値に戻す。項目の数が 0 になったら、次の依頼で環境の情報を送り直す（`started` を戻す）。番の番号と呼び出しの ID は戻さない（`spill/` のファイルの名前が重ならないように）。
- `replay` を、`Record::Rewind` で会話を切り詰める形に改める。P4-02 の推論の区間も一緒に切り詰め、メモリの会話と `replay` の結果が一致するようにする。
- ファイルを戻したパスの、読んだ版の記録を消す（次の `edit` の前に読み直させる）。読んだファイルと変えたファイルの集合（P4-01）は変えない。

## テスト

一時のディレクトリの中のリンク、名前付きのパイプ、ハードリンクで状態を作る。上限は `CheckpointLimits` で、書ける量は P4-02 の口で小さくする。中身を読み直さないことは、公開の `CheckpointStats`（`files_hashed`、`bytes_read`、`objects_written`）で確かめる。

- 時点の記録: 依頼のたび、`bash` の実行の直前、`write`・`edit` が書く直前に時点が記録される。確認を拒否した `bash` と、検査で失敗した `edit` では記録されない。`objects/` に同じ中身と同じ一覧が一度だけ保存される。変わっていないファイルは読み直されない。前の時点と同じ秒に変えたファイルは読み直される。上限で保存しなかった中身の値を、次の時点が使わない。
- 除く範囲: `.gitignore` の規則、`.git`・`.GIT`・`sub/.benitoiteh`、読まないファイル、8 MiB を超えるファイルが除かれ、理由が記録される。項目の数の上限と 256 MiB の上限で、不完全になる。
- 止まらないこと（安全の性質のテスト。07-01）: `.gitignore` を `/dev/zero` へのリンクにしたときと、名前付きのパイプにしたときに、時点の記録が止まらない（見張りのスレッドで時間を区切る）。
- リンクを辿らないこと（安全の性質のテスト）: `notes.txt -> .env` と `dir -> ../outside` のリンクの先の中身が `objects/` に入らない。宛先のないリンクと外を指すリンクを、リンクとして記録して戻す。
- 戻す: 変えたファイル、消したファイル、増えたファイル、実行の権限だけの違い（setuid は付かない）、シンボリックリンク、ディレクトリ、ファイル・ディレクトリ・リンクの間で種類が変わったパスが、選んだ時点のとおりに戻る。戻す前の時点に戻すと、戻したことが戻る。
- 消してよいファイルの規則: 選んだ時点で 8 MiB を超えて除いたファイルが、その後に小さくなっても消されない。今の規則で除くパスも消されない。不完全な時点に戻すときは何も消さない。`before_rewind` が不完全なら、`allow_incomplete` が偽のとき戻さない。
- 安全の性質（07-01）:
  - 書き換えた一覧（`../x`、絶対のパス、`.git/config`、`.GIT/x`）と、書き換えた `objects/` のファイル（ハッシュが合わないもの）で、プロジェクトの外も守る場所も変わらない。
  - 今ハードリンクの数が 2 以上のファイルは「戻せなかった」になり、外の名前の中身が変わらない。
  - 途中の要素をシンボリックリンクに差し替えたディレクトリ（差し替えた状態を先に作っておく）の下に書き戻さず、消さない。
- macOS で大文字と小文字だけを変えた名前の変更（`Foo.txt` から `foo.txt`）を戻しても、書き戻したファイルが消えない（`cfg(target_os = "macos")`）。UTF-8 でない名前を記録して戻す（`cfg(target_os = "linux")`）。
- ハードリンクの数が 2 以上のファイルの一覧のイベントが、新しく見つけたものだけで出る。
- 会話を戻す: 会話が依頼の時点の項目の数に切り詰められ、`Record::Rewind` が書かれる。道具の前の時点と、圧縮の後の古い時点は、会話を戻せない。戻して、続けて依頼し、再開した後に、`replay` の結果がメモリの会話と一致する（P4-02 の推論の区間を含む）。項目の数 0 に戻した後、環境の情報を送り直す。戻した後も呼び出しの ID が重ならない。
- 戻せないものの一覧に、選んだ時点の後の `bash` が入り、拒否した `bash` は入らない。
- サンドボックスの中（`tests/sandbox_rewind.rs`。オーケストレータが手元で走らせる）: サンドボックスの中の子は、`objects/` とセッションのディレクトリに書けない。Linux の `RESOLVE_NO_SYMLINKS` が働く。

## 完了条件

- `scripts/check.sh --inside-codex` が通る。
- 完了の報告に、一覧の JSON の例、`Record::Checkpoint` と `RewindReport` の形、加えた公開の関数と型のシグネチャを書く。
- 時点の記録の時間と大きさを測って書く: 1,000・1 万・10 万のファイルで、初回、2 回目（変化なし）、1 ファイルだけ変えたとき。多くのファイルを持つ、`.gitignore` で除いた `target/` を置き、中を辿らないこと。一つの時点の一覧の大きさと、100 個の時点の累計。手元の macOS で測り、Linux はオーケストレータが測る。
