# P4-03 巻き戻しの記録と戻す処理

## 目的

プロジェクトのディレクトリの状態を時点ごとに記録し、選んだ時点に戻す仕組みを作る（設計書 01-05 の「巻き戻し」）。時点を選ぶ画面（`/rewind`）は P4-08 で作る。この作業では、記録と戻す処理を `Agent` の口として作り、模擬の提供者と一時のディレクトリで確かめる。

- [道具](../../design/01-agent/01-03-tools.md)の「書く道具のパスの規則」「道具の定義の共通の規則」「読まないファイル」「bash（通常モード）」

## 作るもの

### 1. 時点を記録する

- 時点を記録するのは、依頼を受けたとき（一連の処理の前）、通常モードの `bash` の実行の前、`write`・`edit` が書く前（どれも確認を受けた後、実行の直前）、戻す操作の前（3）とする（01-05 の「巻き戻し」。2026-10-17 に BH-017 で決めた）。制限モードの `benitoite_run`・`benitoite_test`・`benitoite_scratch` はまだないので、道具が呼べる口（例: `ToolContext` から呼ぶ `CheckpointHook`）として作り、`bash`・`write`・`edit` がそれを使う。`write`・`edit` が引数の検査や読んでから直す規則で失敗するときは、時点を記録しない（書く直前にだけ記録する）。
- 時点の記録が失敗しても（読めないファイルなど）、道具の実行は止めない。失敗したことを時点の一覧とイベントに記録する。
- プロジェクトのディレクトリの下を、シンボリックリンクを辿らずに辿る（`ignore::WalkBuilder` を `follow_links(false)`、`hidden(false)`、`.gitignore` の規則を使う設定で）。各項目の種類（通常のファイル、ディレクトリ、シンボリックリンク）を記録し、通常のファイルでは中身の SHA-256 の値と実行の権限、シンボリックリンクではリンクの先の文字列を記録する。ほかの種類（名前付きのパイプなど）は除いて、除いた理由を記録する。
- 中身は、セッションのディレクトリの `objects/<SHA-256 の 16 進>` に一度だけ保存する（すでにあれば書かない）。保存は、一時の名前で書いてから名前を付け替える。`objects/` への書き込みは、P4-02 の書ける量に数え、超えたら、それ以上を保存せず、その時点に「上限で記録しなかった」ことを記録する。
- 前の時点から、大きさ、更新の時刻、変更の時刻（ctime）、inode が変わっていない通常のファイルは、中身を読み直さずに前の値を使う。ただし、更新の時刻が前の時点を記録した時刻と同じ秒のファイルは読み直す（01-05 の「巻き戻し」）。
- 除く範囲: `.gitignore` の規則に当たるもの、`.git/` の中、読まないファイルの規則（`ExcludeRules`）に当たるもの、8 MiB を超える通常のファイル。一つの時点で保存する中身の合計が 256 MiB を超えたら、それ以上を保存しない。除いたパスと理由、合計の上限で記録しなかったことを、時点の一覧に記録する。
- ファイルを開くときは、範囲の根から相対に、リンクを辿らずに開く（`safe_fs`）。開いた後に通常のファイルでなければ除く。
- ハードリンクの数が 2 以上の通常のファイルを見つけたら、時点の記録の後に一覧をイベント（例: `AgentEvent::HardLinks { paths }`）で示す。同じ一覧は一つのセッションで一度だけ示す。
- 時点の一覧（マニフェスト）は、セッションのディレクトリの `checkpoints/<時点の ID>.json` に置き、記録のファイルには時点を記録したことを一行書く（`Record::Checkpoint { id, reason, turn, items }`。`items` はその時点の会話の項目の数）。時点の ID は記録の中で一意で、時刻の順に並ぶ形とする。理由: 一覧は大きくなりうるので、記録の行に入れない。

### 2. 時点の一覧を示す

- `Agent` に、時点の一覧（ID、理由、番、会話の項目の数、時刻、記録しなかったことがあるか）を返す口を加える（P4-08 の `/rewind` が選択肢に使う）。

### 3. 戻す

- `Agent` に、時点と範囲（「ファイルと会話」「ファイルだけ」「会話だけ」）を受けて戻す口を加える（例: `pub fn rewind(&mut self, checkpoint: &str, scope: RewindScope, events) -> Result<RewindReport, AgentError>`）。一連の処理の途中では呼べない（`Agent` が処理中でないときだけ呼ばれる口とする）。
- ファイルを戻すときは、戻す前に、今の状態を新しい時点（理由 `before_rewind`）として記録する。その時点に戻せば、戻したことを戻せる。
- 選んだ時点の一覧に合わせて、次のように戻す。
  - 中身か実行の権限が違う通常のファイルを書き戻す。書き戻しは書く道具と同じパスの規則で、範囲の根から相対に、リンクを辿らずに、一時の名前で書いてから付け替える。途中の要素がシンボリックリンクなら書かない。
  - なくなったディレクトリを作る。
  - シンボリックリンクは、リンクとして作り直す（リンクの先は辿らない）。
  - 増えたファイルとシンボリックリンクを消す。消してよいのは、選んだ時点でそのパスが辿った範囲にあり、ファイルがなかったと一覧で確かめられるものだけとする。選んだ時点で除いたパス、今の規則で除くパス、合計の上限で記録しなかった時点のパスは消さず、戻せなかったものとして示す。
  - 増えたディレクトリは、中が空になったときだけ消す。
  - 守る場所（`.git`・`.benitoiteh`）の中には書かない（辿る範囲から除かれているので、一覧に現れない）。
- 戻せないものの一覧: 選んだ時点から今までに行った実行（`bash`、P2 の処理系の実行、`web_fetch`）を記録から集めて、`RewindReport` に入れる。画面への示し方は P4-08 で作る。
- 会話を戻すときは、会話を選んだ時点の項目の数に切り詰め、記録のファイルに `Record::Rewind { items, checkpoint }` を書く（書いた行は消さない）。圧縮の後の時点を選んだときに、圧縮の前の項目の数を指さないよう、時点の項目の数は、その時点の会話（最後の圧縮の後）の数とし、圧縮をまたいで戻すことはできない（圧縮の前の時点は、会話を戻す選択肢に出さず、「ファイルだけ」に限る）。
- `replay` を、`Record::Rewind` で会話を切り詰める形に改める（今は無視している）。
- 読んだファイルの版の記録は、ファイルを戻したパスについて消す（次の `edit` の前に読み直させる）。読んだファイルと変えたファイルの集合（P4-01）は変えない。

### 4. 記録の残し方

- `objects/` と `checkpoints/` は、セッションのディレクトリの権限（0700、ファイルは 0600）で作る。セッションのディレクトリと一緒に、期間を過ぎたら消える（P4-02）。

## テスト

- 時点の記録: 依頼のたび、`bash` の起動の前、`write`・`edit` が書く前に時点が記録され（検査で失敗した `edit` では記録されない）、`objects/` に同じ中身が一度だけ保存される。変わっていないファイルは読み直されない（中身を読んだ回数を数える内部の差し替えか、時点の記録の中の印で確かめる）。記録と同じ秒に変えたファイルは読み直される。
- 除く範囲: `.gitignore` の規則に当たるもの、`.git/` の中、読まないファイル、8 MiB を超えるファイルが除かれ、理由が記録される。合計の上限で止まったことが記録される。
- 戻す: 変えたファイル、消したファイル、増えたファイル、実行の権限、シンボリックリンク、ディレクトリが、選んだ時点のとおりに戻る。戻す前の時点に戻すと、戻したことが戻る。
- 消してよいファイルの規則: 選んだ時点で 8 MiB を超えていて除いたファイルが、その後に小さくなっても、消されずに「戻せなかった」に入る（01-05 の理由の例）。今の規則で除くパスも消されない。
- 安全の性質（07-01）: プロジェクトの中のシンボリックリンクがプロジェクトの外を指しているとき、書き戻しと削除がリンクの先（プロジェクトの外）を変えない。途中の要素をシンボリックリンクに差し替えたディレクトリの下に書き戻さない。`.git` の中を変えない。
- ハードリンクの数が 2 以上のファイルの一覧のイベントが一度だけ出る。
- 会話を戻す: 会話が選んだ時点の項目の数に切り詰められ、`Record::Rewind` が書かれ、`replay` が同じ会話を作る。圧縮の前の時点は会話を戻す選択肢にならない。
- 戻せないものの一覧に、選んだ時点の後の `bash` の実行が入る。
- 書ける量の上限で `objects/` への保存が止まり、時点にそのことが記録される。
