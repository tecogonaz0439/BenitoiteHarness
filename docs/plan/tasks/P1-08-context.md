# P1-08 システムプロンプト、道具の定義、環境の情報

## 目的

LLM に送る文脈のうち、会話より前に置くもの（システムプロンプトと道具の定義）と、環境の情報の塊を作る。システムプロンプトの全文と道具の定義の全文を、期待のファイルで固定するテストを置く。文脈の大きさの見積もりも作る。

## 読む設計書

- [文脈の管理](../../design/01-agent/01-04-context.md)の「文脈の構成」「システムプロンプトの構成」「Benitoite の Skill の置き方」「環境の情報」「送る内容の表示」「文脈の大きさの見積もり」
- [道具](../../design/01-agent/01-03-tools.md)の「道具の定義の共通の規則」「モードごとの道具の一覧」と、P1 で作る五つの道具の節
- [モード](../../design/01-agent/01-02-modes.md)の「制限モード」「道具の一覧を固定する理由」
- [テスト](../../design/07-quality/07-01-testing.md)の「LLM に見せる文の固定」
- [Benitoite の処理系との連携](../../design/04-benitoite/04-01-benitoite-integration.md)の「取り込む文書と版」（`{{benitoite-version}}` の置き換え）
- P1-06・P1-07 の道具の枠組み

## 作るもの

1. `crates/benitoiteh/prompts/`: 英文のファイル。
   - `preamble-restricted.md`、`preamble-normal.md`: 前置き（2〜3 文。Pi の前置きと同じ程度の短さ。作業の進め方の一般論を書かない）。
   - `mode-restricted.md`、`mode-normal.md`: `<mode>` の節。制限モードは、シェルがないこと、`.bnt` だけを書けること、実行の前に利用者の確認があること、`Process.Run` を使うスクリプトは止められうることを書く（01-04）。P1 の時点で `benitoite_*` の道具がないことは書かない（P2 で加わる前提の文にする）。
   - `rules-common.md`: 共通の規則（応答を簡潔にする、ファイルのパスを示す）。
   - `tools/<道具の名前>.md`: 道具ごとの一行の説明と規則（0〜3 行）。P1-06 で置いた仮の英文を、ここからの `include_str!` に差し替える。
   - `benitoite-mapping.md`: 制限モードの `<benitoite>` の前に置く対応の説明（01-04 の「Benitoite の Skill の置き方」の四つの点）。
   - 英文は、設計書に英文で書いてある文を字句を変えずに使い、ほかは短く書く。オーケストレータが取り込む前に文面を見直す。
2. `crates/benitoiteh/src/context/`。
   - システムプロンプトの組み立て: 前置き、`<tools>`（有効な道具の一行の説明）、`<rules>`（有効な道具の規則と共通の規則）、`<mode>`、`<benitoite>` を、モードごとに 01-04 の表のとおりに並べる。制限モードの `<benitoite>` は、対応の説明と、`assets/benitoite/v0.0.6/skill/SKILL.md` の本文（先頭の属性の部分を除く。`{{benitoite-version}}` を `0.0.6` に置き換える）。通常モードの `<benitoite>` は、Skill の名前と `description`（`SKILL.md` の先頭の属性から読む）と、`benitoite_reference` に `SKILL` を指定すれば全文を読めること（P2 で道具ができる前提の文）。`SKILL.md` は `include_str!` で埋め込む。
   - 道具の定義: モードの `ToolSet` から、アダプタに渡す `ToolSpec` の並びを作る。
   - システムプロンプトと道具の定義（普通の形の JSON）の SHA-256 を求める関数（セッションの記録のヘッダに書く。P1-05）。
   - 環境の情報 `<environment>`: プロジェクトのディレクトリの絶対パス、OS の種類、今日の日付（UTC の年月日だけ）、モード、書ける場所とネットワークの可否の要約、処理系の版（P1 では「not configured」などの決まった文）。通常モードのプロジェクトの指示のファイルは P3 で加える。変わった項目だけを同じ形で加える関数も置く（P1 では使わない）。
   - 送る内容の表示の文（01-04 の「送る内容の表示」）: 提供者、モデル、ホストの名前と、読んだファイルの中身などが提供者へ送られることを一行で示す文。`session_start` のイベントに入れる（P1-09）。
   - 文脈の大きさの見積もり: 最後の応答で報告された入力の全体に、その後に加えた内容の UTF-8 のバイト数を 3 で割った値を足す。報告がなければ全体をバイト数で見積もる（01-04）。
3. 期待のファイルとテスト: `crates/benitoiteh/tests/expected/`（`system-restricted.txt`、`system-normal.txt`、`tools-restricted.json`、`tools-normal.json`）。テストは、組み立てた全文を期待のファイルと比べる。期待のファイルの作り方: 初めは、組み立てた結果を書き出して人が読み、意図どおりと確かめてから置く。完了の報告に、期待のファイルを読んで確かめたことを書く。期待のファイルを更新する手順（環境変数で書き出すなど）を用意してよいが、テストの既定の動きでは書き換えない。

## 触るファイル

- `crates/benitoiteh/src/lib.rs`（`pub mod context;`）
- `crates/benitoiteh/src/tools/`（一行の説明と規則の英文の差し替え）

## テスト

- 二つのモードのシステムプロンプトの全文と道具の定義の全文が、期待のファイルと一致する（07-01 の「LLM に見せる文の固定」）。
- 制限モードのシステムプロンプトに Skill の本文が入り、`{{benitoite-version}}` が残っていない。通常モードには入らない。
- システムプロンプトに日付と作業ディレクトリが入っていない（環境の情報の側にだけある）。
- 見積もりの関数（報告ありとなし）。

## 完了条件

- `scripts/check.sh --inside-codex` が通る。
- 完了の報告に、システムプロンプトの二つのモードの大きさ（バイト数）を書く。
