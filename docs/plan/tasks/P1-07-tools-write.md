# P1-07 書く道具（write・edit）

## 目的

`write` と `edit` を、書く道具のパスの規則と、読んでから直す規則とともに作る。

## 読む設計書

- [道具](../../design/01-agent/01-03-tools.md)の「write」「edit」「書く道具のパスの規則」「読んでから直す規則」「書いた後の検査（制限モード）」
- [モード](../../design/01-agent/01-02-modes.md)の「モードごとの組み合わせ」（書き込みの範囲）
- [利用者の確認](../../design/03-safety/03-03-approval.md)の「通常モードの承認の方針」（`write`・`edit` の列）と「非対話での扱い」
- [テスト](../../design/07-quality/07-01-testing.md)の「安全の性質のテスト」の最初の項目
- P0-02 の `safe_fs`、P1-06 の枠組み

## 作るもの

`crates/benitoiteh/src/tools/write.rs`、`edit.rs` ほか。

1. 書く先の判定（`write` と `edit` で共通）。
   - 書ける範囲: 制限モードはプロジェクトの下と一時ディレクトリの `.bnt` のファイルだけ。通常モードは書ける場所（プロジェクトの下と一時ディレクトリ。設定の `normal.writable_roots` は P3 で加える）。
   - 判定は実のパスで行う。まだないファイルは、親のディレクトリの実のパスで判定する。拡張子（`.bnt`）と守る場所（`.git`・`.benitoiteh`）も実のパスで判定する。
   - 最後の要素がシンボリックリンクなら、先がなくても拒む。すでにあるファイルのハードリンクの数が 2 以上なら拒む（P0-02 の `safe_fs` が拒む形を使う）。
   - 守る場所の判定: 書ける場所の根からのパスのどの要素でも、名前が `.git` か `.benitoiteh` に当たれば守る場所とする（`sub/.git/config` も当たる）。比べ方は、どの OS でも ASCII の大文字と小文字を区別しない。理由: 入れ子のリポジトリの hooks も、利用者が後で git を使ったときに動く。macOS の既定のファイルシステムは大文字と小文字を区別しないので、`.GIT/config` も `.git/config` を指しうる。
   - 守る場所の下は、制限モードでは拒む。通常モードでは確認が要る。
   - 通常モードで書ける場所の外は、確認が要る。
   - 確認が要るときは、P1-06 の枠組みのとおり「確認が要る」という結果を返す。P1 の非対話の扱い（通常モードの `never`）では、ループの `Approver` が拒み（03-03 の表の `never` の行）、拒んだ文は、書ける場所の外か守る場所であることと、利用者に頼む方法を示す。
   - 書くときは、P0-02 の `safe_fs` の書き込み（同じディレクトリの一時ファイルに書いてから名前を付け替える）を使う。
2. `write`: 01-03 の「write」のとおり。すでにあるファイルを置き換えるときは読んでから直す規則に従う。LLM には `Wrote <path> (<N> lines).` だけを返す。差分（`similar` で作る）は `ToolOutput` の画面の情報に入れる。
3. `edit`: 01-03 の「edit」のとおり。字面の照合、見つからなければ寄せた形（改行を LF に揃え、行末の空白を除き、引用符とダッシュの異体を ASCII に寄せる）での照合、置き換えなかった行のバイト列を保つこと、改行の形（LF・CRLF）と BOM を保つこと、`replace_all`、四つの誤りの文（字句を変えない）。寄せる文字の一覧（引用符とダッシュの異体）は、Pi の手順（設計書 08-01 の先行事例）を参考に決め、完了の報告に一覧を書く。
4. 読んでから直す規則: `read` が記録した版（デバイス、inode、大きさ、更新の時刻）と今の版を比べる。記録がなければ `File has not been read in this session. Read it with read, then retry.`、違えば `File changed since it was last read. Read it again, then retry.` を返す。`write` と `edit` の後は、書いた後の版を記録し直す。記録は `ToolContext` が持つ（P1-06）。
5. 書いた後の検査（制限モード）は P2 で作る（処理系が要る）。P1 では、制限モードで `.bnt` を書いた結果に、検査の文を付けない。

## テスト

道具の実行器の境界で、本物のファイルシステムで確かめる。

- 安全の性質（07-01 の最初の項目のうち書く道具の分）: 制限モードで `.bnt` 以外を拒む。プロジェクトの外、`..`、外を指すシンボリックリンクを拒む。`x.bnt` という名前で `.git/hooks/` の下のまだないファイルを指すシンボリックリンクに書かず、リンクの先にファイルができない。ハードリンクの数が 2 以上のファイルを拒む。`.git` と `.benitoiteh` の下を拒む。
- 読んでから直す規則: 読まずに置き換える、読んだ後に外から変える、のそれぞれの誤り。書いた後は読み直さずに続けて `edit` できる。
- `edit`: 一つだけ、複数、見つからない、変化なし、空の `old_string`、寄せた形での照合（行末の空白、CRLF、引用符の異体）と置き換えなかった行が元のまま残ること、BOM と CRLF が保たれること、`replace_all`。
- 通常モードで、書ける場所の外と守る場所の書き込みが「確認が要る」になる（拒む流れは P1-09 で確かめる）。`sub/.git/config` と `.GIT/config` も守る場所として扱われる。
