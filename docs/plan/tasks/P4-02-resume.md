# P4-02 再開、セッションの一覧、記録の期間と大きさの上限

## 目的

記録したセッションを再開する仕組み（`--resume <ID>`・`--continue`）と、セッションの一覧（`benitoiteh sessions`）と、記録を残す期間と大きさの上限を作る（設計書 01-05 の「再開」「記録を残す期間」、05-01 の「sessions」）。対話の画面はまだないので、再開は非対話の `exec` で確かめる。対話の画面からの再開（と、制限モードのセッションを通常モードで再開するときの確認の画面）は P4-07 で作る。

## この作業が認める型の変更

- `Record::SessionStart` に、再開の印、ベースの URL、システムプロンプトと道具の定義のハッシュを `#[serde(default)]` の欄で加える。
- `Session` に、すでにあるセッションを開く関数を加える。

## 作るもの

### 1. 引数

- `--resume <ID>` と `--continue` を `ArgsError::Unavailable` から外し、`exec` で使えるようにする。二つを同時に指定したら使い方の誤りとする。`--allow` と `--project-parent` は今までどおり使えない。
- 対話の画面（引数のない起動）はまだないので、対話の形での再開は今までどおり使えない。

### 2. セッションを選んで開く

- `Session` に、すでにあるセッションを開く関数（例: `Session::open(paths: &DataPaths, id: &SessionId) -> Result<Session, SessionError>`）を加える。ディレクトリを範囲の外へ出ない形で開き、ロックのファイルの錠を取る。取れなければ「動いている」誤りとする。一時ディレクトリは新しく作る（同じ名前のものが残っていれば、`cleanup` と同じ確かめで消してから作る）。
- `--resume <ID>`: ID の形を検査し（パスの要素にしてよい形だけ）、そのセッションを開く。ないときと記録が読めないときは誤りとする。
- `--continue`: セッションのディレクトリを ID の新しい順に見て、記録の最後のプロジェクトのディレクトリ（`Record::ProjectDirChanged` があればその最後、なければヘッダ）の実のパスが、今のプロジェクトのディレクトリの実のパスと同じで、錠が取れる最初のものを開く。ないときは誤りとする。
- `--resume` に `--project` を添えて、記録の最後のプロジェクトのディレクトリと違うディレクトリを示したら、使い方の誤りとする。`--project` がなければ、記録のディレクトリを使う。
- 記録の形式の版が今の版と違えば、再開できないことを示して誤りとする。

### 3. 起動の値

- モード: `--mode` があればそれ、なければ記録のモード（最後の `session_start` のもの、なければヘッダ）とする。制限モードのセッションを通常モードで再開するときは、`exec` では行わず、使い方の誤りとする（03-01 の「モードを変える操作」。対話の確認は P4-07）。通常モードのセッションを制限モードで再開するのは許す。
- 提供者の設定の名前とモデル: 明示しなければ記録の最後のもの。その名前の提供者が今の設定になければ誤りとする。推論の深さ、サンドボックスと承認の方針、書ける場所、上限は、今の起動の指定と設定による。
- 環境の情報: 会話の最初の発言の環境の情報は記録のものを使い、今の値と違う項目（日付など）は、01-04 の「環境の情報」の変化として、次の依頼の前に加える。
- プロジェクトの指示のファイルは、今の起動のときに読み直し、記録の会話にある指示と違えば、変化として加える（同じなら加えない）。

### 4. 会話を組み立て直す

- `replay` で会話を組み立て直す（最後の圧縮があればその後）。記録の最後の行が途中で切れていれば捨てる（`read_records` の今の扱いを確かめ、なければ加える）。
- 結果の記録のない道具の呼び出しに補う結果（01-05 の「再開」の英文と、取り消しと同じ結果）を、再開のときに `Record::ToolResult` として記録のファイルに書く（後の `replay` が同じ会話を作るように）。自動で実行し直さない。
- 番の番号と呼び出しの ID（`turn-N-call-i`）は、記録の最大の番の番号の続きから数える。
- 再開の `session_start` の行を書く（2026-10-17 の 01-05 の追記。再開の印、提供者の設定の名前、ベースの URL、モデル、モード、システムプロンプトと道具の定義のハッシュ）。
- 読んだファイルと変えたファイルの集合は、記録から作り直す（P4-01 の関数）。このセッションで許したコマンドと読んだファイルの版は戻さない。

### 5. 推論の内容

- 記録の最後の `session_start`（なければヘッダ）のシステムプロンプトと道具の定義のハッシュが今のものと違うときは、会話のすべての `AssistantTurn` から推論の内容を除く（P4-01 の除く処理を、残した番だけでなく全体に使う）。送り先（提供者の設定の名前、ベースの URL、モデル）が違うときは、今までどおりアダプタが推論を送らない（`raw_items.destination` の比べ方）。
- `reasoning_replay` が `all-turns` で、送り先かハッシュが記録と違うときは、最初の要求の前に、残す範囲を設けない圧縮を行う（01-04 の「推論の内容の扱い」。P4-01 の口を使う）。圧縮が失敗したら、再開を止めて示す。

### 6. セッションの一覧

- `benitoiteh sessions [--project <dir>] [--json]` を加える（05-01 の「sessions」）。各セッションの記録は、ヘッダと最初の依頼が分かるところまで読めばよい。動いているかは、ロックの錠を取れるかで調べ、調べた後に錠を放す。
- 最初の依頼の先頭の 60 文字は、`Record::User` の `Request` の部分から取り、制御の文字を目に見える形に変える（P4-06 の関数がまだなければ、この作業で `ui` に小さな関数を置き、P4-06 で共有する）。

### 7. 記録を残す期間と大きさの上限

- 起動のとき（`exec`、`sessions`）に、`[sessions] retention_days`（既定 30）を過ぎたセッションのディレクトリを消す。過ぎたかは、記録のファイルの更新の時刻で判定する。動いているもの（錠が取れないもの）と、今開いたセッションは消さない。消すときはシンボリックリンクを辿らない。
- 起動のときに、すべてのセッションのディレクトリの大きさの合計を数え、このセッションの `spill/` と `objects/` に書ける量を、1 GiB と「10 GiB − ほかのセッションの合計」の小さい方とする（01-05 の「記録を残す期間」）。`Session` がこの量を持ち、`SpillWriter`（と P4-03 の `objects/` の書き手）が、書いた量を足しながら超えないようにする。超えた書き込みは誤りにし、`bash` の結果では今の「保存できなかった」の印になる（P3-05）。再開したセッションでは、すでにある `spill/` と `objects/` の大きさから数え始める。
- 合計が 10 GiB を超えているときは、起動のときに、そのことと、期間を短くする方法を標準エラー出力に一行で示す（英文は `text` に置く）。
- 記録のファイル（`session.jsonl`）は、この上限で止めない。

## テスト

模擬の提供者と、一時の `XDG_STATE_HOME` で確かめる。

- `exec --resume <ID>`: 前の `exec` のセッションの会話に続けて、新しい依頼を送る。送った要求が、前の会話と新しい依頼を持つ。記録は同じファイルに追記され、再開の `session_start` が一行加わる。`replay` が `agent.conversation()` と一致する。
- `exec --continue`: 同じプロジェクトの最も新しいセッションを選ぶ。別のプロジェクトのセッションは選ばない。動いているセッション（テストの中で錠を持つ）は選ばない。
- `--resume` と `--continue` の同時指定、`--resume` と違う `--project`、ない ID、パスの要素にできない ID（`../x` など）が誤りになる。
- 制限モードのセッションを `--mode normal` で `exec` で再開すると、使い方の誤りになる（安全の性質のテスト。07-01）。通常モードのセッションを制限モードで再開できる。
- 結果の記録のない道具の呼び出し（実行を始めた記録あり、なし）に、決まった結果が補われ、記録に書かれ、実行し直されない。
- 番の番号と呼び出しの ID が記録の続きから数えられ、前の `spill/` のファイルを上書きしない。
- システムプロンプトのハッシュが記録と違うと、前の番の推論の内容を送らない。同じなら送る（Anthropic の thinking のブロック）。`all-turns` で送り先が違うと、最初の要求の前に残す範囲を設けない圧縮が行われる。
- 提供者を明示しないと記録の提供者の設定の名前とモデルを使う。その名前が設定になければ誤りになる。
- `sessions`: 新しい順に並び、`--project` で絞れ、`--json` で一行一件になる。最初の依頼の制御の文字が目に見える形になる。読めない記録は ID と理由だけを示して続ける。
- 期間: 期間を過ぎたセッションが起動のときに消え、動いているものと期間内のものは残る。シンボリックリンクの先は消えない。
- 上限: 書ける量を小さくした `Session`（テストのための差し替えを `#[cfg(test)]` か内部の関数で用意してよい）で、`spill/` への書き込みが上限で止まり、`bash` の結果が「保存できなかった」の印になる。合計が上限を超えているときに、起動のときの一行が出る。
