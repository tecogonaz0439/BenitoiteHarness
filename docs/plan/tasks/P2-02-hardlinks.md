# P2-02 サンドボックスの中のハードリンクの作成（BH-092）

## 目的

サンドボックスの中のコマンドが、書ける場所の外のファイルへのハードリンクを、書ける場所の中に作れるかを、macOS の Seatbelt と Linux の bubblewrap の本物の子プロセスで確かめる（BH-092 の【要検証】）。作れれば、書く道具のハードリンクの拒否（設計書 01-03「書く道具のパスの規則」）だけでは足りないので、作業を止めて報告する。

オーケストレータが 2026-10-17 に macOS 27.0.1 で、`(deny default)` から始めて読み取りを広く許し、書き込みを一つのディレクトリに限った小さな方針で `/bin/ln` を試した。外のファイルへのハードリンクは `Operation not permitted` で拒否され、書ける場所の中どうしのハードリンクは作れた。この作業では、`benitoiteh` の本物の方針で確かめる。

## 作るもの

1. `sandbox-probe` に、ハードリンクを作る操作（`hardlink <元> <先>`。`std::fs::hard_link`）を加える。拒否は既存の操作と同じ終了状態（`EPERM`・`EACCES` は 10）で返し、Linux の `EXDEV` も見分けられるように、`EXDEV` は別の終了状態（12）にする。
2. 次のテストを、macOS と Linux の両方に加える。方針はどちらも既存のテストの既定の方針（書ける場所が一つ、読ませない場所が一つ、守る名前が `.git` と `.benitoiteh`）を使う。
   - 書ける場所の外の、読めるファイル（書ける場所の兄弟のディレクトリに置く）へのハードリンクを、書ける場所の中に作れない。
   - 読ませない場所のファイルへのハードリンクを、書ける場所の中に作れない。
   - 書ける場所の中の守る場所（`.git/config`）へのハードリンクを、書ける場所の中のほかの名前で作れない。
   - 書ける場所の中のファイルへのハードリンクを、書ける場所の中に作れる（通常の操作が拒まれないこと）。
   - 拒まれたテストでは、先の名前が書ける場所に残っていないことと、元のファイルのリンクの数が 1 のままであることも確かめる。
3. Linux では、拒否が `EXDEV`（マウントの境を越えるリンク）によるか、Landlock の `EACCES` によるかを、終了状態で区別してテストの期待に書く。理由: Linux では、書ける場所は `--bind` の別のマウントなので、外のファイルとの間のリンクはカーネルが `EXDEV` で拒むと見込まれる。どちらで拒まれたかを残し、設計書に書く。
