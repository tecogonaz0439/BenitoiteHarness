# P4-08 `/` で始まるコマンドと、P4 の安全の性質のテストの一覧

## 目的

対話の画面の `/` で始まるコマンド（`/help`・`/status`・`/compact`・`/rewind`・`/new`・`/quit`）を作る（設計書 05-02 の「`/` で始まるコマンド」）。圧縮（P4-01）、巻き戻し（P4-03）、対話の画面（P4-06・P4-07）の口を使う。あわせて、07-01 の安全の性質のテストのすべてについて、どのテストが確かめるかの一覧を作る（ロードマップの P4 の完了条件の準備）。

## この作業が認める型の変更

- 働き手のスレッドの仕事に、`Compact`・`Status`・`ListCheckpoints`・`PreviewRewind`・`Rewind`・`End` を加える（`Agent` を `Mutex` で包まない）。
- `Agent` の状態の写し（例: `AgentStatus`。セッションの ID、モード、提供者の設定の名前とモデル、ホスト、サンドボックスの方針、承認の方針、使ったトークンの累計、文脈の見積もりと上限、読んだプロジェクトの指示のファイルと読まなかったもの）を返す口。
- 戻さずに戻せないものの一覧を返す口（例: `Agent::rewind_preview(checkpoint, scope) -> RewindPreview`）。一覧は `RewindReport` と同じ関数で作り、選んだ時点の後の `web_fetch` の呼び出しも含める（01-05 の「戻せないものの表示」。`RewindReport` にも同じく加える）。
- P4-03 の時点の一覧の口を広げ、依頼の先頭（今の世代なら会話から、なければ記録の行から。取れなければ `(not available)`）と、道具の前の時点の道具の一行（P4-06 の道具の呼び出しの一行の規則）を返す。
- セッションを終える口（例: `Agent::end(reason)`。`session_end` を一行書く）。
- 画面の芯が、`Prepared` を作る関数（か trait）を外から受け取る形（`/new` とテストのため）。

## 作るもの

### 1. 入力の解釈

- コマンドとして解釈するのは、画面の入力欄で Enter を押して送った文だけとする。LLM の出力、道具の結果、`AgentInput`、記録、再開した会話の文は、コマンドとして解釈しない。
- 文の先頭が `/` で、続く名前が小文字の英字だけのとき、コマンドとする（大文字と小文字を区別する。先頭の空白は除かず、依頼として送る）。名前の後の空白の後ろの全文（改行を含む）を引数とする。`/` だけの文と知らない名前は、`/help` を案内して示す（LLM に送らない）。引数を取らないコマンド（`/help`・`/status`・`/rewind`・`/new`・`/quit`）に引数を付けたら誤りとして示す。
- `//` で始まる文は、先頭の `/` を一つ除いて、依頼・操縦・後続として送る（三つで同じ扱い）。
- 一連の処理の途中（圧縮と戻す処理の最中を含む）は、`/quit` だけを受け付け、ほかは「処理の途中では使えない」と示す。処理の途中の Alt+Enter（後続）で `/` で始まる文は拒む。
- 入力の履歴（P4-07）には、打ったままの文を入れる（知らない名前も入れる）。`/rewind` の選択と確かめのキーは入れない。

### 2. コマンド

- `/help`: コマンドと入力の操作の一覧（05-02 の表）を示す。
- `/status`: `AgentStatus` と `Prepared` の値を示す。セッションの ID、モード、提供者の設定の名前とモデル、ホストの名前（`base_url` は示さない）、処理系（`not checked`。英文は `text` に置き、処理系を探しに行かない）、サンドボックスの方針（`--no-sandbox` で外したかを含む）、承認の方針、使ったトークンの量（このプロセスで、このセッションの依頼ごとの `Summary.tokens` と、手動の圧縮の `CompactReport.usage` の和。再開の前の分は含めない。費用は示さない。BH-035）、文脈の見積もりと上限、読んだプロジェクトの指示のファイルと読まなかったもの。文字列は `terminal_text` で変えて示す。
- `/compact [指示]`: 働き手のスレッドの `Compact` の仕事で `Agent::compact` を呼ぶ。処理中は状態の行に示し、一度の ESC と Ctrl+C で取り消せる。結果（済んだ、圧縮するものがない、取り消した、失敗した）と、要約した項目の数と残した項目の数を一行で示す。手動の圧縮の後に、`compactions` を数えた `Record::Summary` を一行追記する。
- `/rewind`:
  1. 時点の一覧（新しい順。番の番号、理由、時刻（UTC）、依頼の先頭か道具の一行、会話を戻せるか、不完全か）を選択の画面で示し、↑・↓ と Enter で選ぶ。一覧が下の部分の高さを超えたら、選択の窓を動かす。ESC でやめる。
  2. 範囲（「files and conversation」「files only」「conversation only」）を選ぶ。時点の一覧の「会話を戻せるか」が偽の時点（道具の前の時点、戻す操作の前の時点、圧縮か会話の巻き戻しで世代が変わる前の時点）では、「files only」だけを選べる。
  3. `rewind_preview` で戻せないもの（選んだ時点の後の `bash` と `web_fetch` の呼び出しなど）を得て示す（多ければ最初の 20 件と `N more`）。範囲がファイルを含むときだけ、戻す前の状態も時点として記録することを示す。選んだ時点が不完全なら、増えたファイルを消さないことを示す。`[y] rewind` `[n] cancel` で確かめる。
  4. `allow_incomplete = false` で `rewind` を呼ぶ。戻す前の時点が不完全だという誤りが返れば、不完全の理由を示し、`[f] rewind anyway` `[n] cancel` で確かめ、`[f]` なら `true` で呼び直す（戻す前の時点はもう一度記録される）。
  5. 結果（書き戻した数、消した数、作った数、戻せなかったものの一覧（多ければ最初の 20 件と `N more`））を示す。
  - 3 と 4 の確かめのキーには、P4-07 の確認の画面と同じ入力の守り（示す前に届いていたキーと貼り付けを捨てる、示した後 300 ミリ秒より前のキーを捨てる、ESC は拒否）を、共通の関数で掛ける。
  - 示す文字列（依頼の先頭、道具の一行、戻せないものの一覧、戻せなかったもののパスと理由、不完全の理由）は、すべて `terminal_text(.., false)` で変える。
  - 戻す処理は取り消せない。最中の `/quit` と終える合図では、終わるまで待つことを状態の行に示す。
- `/new`: 新しいセッションを先に準備する（`Prepared` を作る関数を、`--resume`・`--continue` と起動のときの依頼の引数を除いた起動の指定で呼ぶ。設定のファイルは読み直す）。準備に失敗したら、今のセッションを続けて誤りを示す。成功したら、働き手のスレッドの `End` の仕事で今のセッションを終え（`session_end` を一行書く）、`Agent` を落とした（一時ディレクトリが消えた）ことを画面のスレッドに知らせてから、新しい `Agent` に替え、起動のときの表示（提供者・モデル・ホスト・送る内容・サンドボックス・診断）を出し直す。このセッションで許したコマンドとドメインの集合と、読んだ版の記録は引き継がない。モードと承認の方針は起動の指定から変わらない（03-01）。前の画面の出力は端末の履歴に残る。入力の履歴は同じプロジェクトのものを使い続ける。
- `/quit`: 終える（終了状態 0）。一連の処理の途中なら、P4-06 の「処理の途中で終えるときの流れ」を使う。
- モードを変えるコマンドと、提供者やモデルを変えるコマンドは設けない（05-02）。

### 3. 安全の性質のテストの一覧

- 07-01 の安全の性質のすべての項目について、確かめるテストの名前（ファイルと関数）を挙げた一覧を、`docs/plan/results/P4-safety.md`（新）に表で書く。項目ごとに、確かめる環境（Codex の中、手元の macOS、aarch64 のコンテナ、x86_64 の Linux）を記し、まだ確かめられないものは理由（「`v0.0.7` の処理系の連携で確かめる」「オーケストレータが手元で走らせる」など）を記す。P4 で加えた主のプロセスの操作（圧縮、再開、巻き戻し、`web_fetch`、`glob`・`grep` の辿り方、確認の画面、入力の履歴、端末の制御の列、`/rewind` の確かめ、制限モードから通常モードへの再開）を必ず含める。足りないテストがあれば、この作業で加える。
- この作業の時点では、P4 の完了条件のうち、`create_project` と処理系の項目が残ることを一覧に記す。オーケストレータは、取り込んだ後に、すべてのテストを手元の macOS、aarch64 のコンテナ、x86_64 の Linux で走らせ、07-01 の求める環境の情報（OS と版、CPU、カーネル、Landlock の ABI の版）を一覧に添える。

## テスト

端末なしで、画面の芯にキーのイベントの列と書き先を渡して確かめる。`/new` は、模擬の提供者と一時のディレクトリで `Prepared` を作る関数を渡す。`/rewind` の状態は、サンドボックスを要さない通常モードの `write`・`edit` で作る。

- コマンドの解釈: 知らない名前、`/` だけ、大文字の名前、先頭の空白、引数を取らないコマンドの引数、`//` の扱い（依頼・操縦・後続）、処理の途中で使えないこと、Alt+Enter の `/` の文の拒否、`/compact` の複数行の指示が要約の依頼に入ること（模擬の提供者）。
- 安全の性質（07-01）: LLM の応答の文に `/new`・`/rewind` などを含めても何も実行されない。`/rewind` の確かめの画面を示す前に打った `y` と、示した直後の `y` で戻らない。
- `/status` の表示の内容（描画の純関数で）。トークンの量が、依頼ごとの集計と手動の圧縮の使用量の和と一致する。`base_url` が示されない。
- `/rewind`: 選択の画面のキーの操作、会話を戻せない時点（道具の前の時点、会話を戻した後の古い時点、圧縮の前の時点）で範囲が「files only」に限られること、`[y]` でなければ戻さないこと、不完全な戻す前の時点で `[f]` を求めること、戻せないものの一覧に `bash` と `web_fetch` が入ること、戻した結果の表示。ファイルと会話が選んだ時点に戻る。
- `/new`: 新しいセッションの ID になり、前のセッションの記録に `session_end` が書かれ、前の一時ディレクトリが消え、`[a]` で許したコマンドが引き継がれない。準備に失敗したら今のセッションが続く。
- `/quit`: 芯が終了状態 0 を返し、書き先の最後が P4-06 の端末を戻す列である。処理の途中でも同じ。
