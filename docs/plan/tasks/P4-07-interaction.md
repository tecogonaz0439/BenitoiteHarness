# P4-07 対話の操作と確認の画面

## この作業が認める型の変更

- `Agent` に、一連の処理の途中の入力を受け取る口と、取り消しの二つの段階を表す印を加える（形は任せる。例: `run` の引数を `RunControl { cancel_step: Arc<AtomicBool>, cancel_run: Arc<AtomicBool>, inputs: Receiver<AgentInput> }` にする）。`exec` は今までどおり一つの印で動く形を保つ。

## 作るもの

### 1. 操縦と後続

- 一連の処理の途中の Enter は操縦とする。入力欄の文を `AgentInput::Steering` としてループへ送る。ループは、今の応答の道具の呼び出しがすべて終わった後、次の要求の前に、利用者の発言（`UserPartKind::Steering`、記録は `UserKind::Steer`）として会話に加える。一連の処理が最後の応答（道具を呼ばない応答）で終わる直前に届いた操縦は、終わらずに次の要求を送る。
- Alt+Enter は後続とする。一連の処理が終わった後に、新しい依頼として送る。複数あれば順に送る。
- 送った操縦と後続は、出力に一行で示す（後続は送るまで状態の行に件数を示す）。

### 2. 取り消し

- ESC（一度）: 01-01 の 2026-10-17 の追記のとおり。道具の実行の途中なら、その応答のまだ終わっていない道具の呼び出しを取り消した結果にして続ける。LLM の応答を待つ・受け取る途中なら、一連の処理を止める。確認の画面では拒否とする。
- ESC（続けて二度。間隔は 1 秒以内）と、一連の処理の途中の Ctrl+C: 一連の処理を止め、入力欄に戻る。
- 止めたときは、止める前に子プロセスが行った操作は戻らないことを一行で示す（01-01 の「取り消し」）。
- `bash` の子プロセスを止める仕組み（`run` の取り消しの印）は、一度の ESC でも二度の ESC でも働く。

### 3. 確認の画面

- `Approver` の実装を作る。ループのスレッドから確認の要求を画面のスレッドへ送り、答えを待つ。画面のスレッドは、出力の流れの中に枠付きの確認の画面を示し、答えを一つのキーで受ける（05-02 の「確認の画面」の形）。
- 示すもの（すべて `terminal_text` で制御の文字を目に見える形にする）: 種類ごとの題、`ApprovalFacts` の欄（コマンド、作業ディレクトリ、パス、サンドボックスの方針、URL とドメイン）、`justification` は `Reason given by the model:` の見出しを付けて事実と分けて示す。
- 答えのキー（英語。`ui` の `text` に置く）:
  - `Command`: `[y] run` `[a] allow this exact command for this session` `[n] decline` `[m] decline with a message`
  - `Escalate`: `[y] run outside the sandbox once` `[n] decline` `[m] decline with a message`
  - `WriteScope`: `[y] write` `[n] decline` `[m] decline with a message`
  - `WebFetch`: `[y] fetch once` `[s] allow this domain for this session` `[n] decline` `[m] decline with a message`
- `[m]` は、枠の中に一行の入力欄を開き、Enter で `DeniedWithMessage` とその文を返す。ESC で入力をやめて選択に戻る。
- 答えを待つ間は、ほかの入力を受けない。ESC は拒否とする。確認の画面を示す前に届いていたキーの入力と、貼り付けの入力は、答えに使わずに捨てる（03-03 の「確認の共通の規則」）。画面を示した後、短い時間（例: 300 ミリ秒）より前に届いたキーも捨てる（利用者が前の入力の続きで打ったキーで答えないため）。
- 一連の処理を二度の ESC で止めたときに確認の画面が開いていれば、`Cancelled` を返す。
- 対話の承認の方針の既定を `on-request` にし、`--approval` の三つの値を受け付ける。P4-06 で加えた「確認が要る操作は拒否される」の起動の一行を除く。制限モードの対話の方針も `on-request` に当たる値とする（`web_fetch` の確認に答えられる）。

### 4. 入力の履歴

- 送った依頼、操縦、後続を、プロジェクトごとの履歴のファイル（データのディレクトリの `history/<プロジェクトのディレクトリの実のパスの SHA-256 の 16 進>`、05-01 の「データの置き場所」）に、一行一件の JSON の文字列で追記する。ディレクトリは 0700、ファイルは 0600 で作り、開くときはシンボリックリンクを辿らない。
- 起動のときに、新しい 500 件を読む。500 件を超えたら、書き足すときに古い側を除いて書き直す（一時のファイルに書いてから付け替える）。
- ↑・↓ は、入力欄が一行のとき、この履歴を辿る。
- 確認の画面の `[m]` の文は履歴に入れない。

### 5. 対話の形での再開

- `benitoiteh --resume <ID>` と `benitoiteh --continue` を対話の形で使えるようにする（P4-02 の選び方と組み立て直しを使う）。再開したら、前の会話の最後の数件（例: 利用者の発言と応答の最後の 3 組）を出力に示す。
- 制限モードのセッションを `--mode normal` で再開するときは、起動の前に、前の文脈に信頼しない内容が含まれうることを示す確認の画面を出し、`[y]` のときだけ再開する（03-01 の「モードを変える操作」）。

## テスト

- 操縦: 模擬の提供者で、道具を呼ぶ応答の途中に操縦を送ると、道具の結果の後、次の要求の前に利用者の発言として入る。最後の応答の直前に届いた操縦で、一連の処理が続く。記録に `steer` の行が入る。
- 後続: 一連の処理の後に、新しい依頼として順に送られる。
- 取り消し: 一度の ESC で、`bash` の長いコマンド（`--sandbox danger-full-access` の `sleep`）が止まり、取り消した結果で一連の処理が続く。応答の受け取りの途中の一度の ESC で、一連の処理が止まる。二度の ESC で止まる。
- 確認の画面（端末なしで、キーのイベントの列を与える形）:
  - 種類ごとのキーが、`Approved`・`ApprovedForSession`・`Denied`・`DeniedWithMessage` に対応する。`Escalate` と `WriteScope` に `[a]`・`[s]` がない。
  - 画面を示す前に届いたキー、貼り付け、示した直後のキーが答えに使われない（安全の性質のテスト。07-01）。
  - ESC が拒否になる。`[m]` の文が拒否の結果に入る。
  - 事実と `justification` が分けて示され、制御の文字が目に見える形になる（安全の性質のテスト）。
- 履歴: 権限が 0600 で、500 件を超えると古い側が除かれ、プロジェクトごとに分かれる。シンボリックリンクに置き換えた履歴のファイルを辿らない。`[m]` の文が入らない。
- 再開: 制限モードのセッションを通常モードで再開するとき、`[y]` でなければ再開しない（安全の性質のテスト）。
