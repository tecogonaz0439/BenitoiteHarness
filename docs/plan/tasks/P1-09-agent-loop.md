# P1-09 エージェントのループ

## 目的

エージェントのループ（要求、ストリーミングの受け取り、道具の実行、結果の返却の繰り返し）を、イベントとセッションの記録とともに作る。

## 作るもの

`crates/benitoiteh/src/agent/`。

1. イベント `AgentEvent`（01-01 の「イベント」の 13 種）。欄は次のとおりとし、`serde` で JSON にする（`"type"` の欄で種類を分ける。`exec --json` の行と同じ形）。
   - `session_start`: `session_id`、`mode`、`provider`、`model`、`host`、`benitoiteh_version`、`notice`（P1-08 の送る内容の表示の文）。
   - `turn_start`: `turn`。`text_delta`・`reasoning_delta`: `turn`、`text`。
   - `tool_call`: `turn`、`call_id`（内部の ID）、`name`、`arguments`。
   - `approval_request`・`approval_result`: `call_id`、`kind`、`summary`、`decision`（P1 では非対話の拒否だけが出る）。
   - `tool_result`: `turn`、`call_id`、`name`、`is_error`、`summary`（結果の先頭の一行。画面と `exec` の要約のため）。
   - `turn_end`: `turn`、`finish_reason`、`usage`。
   - `compaction`: 型だけを置く（P4）。
   - `retry`: `attempt`、`delay_ms`、`reason`。`error`: `kind`、`message`。`session_end`: `outcome`（`completed`・`failed`・`cancelled`）と理由。
2. ループ `Agent`: エージェントのスレッドで動く。
   - 入力: 依頼の文、取り消しの印（`Arc<AtomicBool>`）。P1 の操縦と後続は型だけを置く（P4）。
   - 出力: `AgentEvent` を長さに上限のあるチャネル（`sync_channel`）で送る。`agent` は画面を知らない（06-01）。
   - 確認: 確認を受ける側を表す型（`Approver` など）を引数に取る。P1 では非対話の扱い（03-03 の「非対話での扱い」。通常モードの `never`）だけを作る。
   - 番の流れ（01-01）: 依頼を会話に加え、要求を作ってストリームを受け取り、終わりの理由で分ける。圧縮（手順 2）は P4 で作るので、P1 では行わない。文脈の超過の誤りは、P1 ではやり直さずに一連の処理を止める（誤りの文に圧縮がまだないことを書く）。
   - ストリーミング: ストリームのスレッド（P0-03 の `http` のストリーミングの要求）から受け取ったバイト列を、P1-01 の SSE の読み取りとアダプタで `StreamEvent` に変え、`text_delta` などのイベントを送る。最後にデータを受け取った時刻を見張り、上限（既定 300 秒。テストで短くできる）を超えたら打ち切り、ストリームの途中の切断として扱う。
   - 終わりのイベントを受け取る前の切断、ストリームの中の誤り: 応答の道具の呼び出しを実行しない。
   - 出力の上限: 道具の呼び出しを実行せず、各呼び出しに 01-01 の決まった文を結果として返し、次の番へ進む。
   - 拒否: 一連の処理を止め、拒否されたことと分類を `error` のイベントで示す。
   - 道具の実行（01-01 の「道具の実行」の 1〜4）: 応答の順に検証し、並行の可否が「可」の続く区間を `std::thread::scope` で最大 8 つ並べて実行し、「不可」は一つずつ実行し、結果は応答の順に会話に加える。手順 5（ストリームの途中で読み取りの道具を先に始める）は、P1 では作らない（P2 の後に、効果を測る作業として加える）。
   - 子プロセスを起動する道具と書く道具は、実行を始める前に `tool_start` を記録に書く（01-05）。
   - やり直し（01-01 の「やり直し」）: 分類と回数（最大 4 回）、間隔（1 秒から倍、30 秒を上限、±20% のゆらぎ。`Retry-After` があれば 60 秒を上限にその値）、`retry` のイベント。ストリームの途中で切れたら受け取った分を捨てて同じ要求を送り直す。待つ間も取り消しの印を見る。テストで間隔を短くできる形にする。
   - 上限（01-01 の「上限」）: 番の数（既定 200）、一連の処理のトークンの量（既定なし）。検査と修正の回数は P2 で数える（型と設定の受け渡しだけ置く）。
   - 同じ呼び出しの繰り返し（01-01）: 同じ道具を同じ引数で続けて呼んだ 3・5・8 回目の結果の末尾に決まった注意を加える。
   - 取り消し: 取り消しの印が立ったら、要求の受け取りを打ち切り（P0-03 の打ち切り）、結果のない呼び出しに `Tool call was cancelled by the user.` を補い、`session_end` を `cancelled` で送る。打ち切れずに切り離したストリームのスレッドが 2 つあるときは、新しい要求を送らずに待つ（01-01 の「取り消し」）。
   - 推論の送り返し: 同じ送り先、同じシステムプロンプトと道具の定義のハッシュのときだけ、アダプタに前の応答の `RawItems` を使わせる（01-04 の「推論の内容の扱い」）。
   - Anthropic の `cache_control` の「前の要求の会話の最後の項目」の位置を、ループが覚えてアダプタに渡す。
   - 集計（P1-05 の `summary`）の数を足す。
3. 記録: 01-05 のとおり、`session_start` の前にヘッダの行、各イベント（差分を除く）、応答を受け取り終えた時点の `assistant` の行、利用者の発言、`tool_start`・`tool_result` を書く。

## テスト

模擬の提供者の台本で、ループの境界で確かめる（`tests/agent_loop.rs`）。

- 道具を使う一連の処理（`read` を呼び、結果を受けて文で終わる）が、イベントの列と記録の行の列のとおりに進む。
- 一つの応答の中の複数の読み取りの道具が並べて実行され、結果が応答の順に会話に加わる。`write` を挟むと、その前後で区切られる。
- 出力の上限（`max_tokens`・`length`）と、終わりのイベントの前の切断で、道具が実行されない（ファイルが書かれない）。
- 429 と切断のやり直し（回数、`Retry-After`、やり直した要求の本文が同じであること）、401 で止まること、文脈の超過で止まること。
- データが届かない時間の上限（短くした値で）で、打ち切ってやり直す。
- 番の数の上限で止まる。
- 同じ呼び出しの 3 回目に注意が付く。
- 取り消し: ストリームの途中と、道具の実行の後で止め、結果のない呼び出しに決まった結果が補われる。
- 同じ送り先の 2 回目の要求で、前の応答の元の項目が順序と ID を変えずに送られる（模擬の提供者の記録で確かめる）。
